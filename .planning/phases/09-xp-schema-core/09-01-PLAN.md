  <action>
Create the migration file wrapped in BEGIN/COMMIT (matching all existing migrations). Include these sections in order:

**Section 1: Create connect.xp_transactions table**
```sql
CREATE TABLE IF NOT EXISTS connect.xp_transactions (
  id               UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id          UUID        NOT NULL REFERENCES public.users(id) ON DELETE CASCADE,
  source           TEXT        NOT NULL,
  amount           INT         NOT NULL CHECK (amount > 0),
  metadata         JSONB,
  idempotency_key  TEXT        NOT NULL UNIQUE,
  created_at       TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

**Section 2: Index for user history queries (reverse chronological)**
```sql
CREATE INDEX IF NOT EXISTS idx_xp_transactions_user_created
  ON connect.xp_transactions(user_id, created_at DESC);
```
Note: The UNIQUE constraint on `idempotency_key` auto-creates an index. No additional index needed for it.

**Section 3: ALTER connected_profiles to add total_xp and current_level**
```sql
ALTER TABLE connect.connected_profiles
  ADD COLUMN IF NOT EXISTS total_xp     BIGINT NOT NULL DEFAULT 0,
  ADD COLUMN IF NOT EXISTS current_level INT    NOT NULL DEFAULT 0;
```
Do NOT drop or rename the existing legacy `xp` column — Phase 10 handles that.

**Section 4: DROP and recreate connected_profiles_public view**
Must include ALL existing columns from the Phase 6 version (migration 019) PLUS the two new columns. The view must:
- Include: id, user_id, display_name, account_standing, verification_status, verification_method, verified_region, xp (legacy), total_xp (new), current_level (new), gem_balance, gem_balance_red, gem_balance_blue, gem_balance_yellow, gem_reserve_cap, veracity_rating, deleted_at, created_at, updated_at
- OMIT: tolerance_rating, legal_name, home_address (internal fields)
- WHERE: deleted_at IS NULL
- Re-GRANT SELECT to authenticated after DROP (DROP removes grants)

**Section 5: Enable RLS on xp_transactions**
```sql
ALTER TABLE connect.xp_transactions ENABLE ROW LEVEL SECURITY;
```

**Section 6: RLS policy — owner read only**
```sql
CREATE POLICY "xp_transactions: owner read"
  ON connect.xp_transactions
  FOR SELECT
  TO authenticated
  USING ((select auth.uid()) = user_id);
```
No INSERT, UPDATE, or DELETE policies. All writes go through `award_xp` SECURITY DEFINER RPC (Plan 09-02).

**Section 7: GRANT SELECT on xp_transactions**
Grant SELECT to both `authenticated` and `anon`. Anon gets zero rows via RLS (no anon policy), but the GRANT prevents permission-denied errors (returns empty set instead). This matches the gem_transactions pattern from migration 008/011.
```sql
GRANT SELECT ON connect.xp_transactions TO authenticated;
GRANT SELECT ON connect.xp_transactions TO anon;
```

Add clear section header comments matching the style of migration 019 (Phase 6 gems schema). Each section should have a `-- =====` separator and a brief explanation comment.
