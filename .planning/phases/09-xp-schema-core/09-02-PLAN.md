**Section 1: connect.calculate_level function**

Create a standalone `LANGUAGE sql` function (not plpgsql — pure arithmetic, no procedural logic needed):

```sql
CREATE OR REPLACE FUNCTION connect.calculate_level(p_total_xp BIGINT)
RETURNS TABLE (level INT, xp_in_level INT, xp_to_next_level INT)
LANGUAGE sql
IMMUTABLE
SECURITY DEFINER
SET search_path = ''
```

Level thresholds (LOCKED):
- Levels 1-3: 2,000 XP each (tier 1). Cumulative: 0-5,999 XP.
- Levels 4-9: 3,000 XP each (tier 2). Cumulative: 6,000-23,999 XP.
- Levels 10-29: 4,000 XP each (tier 3). Cumulative: 24,000-103,999 XP.
- Level 30+: 5,000 XP each (tier 4). Cumulative: 104,000+ XP.

Tier boundary constants: tier2_start = 6000, tier3_start = 24000, tier4_start = 104000.

Use CTE with `thresholds` and `computed` pattern from RESEARCH.md. Key formulas:
- Level in tier 1: `(p_total_xp / 2000)::INT + 1`
- Level in tier 2: `3 + ((p_total_xp - 6000) / 3000)::INT + 1`
- Level in tier 3: `9 + ((p_total_xp - 24000) / 4000)::INT + 1`
- Level in tier 4: `29 + ((p_total_xp - 104000) / 5000)::INT + 1`
- `xp_in_level` = modulo of XP within current tier's step size
- `xp_to_next_level` = tier step size minus xp_in_level

GRANT EXECUTE to `authenticated` AND `anon` (anon needs it for Phase 10 public XP endpoint).

**Section 2: connect.award_xp RPC**

Create a `LANGUAGE plpgsql` SECURITY DEFINER function with `SET search_path = ''`.

Input params: `p_user_id UUID, p_source TEXT, p_amount INT, p_idempotency_key TEXT, p_metadata JSONB DEFAULT NULL`

RETURNS TABLE with columns:
- Transaction fields: `id UUID, user_id UUID, source TEXT, amount INT, metadata JSONB, idempotency_key TEXT, created_at TIMESTAMPTZ`
- Computed fields: `total_xp BIGINT, current_level INT, xp_in_level INT, xp_to_next_level INT`
- Idempotency flag: `is_duplicate BOOLEAN`

Implementation steps (follow credit_gems pattern from migration 023):

1. **Validate amount** — `IF p_amount <= 0 THEN RAISE EXCEPTION`. Belt-and-suspenders alongside the CHECK constraint.

2. **Advisory lock** — `PERFORM pg_advisory_xact_lock(hashtext(p_user_id::text));`
   Use transaction-level lock (NOT session-level). Releases on COMMIT/ROLLBACK.

3. **Idempotency pre-check** — SELECT from `connect.xp_transactions` WHERE `idempotency_key = p_idempotency_key`. If FOUND:
   - Read current `total_xp` from `connected_profiles`
   - Call `connect.calculate_level(total_xp)` for computed fields
   - RETURN QUERY with the original transaction row + current profile state + `is_duplicate = TRUE`
   - RETURN (exit function)

4. **Lock profile row** — `SELECT cp.total_xp INTO v_new_total_xp FROM connect.connected_profiles cp WHERE cp.user_id = p_user_id FOR UPDATE;`
   If NOT FOUND, RAISE EXCEPTION (user has no connected_profiles row).

5. **Calculate new total** — `v_new_total_xp := v_new_total_xp + p_amount;`

6. **Calculate level** — `SELECT * INTO v_level_info FROM connect.calculate_level(v_new_total_xp);`

7. **Update connected_profiles** — SET `total_xp = v_new_total_xp, current_level = v_level_info.level, updated_at = now()` WHERE `user_id = p_user_id`.

8. **Insert ledger row** — INSERT INTO `connect.xp_transactions` with all params. Use `RETURNING * INTO v_inserted_row`.

9. **Return result** — RETURN QUERY with inserted row fields + computed level fields + `is_duplicate = FALSE`.

10. **EXCEPTION WHEN OTHERS THEN RAISE** — re-raise, Postgres auto-rolls back.

GRANT EXECUTE to `authenticated` only (not anon — XP awards require authentication; service role bypasses grants anyway).

Add clear section header comments matching the style of migration 023 (Phase 6 RPCs).
