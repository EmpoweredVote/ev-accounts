Create `backend/src/routes/compassContributor.ts` with a new Express Router.

**Middleware stack for both routes:**
`requireAuth` then `requireRole(['compass_stance_editor', 'campaign_manager'])` — this checks the user has at least one of these roles (OR logic). The fine-grained jurisdiction/resource check happens in the handler body using `getMatchingGrant`.

**Zod validation schemas:**

```typescript
const singleStanceSchema = z.object({
  value: z.number().int().min(1).max(5),
  write_in_text: z.string().max(500).optional(),
});

const bulkStanceSchema = z.object({
  stances: z.array(z.object({
    topic_id: z.string().uuid(),
    value: z.number().int().min(1).max(5),
    write_in_text: z.string().max(500).optional(),
  })).min(1).max(100),
});
```

**Route 1: PUT /stances/:politicianId/:topicId (single write)**

1. Validate politicianId and topicId are UUIDs (regex check, 422 if not)
2. Parse body with singleStanceSchema (422 on failure)
3. Get user's grants from `getCachedUserRoles(userId)`
4. Call `getPoliticianJurisdiction(politicianId)` — 404 if politician not found
5. Call `getMatchingGrant(grants, politicianId, politicianGeoid)` — 403 if null returned, with message "You do not have permission to edit stances for this politician"
6. Begin transaction via `pool.connect()`:
   a. SELECT current value: `SELECT value, write_in_text FROM inform.politician_answers WHERE politician_id = $1 AND topic_id = $2`
   b. Verify topic exists: `SELECT id FROM inform.compass_topics WHERE id = $1 AND is_live = true` — 404 if not found
   c. UPSERT stance: `INSERT INTO inform.politician_answers (politician_id, topic_id, value, write_in_text) VALUES ($1, $2, $3, $4) ON CONFLICT (politician_id, topic_id) DO UPDATE SET value = EXCLUDED.value, write_in_text = EXCLUDED.write_in_text`
   d. Write audit log via `writeStanceAuditLog(client, { actorId, targetUserId: actorId, roleGrantId: matchingGrant.id, featureScope: matchingGrant.feature_scope, jurisdictionGeoid: matchingGrant.jurisdiction_geoid, resourceId: matchingGrant.resource_id, topicId, oldValue: prev?.value ?? null, newValue: value, writeInTextChanged: (prev?.write_in_text ?? null) !== (write_in_text ?? null) })`
   e. COMMIT
7. Return 200 with `{ politician_id, topic_id, value, write_in_text: write_in_text ?? null }`
8. ROLLBACK + release in catch/finally (follow vqService.ts pattern exactly)

**CRITICAL: `roleGrantId` must be `matchingGrant.id`** — this is the user_roles ROW UUID (added to UserRoleGrant in Plan 01). Do NOT use `matchingGrant.role_id` which is the roles DEFINITION UUID from public.roles. The audit log needs to trace back to the specific grant row that authorized the write.

**Route 2: PUT /stances/:politicianId/bulk (batch write)**

1. Validate politicianId is UUID
2. Parse body with bulkStanceSchema (422 on failure)
3. Get grants, politician jurisdiction, matching grant (same as single — 404/403 on failure)
4. Begin transaction:
   a. Verify ALL topic_ids exist and are live in one query: `SELECT id FROM inform.compass_topics WHERE id = ANY($1) AND is_live = true` — if count !== stances.length, ROLLBACK and return 422 with invalid topic IDs listed
   b. Fetch ALL current values: `SELECT topic_id, value, write_in_text FROM inform.politician_answers WHERE politician_id = $1 AND topic_id = ANY($2)`
   c. For each stance in the batch:
      - UPSERT into inform.politician_answers
      - Write audit log entry (one row per topic changed — skip if value AND write_in_text unchanged)
      - Use `matchingGrant.id` for roleGrantId (same as single route)
   d. COMMIT
5. Return 200 with `{ politician_id, updated: N }` where N is count of stances actually written
6. ROLLBACK + release in catch/finally

**Error responses (consistent with codebase):**
- 401: `{ error: 'unauthorized' }` (from requireAuth)
- 403: `{ error: 'forbidden' }` (from requireRole) or `{ code: 'FORBIDDEN', message: '...' }` (from handler jurisdiction check)
- 404: `{ code: 'NOT_FOUND', message: 'Politician not found' }` or `{ code: 'NOT_FOUND', message: 'Topic not found or not live' }`
- 422: `{ code: 'VALIDATION_ERROR', message: '...' }`
- 500: `{ code: 'INTERNAL_ERROR', message: 'An unexpected error occurred' }`

**Important:** Import `pool` from the same location as compassService.ts and vqService.ts use it (likely `../lib/db.js` or `../lib/supabase.js` — check the import pattern).
