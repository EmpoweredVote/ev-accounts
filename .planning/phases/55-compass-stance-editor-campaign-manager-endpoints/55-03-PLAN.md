Add a new GET route to the existing compassContributor.ts router (created in Plan 02).

**Route: GET /contributors/politicians**

Middleware: `requireAuth` then `requireRole(['compass_stance_editor', 'campaign_manager'])`

Handler logic:
1. Get user's grants: `const grants = await getCachedUserRoles(userId)`
2. Filter grants to only compass-relevant roles: `grants.filter(g => ['compass_stance_editor', 'campaign_manager'].includes(g.slug))`
3. Call `getContributorPoliticians(filteredGrants)` from stanceService.ts
4. Return 200 with the array (may be empty — that's a valid 200 response per LOCKED decisions)

**Response shape:**
```json
[
  {
    "id": "uuid",
    "first_name": "string",
    "last_name": "string",
    "full_name": "string",
    "office_title": "string",
    "photo_url": "string",
    "home_jurisdiction_geoid": "string | null"
  }
]
```

**Important notes:**
- This does NOT modify the existing `GET /compass/politicians` route (that's in compass.ts, untouched)
- Politician records only — no stances included (per LOCKED decisions: "stances fetched separately via existing GET /compass/politicians/:id/answers")
- Deduplicate results if a user has multiple grants that resolve to overlapping politician sets (e.g., both a campaign_manager for politician X and a stance_editor for politician X's jurisdiction)
- Register this route BEFORE the `/:politicianId` parameterized routes to prevent Express from capturing "contributors" as a politicianId

**Route registration order in compassContributor.ts must be:**
1. `GET /contributors/politicians` (specific path)
2. `PUT /stances/:politicianId/bulk` (specific sub-path before single)
3. `PUT /stances/:politicianId/:topicId` (parameterized)
