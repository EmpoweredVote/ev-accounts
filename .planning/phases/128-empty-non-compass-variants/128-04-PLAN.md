<interfaces>
Auto-bump pipeline (from CLAUDE.md and ev-ui/README-AUTOBUMP.md):

1. `cd ev-ui && npm version minor` — bumps package.json version + creates a git tag (default tag format `v{version}`)
2. `git push origin main --follow-tags` — pushes commits + the new tag
3. The tag push triggers `.github/workflows/publish.yml`:
   - Runs `npm run build`, then `npm publish` via OIDC trusted publishing (no NPM_TOKEN, automatic provenance)
   - Fires `repository_dispatch` to: CompassV2, essentials, read-rank, civic-spaces (using DISPATCH_TOKEN — fine-grained PAT)
4. Each consumer's `.github/workflows/ev-ui-bump.yml` opens a PR. For minor and patch bumps, it auto-merges if `build-check.yml` is green.
5. Render auto-deploys each consumer on merge to main.

Why minor (not patch):
- Plan 02 adds two new public props: `variant` and `onBuildCompass`
- New public API surface = minor bump per semver (major would be a breaking change)
- Defaults preserve Phase 127 callers, so it is non-breaking — minor is correct, not major

Pre-publish checklist (must hold true from Plan 02):
- `cd ev-ui && npm run build` exits 0
- `ev-ui/src/CompassCardHorizontal.jsx` contains the literal strings "Build your compass" and "Compass currently unavailable for this role." (verified by Plan 02 acceptance)
- The `variant` prop has default `'compass'` so existing callers do not regress
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local dev -> npm registry (via OIDC) | Publish step runs in GitHub Actions; OIDC trusted publishing replaces long-lived NPM_TOKEN. Provenance attestation is automatic. |
| ev-ui repo -> consumer repos | `repository_dispatch` carries a fine-grained `DISPATCH_TOKEN` (PAT). Token is repo-scoped and limited to dispatch-only operations. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-128-04-01 | Tampering | npm publish artifact | accept | OIDC trusted publishing produces provenance attestations; the artifact is signed by GitHub's OIDC identity. No NPM_TOKEN exposure. |
| T-128-04-02 | Elevation of Privilege | DISPATCH_TOKEN | accept | Fine-grained PAT scoped to `repository_dispatch` only, per ev-ui/README-AUTOBUMP.md. Token rotation is a separate concern (not in Phase 128 scope). |
| T-128-04-03 | Spoofing | auto-merged consumer PR | accept | `build-check.yml` gates the merge — a build failure blocks the auto-merge. The merge is reviewable via git history. |
| T-128-04-04 | Denial of Service | publish.yml run | accept | Workflow is idempotent; if it fails, re-tagging or manual `npm publish` is the documented fallback (CLAUDE.md ev-ui section). |

No new server-side application surface introduced. The publish pipeline is established CI infrastructure that has shipped multiple prior ev-ui versions without incident.
</threat_model>
