Then write `backend/migrations/267_ut_2026_primary.sql` following these rules:

**Structure:**
```
-- Migration 267: UT 2026 Primary — Phase 99 Plan 03
-- Seeds election, races, and race_candidates for the Utah June 23, 2026 primary.
-- Idempotent: ON CONFLICT DO NOTHING throughout.
-- Source: backend/data/election-research/2026-06-23-utah-primary.csv
```

**Section 1 — Government stub (if not found in DB query):**
Use `INSERT INTO essentials.governments (name, state_abbreviation) VALUES ('State of Utah', 'UT') ON CONFLICT DO NOTHING` (or skip entirely if row already exists — check query result first).

**Section 2 — Election row:**
```sql
INSERT INTO essentials.elections (name, election_date, election_type, jurisdiction_level, state)
VALUES ('UT 2026 Primary', '2026-06-23', 'primary', 'state', 'UT')
ON CONFLICT (name, election_date, state) DO NOTHING;
```

**Section 3 — Races and race_candidates in a DO $$ block:**

The unique constraint on races is `UNIQUE (election_id, position_name, primary_party)`. For primary races, the ON CONFLICT clause is `ON CONFLICT (election_id, position_name, primary_party) DO NOTHING`.

Group CSV rows by `(position_name, primary_party)` to produce one race per unique combo. Each race's `primary_party` comes from the CSV column. `seats` is 1 for all CSV rows. `office_id` is NULL for all races (UT legislative offices are not yet in DB).

For race_candidates, use `IF NOT EXISTS (SELECT 1 FROM essentials.race_candidates WHERE race_id = v_race AND full_name = '<full_name>') THEN INSERT ... END IF` — this is the established idempotency pattern from migration 183.

Set `politician_id` to the UUID from the CSV column when non-empty, NULL otherwise. Cast non-null IDs as `::uuid`. Set `candidate_status = 'active'` for all rows (all CSV rows are active or 'filed' per the status column — use the CSV value). Set `is_incumbent` from CSV boolean column. Set `source = 'https://vote.utah.gov/2026-candidate-filings/'`.

Handle CSV note rows (lines starting with `#`) — these are comments in the raw file, not data rows.

Note: Line 156-162 of the CSV has a 6-column variant with office_id embedded (Brady Brammer, Kelly Smith, Kandee Myers for SD 21; Keith Grover, Tucker Smith for SD 23). Those office_ids go on the `essentials.races` row for those districts, not as candidate field.

District types present in CSV: NATIONAL_LOWER, STATE_UPPER, STATE_LOWER, COUNTY, SCHOOL. All map directly to races `position_name` column — no district lookup needed for UT since office_id is NULL for most rows.

**Section 4 — New politician rows:**
For any candidate that has a non-null `politician_id` in the CSV, verify the row exists (done in pre-migration query above). Do NOT insert politicians in this migration — politicians records are managed separately and the UUID references are trusted from the CSV research.
