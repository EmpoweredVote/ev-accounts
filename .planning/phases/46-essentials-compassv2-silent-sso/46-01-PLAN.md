Add a `publicFetch` function to `C:/Transparent Motivations/essentials/src/lib/auth.js`. This resolves the open question from RESEARCH — Essentials WILL have publicFetch (same signature as CompassV2's publicFetch).

publicFetch is identical to apiFetch but does NOT clear the token or call redirectToLogin on 401. It simply returns the raw response. This is critical because the SSO flow may store a token that subsequently fails the /account/me check — using apiFetch would trigger a redirect loop.

Implementation:

```javascript
export async function publicFetch(path, options = {}) {
  const token = getToken();
  return fetch(`${API_BASE}${path}`, {
    ...options,
    headers: {
      'Content-Type': 'application/json',
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
      ...options.headers,
    },
  });
}
```

Place it directly after the existing `apiFetch` function. It uses the same `API_BASE`, `getToken`, and header pattern — the only difference is no 401 handling (no clearToken, no redirectToLogin).

Replace with:

const logout = async () => {
  try {
    const token = getToken();

      method: 'POST',

        ...(token ? { Authorization: `Bearer ${token}` } : {}),
