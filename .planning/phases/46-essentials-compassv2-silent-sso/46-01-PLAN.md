Replace the current `logout` function in CompassContext.jsx. The current implementation uses `apiFetch('/auth/logout', { method: 'POST' })` which does NOT send `credentials: 'include'`, so the httpOnly ev_session cookie is never cleared.

New logout implementation:

```javascript
const logout = async () => {
  try {
    const token = getToken();
    await fetch('/api/auth/logout', {
      method: 'POST',
      credentials: 'include',
      headers: {
        ...(token ? { Authorization: `Bearer ${token}` } : {}),
      },
    });
  } catch {
    // Network error — clear local state anyway
  }
  clearToken();
  setIsLoggedIn(false);
  setUserName(null);
  setUserAnswers([]);
  setSelectedTopics([]);
  setVerdicts({});
};
```

Key changes:
- Use native `fetch` with `credentials: 'include'` (NOT apiFetch — apiFetch doesn't send credentials)
- Include Bearer token in Authorization header for Supabase session revocation
- Always clear local state in the finally path, regardless of API call success/failure
- No navigate or redirect after logout — user stays on current page (per locked decisions)
- The URL is `/api/auth/logout` (Netlify proxy handles routing to ev-accounts)
