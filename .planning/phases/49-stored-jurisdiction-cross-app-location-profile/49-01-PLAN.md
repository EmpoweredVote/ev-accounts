  <action>
Create a Supabase migration that:

1. Adds 7 new columns to `connect.connected_profiles`:
   - `congressional_geo_id TEXT DEFAULT NULL`
   - `state_senate_geo_id TEXT DEFAULT NULL`
   - `state_house_geo_id TEXT DEFAULT NULL`
   - `county_geo_id TEXT DEFAULT NULL`
   - `school_district_geo_id TEXT DEFAULT NULL`
   - `jurisdiction_state TEXT DEFAULT NULL` (2-letter abbreviation)
   - `jurisdiction_city TEXT DEFAULT NULL`

2. Backfills existing users by looping through all connected_profiles where `location_consent = true`:
   ```sql
   DO $$
   DECLARE
     r RECORD;
     j RECORD;
   BEGIN
     FOR r IN SELECT user_id FROM connect.connected_profiles WHERE location_consent = true LOOP
       SELECT * INTO j FROM connect.resolve_user_jurisdiction(r.user_id);
       IF j IS NOT NULL AND j.congressional IS NOT NULL THEN
         UPDATE connect.connected_profiles SET
           congressional_geo_id = j.congressional,
           state_senate_geo_id = j.state_senate,
           state_house_geo_id = j.state_house,
           county_geo_id = j.county,
           school_district_geo_id = j.school_district,
           updated_at = now()
         WHERE user_id = r.user_id;
       END IF;
     END LOOP;
   END $$;
   ```

Note: `jurisdiction_state` and `jurisdiction_city` are NOT backfillable from the RPC (it doesn't return state/city). These will be populated on the next set-location call for each user. This is acceptable — the geocodingService return value will provide state and city going forward.

IMPORTANT: Use the Supabase MCP `apply_migration` tool. Migration name: `add_jurisdiction_columns_to_connected_profiles`.
