  <name>Task 1: Add silent SSO check to App.tsx mount useEffect</name>
  <files>app/src/App.tsx</files>
  <action>
In `App.tsx`, insert the silent SSO check in the `else` branch of the mount useEffect (line 76-78, where currently only `setLoading(false)` is called when no stored token exists).

**Define `silentSsoCheck` as an inline async function** at the top of the useEffect callback (or just above the else branch). It must:

1. Call `fetch` against the accounts API SSO endpoint with `credentials: 'include'`:
   - URL: `${import.meta.env.VITE_API_URL || ''}/api/auth/session` (matches the existing `API_BASE` pattern in `lib/api.ts` but use VITE_API_URL directly since this is a raw fetch, not apiFetch)
   - IMPORTANT: The `apiFetch` helper in `lib/api.ts` prepends `/api` to the path. For the SSO check, use raw `fetch` directly with the full path `/api/auth/session` to avoid double-prefixing.
   - Options: `{ credentials: 'include' }` — no Authorization header (the cookie IS the credential)
   - 3-second timeout via `AbortController` + `setTimeout`

2. Handle responses:
   - 401: return null immediately (not logged in elsewhere, no retry)
   - 200 (ok): parse JSON as `{ access_token: string; refresh_token: string }`, return it
   - 5xx or network error: retry ONCE after 1-second delay (same fetch call), then return null if retry fails
   - AbortController timeout: return null

3. In the `else` branch (no stored token):
   - Call `silentSsoCheck()`
   - If result is non-null:
     - Write `result.access_token` to `localStorage.setItem('ev_token', ...)`
     - Set token in store: `useAuthStore.setState({ accessToken: result.access_token })`
     - Fetch `/account/me` via `apiFetch<MeResponse>('/account/me')` and call `setAuth(result.access_token, user)` — reuse the exact same pattern as the hash-fragment branch (lines 39-53)
     - On fetch failure: call `clearAuth()`
   - If result is null: call `setLoading(false)` (existing behavior — unauthenticated)

4. **Spinner delay (150ms):** The SSO check should NOT show a spinner unless it takes >150ms. The current behavior is `isLoading: true` by default in the auth store. To implement the delay:
   - At the start of the else branch, immediately set `setLoading(false)` (hide any loading state)
   - Start a 150ms timer: `const spinnerTimer = setTimeout(() => setLoading(true), 150)`
   - After `silentSsoCheck()` resolves (whether success or null), clear the timer: `clearTimeout(spinnerTimer)`
   - Then proceed with the existing logic (setAuth on success, setLoading(false) on null)
   - This means: fast SSO checks (<150ms) never show a spinner; slow ones show it after 150ms

**Do NOT modify the hash-fragment branch (lines 27-55) or the stored-token branch (lines 58-75).**
