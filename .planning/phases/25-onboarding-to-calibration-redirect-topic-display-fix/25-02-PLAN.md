Fix the post-onboarding redirect so users enter the calibration flow instead of seeing a dead-end "need more topics" message on /results.

**Current behavior analysis:**

The Onboarding.jsx `handleNext` (line ~104) and `handleClose` (line ~74) both call `navigate("/results")`. When a fresh user arrives at /results (Compass.jsx), the calibration overlay logic kicks in:

- `needsCalibration` checks: `unansweredCompassTopics.length > 0 && !calibrationSkipped && !calibrationCompleted`
- BUT for a brand-new user with NO selectedTopics, `unansweredCompassTopics` is EMPTY (no topics selected = nothing is unanswered), so `needsCalibration` is `false`.
- The `useEffect` that auto-routes to calibration pick screen (line ~280-285) checks `!showChart && !calibrationActive && selectedTopics.length > 0` — this also fails because `selectedTopics.length === 0`.
- So the user sees the BelowThresholdChart which shows "Answer 3 more topics to see your compass" — the dead-end message.

**The fix:**

The calibration overlay needs to trigger for users who have completed onboarding but have NOT yet calibrated (no selectedTopics, no answers). This is the "first-time on compass page" scenario.

In Compass.jsx, update the calibration trigger logic:
1. The `needsCalibration` condition currently requires `unansweredCompassTopics.length > 0` — this excludes users with zero selected topics.
2. Add a new condition: if the user has NO selectedTopics AND has NOT skipped AND has NOT completed calibration, they need calibration. This captures the fresh-from-onboarding state.
3. Specifically, change the calibration trigger so that fresh users (selectedTopics.length === 0, no calibration_skipped, no calibration_completed) also see the calibration overlay starting at the welcome step.

**Implementation approach:**

In Compass.jsx, modify the `needsCalibration` derivation (around line ~268):
```javascript
// OLD:
const needsCalibration = unansweredCompassTopics.length > 0 && !calibrationSkipped && !calibrationCompleted;

// NEW: Also trigger for fresh users with no topics selected (first-time after onboarding)
const needsCalibration = (!calibrationSkipped && !calibrationCompleted) &&
  (unansweredCompassTopics.length > 0 || selectedTopics.length === 0);
```

This means:
- Fresh user from onboarding (0 selected topics, no skip/complete flags) -> `needsCalibration` = true -> CalibrationOverlay shows welcome step
- User who picked topics but hasn't answered them all -> `needsCalibration` = true -> CalibrationOverlay shows answer step (resumeMode)
- User who completed calibration -> `calibrationCompleted` = true -> `needsCalibration` = false -> sees chart
- User who skipped calibration -> `calibrationSkipped` = true -> `needsCalibration` = false -> sees BelowThresholdChart

Also remove or guard the auto-route to pick screen useEffect (line ~280-285) so it doesn't conflict — it already checks `selectedTopics.length > 0`, so it won't fire for fresh users, which is correct.

**Verify edge cases from CONTEXT.md decisions:**
- Guests and logged-in users follow the same flow (both use localStorage flags for calibration state)
- Back button during calibration: CalibrationOverlay.handleBack goes to pick step from answer index 0, or does nothing in resumeMode — never exits to onboarding. The welcome step has no back — only "Get Started" and "Skip for now". This is already correct per ONBOARD-04.
- If user completed onboarding and returns: `help_seen` localStorage prevents re-showing onboarding. HelpGuard redirects to current route. If they haven't calibrated, they'll hit /results and see calibration overlay again. This is correct.

**No changes needed to Onboarding.jsx** — the redirect to /results is correct because that's where the calibration overlay lives. The fix is entirely in Compass.jsx's calibration trigger logic.
