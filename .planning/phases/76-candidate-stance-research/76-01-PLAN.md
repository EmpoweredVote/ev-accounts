**Body structure — one section per candidate, alphabetical by surname:**

For each candidate row in the CSV, emit two upserts:

```sql
-- ----- Steve Marshall (AL, -400101) / abortion -----
INSERT INTO inform.politician_answers (politician_id, topic_id, value)
VALUES ('a9e04e1e-92d4-44e4-a411-b6fe4814290a',
        '<topic_id from CSV>',
        <value from CSV>)
ON CONFLICT (politician_id, topic_id)
DO UPDATE SET value = EXCLUDED.value;

INSERT INTO inform.politician_context (politician_id, topic_id, reasoning, sources)
VALUES ('a9e04e1e-92d4-44e4-a411-b6fe4814290a',
        '<topic_id from CSV>',
        $$<reasoning text verbatim from CSV>$$,
        ARRAY['<source_url_1>',
              '<source_url_2>']::text[])
ON CONFLICT (politician_id, topic_id)
DO UPDATE SET reasoning = EXCLUDED.reasoning, sources = EXCLUDED.sources;
```

**Critical rules for CSV → SQL conversion:**

1. Dollar-quote reasoning with `$$...$$` — reasoning text contains apostrophes
   and quotes; dollar-quoting avoids escaping hell. If reasoning itself
   contains `$$`, use a tagged variant: `$REASON$...$REASON$`.

2. Sources array: include ONLY non-empty URLs. If `source_url_2` and
   `source_url_3` are empty, emit `ARRAY['url1']::text[]`, not
   `ARRAY['url1', '', '']::text[]`.

3. If the CSV uses pipe-separated sources (one column with
   `url1|url2|url3`), split on `|` during conversion and strip empties.

4. UTF-8 without BOM. Some candidate names or reasoning may contain
   accented characters or non-ASCII — preserve them exactly.

5. Section headers as SQL comments separate each candidate block for
   readability and grep-ability.

6. Use the exact UUIDs from the candidate inventory table — do not
   re-look-up by name. Hard-code the UUIDs.
