**Body structure — one section per candidate, alphabetical by surname:**

For each candidate row in the CSV, emit two upserts using the exact pattern
established in Phase 74 (see context @74-01-PLAN.md Section A):

```sql
-- ----- Scott Colom (MS, -400129) / abortion -----
INSERT INTO inform.politician_answers (politician_id, topic_id, value)
VALUES ('4fd59af4-eca7-4cdc-9082-178278ce3dc8',
        '<topic_id from CSV>',
        <value from CSV>)
ON CONFLICT (politician_id, topic_id)
DO UPDATE SET value = EXCLUDED.value;

INSERT INTO inform.politician_context (politician_id, topic_id, reasoning, sources)
VALUES ('4fd59af4-eca7-4cdc-9082-178278ce3dc8',
        '<topic_id from CSV>',
        $$<reasoning text verbatim from CSV>$$,
        ARRAY['<source_url_1>',
              '<source_url_2>']::text[])
ON CONFLICT (politician_id, topic_id)
DO UPDATE SET reasoning = EXCLUDED.reasoning, sources = EXCLUDED.sources;
```

**Critical rules for CSV → SQL conversion (identical to Plans 76-01 and 76-02):**

1. Dollar-quote reasoning with `$$...$$`. Use tagged variant `$REASON$...$REASON$`

2. Sources array: include ONLY non-empty URLs. Strip empties.

3. If sources are pipe-separated in one column, split on `|`.

4. UTF-8 without BOM. Preserve accented characters exactly.

5. Section headers as SQL comments separate each candidate block.

6. Use the exact UUIDs from the candidate inventory table.

**Topic UUID handling:** Use the `topic_id` column directly from the CSV.
