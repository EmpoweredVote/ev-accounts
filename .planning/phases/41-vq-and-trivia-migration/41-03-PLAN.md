**Read 41-01-SUMMARY.md first** to get the exact table inventory and user_id column detection results. The RLS category for each table depends on whether it has a user_id (or player_id/created_by) column.

**RLS Category Assignment Rules (from Phase 34 pattern):**

1. **Owner-read** — Tables with user_id/player_id column: Only the row owner can SELECT their own rows.
   - Policy: `USING ((SELECT auth.uid()) = user_id)` (cast to uuid if column is text)
   - TO: `authenticated`

2. **Authenticated-read** — Tables with shared game data that requires login (e.g., active quest state, consensus data).
   - Policy: `USING (true)`
   - TO: `authenticated`

3. **Public-read** — Reference/content tables (topics, questions, collections, quest templates).
   - Policy: `USING (true)`
   - TO: `anon, authenticated`

**Expected categories (verify against Plan 01 findings):**

validation_quests schema:
- Tables with user_id -> owner-read (submissions, veracity profiles, player progress)
- Tables without user_id -> authenticated-read or public-read (quest definitions, consensus thresholds)

trivia schema:
- Tables with user_id/player_id -> owner-read (player stats, scores)
- Tables without user_id -> public-read (topics, questions, collections, election races)

**Write the migration file following Phase 34 patterns exactly:**

```sql
-- Phase 41: RLS for validation_quests and trivia schemas
-- Pattern: Phase 34 (20260319000044_phase34_essentials_rls.sql)

-- ============================================
-- VALIDATION_QUESTS SCHEMA
-- ============================================

-- Owner-read tables (have user_id column)
ALTER TABLE validation_quests.<table_name> ENABLE ROW LEVEL SECURITY;
CREATE POLICY "<table_name>: owner select"
  ON validation_quests.<table_name>
  FOR SELECT
  TO authenticated
  USING ((SELECT auth.uid()) = user_id);

-- ... repeat for each owner-read table

-- Authenticated-read tables (shared game data, no user_id)
ALTER TABLE validation_quests.<table_name> ENABLE ROW LEVEL SECURITY;
CREATE POLICY "<table_name>: authenticated read"
  ON validation_quests.<table_name>
  FOR SELECT
  TO authenticated
  USING (true);

-- ... repeat for each authenticated-read table

-- ============================================
-- TRIVIA SCHEMA
-- ============================================

-- Public-read tables (game content)
ALTER TABLE trivia.<table_name> ENABLE ROW LEVEL SECURITY;
CREATE POLICY "<table_name>: public read"
  ON trivia.<table_name>
  FOR SELECT
  TO anon, authenticated
  USING (true);

-- ... repeat for each public-read table

-- Owner-read tables (player-linked)
ALTER TABLE trivia.<table_name> ENABLE ROW LEVEL SECURITY;
CREATE POLICY "<table_name>: owner select"
  ON trivia.<table_name>
  FOR SELECT
  TO authenticated
  USING ((SELECT auth.uid()) = user_id);

-- ... repeat for each owner-read table
```

**Important notes:**
- If user_id column is TEXT type (not UUID), use `user_id::uuid = (SELECT auth.uid())` -- same cast pattern as Phase 34 compass tables.
- vq_service and trivia_service roles have BYPASSRLS, so they are NOT affected by these policies. No need to add them to policy TO clauses.
- SELECT-only policies. VQ writes go through vq_service (BYPASSRLS). Trivia writes go through trivia_service or ev-accounts service_role. No INSERT/UPDATE/DELETE policies needed for anon/authenticated.
