**Smoke Test A: VQ confirm-stance flow (CONS-18)**

The `POST /api/vq/confirm-stance` endpoint is on ev-accounts (not VQ). It calls `connect.confirm_vq_stance` RPC. This tests that the VQ confirmation flow still works end-to-end after all Phase 41 changes.

Ask the user for:
- ev-accounts API URL (e.g. `https://ev-accounts-xxxx.onrender.com`)
- A valid `politician_id` (essentials.politicians UUID)
- A valid `topic_id` (inform.compass_topics UUID)
- The `VQ_GEMS_SERVICE_KEY` value (or `X-Gems-Service-Key` header value)

If user cannot provide these, use the Supabase MCP to fetch valid UUIDs:
```sql
-- Get a valid politician_id
SELECT id FROM essentials.politicians LIMIT 1;

-- Get a valid topic_id
SELECT id FROM inform.compass_topics WHERE is_live = true LIMIT 1;
```

Run the smoke test:
```bash
curl -s -X POST https://<ev-accounts-url>/api/vq/confirm-stance \
  -H "X-Gems-Service-Key: <VQ_GEMS_SERVICE_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "politician_id": "<valid-essentials-uuid>",
    "topic_id": "<valid-compass-topic-uuid>",
    "confirmed_value": 3,
    "correct_user_ids": [],
    "incorrect_user_ids": [],
    "idempotency_key": "smoke-test-phase41-final-001",
    "gems_amount": 1
  }'
```
Expected: HTTP 200, body contains `politician_id`, `topic_id`, `confirmed_value`.
If `replayed: true` is returned, the idempotency key was already used — change the key suffix and retry.

**Smoke Test B: Leaderboard profiles endpoint (new in Phase 41)**

Get a valid user_id from trivia.player_stats:
```sql
SELECT user_id FROM trivia.player_stats LIMIT 1;
```

Test the endpoint:
```bash
curl -s "https://<ev-accounts-url>/api/trivia/leaderboard-profiles?user_ids=<user_id>" \
  -H "X-Service-Key: <TRIVIA_SERVICE_KEY>"
```
Expected: HTTP 200, body `{ "profiles": [{ "user_id": "...", "display_name": "...", "pseudonym": "...", "total_xp": N, "level": N, "avatar_url": null }] }`.

Note: if player_stats user_ids don't match public.users (edge case with test data), the profile array may be empty — that's still a 200 and correct behavior (LEFT JOIN returns nothing for unknown user_ids).

**If either smoke test fails:**
- 401/403 on confirm-stance: VQ gems service key issue (not Phase 41 related)
- 500 on confirm-stance: check ev-accounts logs; may be RLS blocking confirm_vq_stance RPC writes
- 401/403 on leaderboard: TRIVIA_SERVICE_KEY mismatch
- 500 on leaderboard: check pool.query() column name assumptions in trivia.ts
- Connection error from CTC (visible in Render logs): trivia_service password or role issue

**Document results** in 41-04-SUMMARY.md: HTTP status, response shape, any issues encountered.
