**Read `backend/src/middleware/serviceKeyAuth.ts`** to understand how service key auth works. CTC already uses `TRIVIA_SERVICE_KEY` for XP awards (serviceKey: `civic_trivia_championship_score`). This endpoint uses the same auth.

**Create `backend/src/routes/trivia.ts`:**

```typescript
import { Router } from 'express';
import { pool } from '../lib/db';
import { serviceKeyAuth } from '../middleware/serviceKeyAuth';

const router = Router();

// GET /api/trivia/leaderboard-profiles?user_ids=uuid1,uuid2,uuid3
// Auth: TRIVIA_SERVICE_KEY (service-to-service, not user-facing)
// Returns: pseudonym, total_xp, level, avatar for each requested user_id
// Used by CTC leaderboard to display player display info
router.get(
  '/leaderboard-profiles',
  serviceKeyAuth(['civic_trivia_championship_score']),
  async (req, res) => {
    const raw = req.query.user_ids as string | undefined;
    if (!raw) {
      return res.status(400).json({ error: 'user_ids query param required' });
    }

    const userIds = raw
      .split(',')
      .map((id) => id.trim())
      .filter((id) => id.length > 0);

    if (userIds.length === 0) {
      return res.status(400).json({ error: 'user_ids must contain at least one UUID' });
    }

    if (userIds.length > 100) {
      return res.status(400).json({ error: 'user_ids max 100 per request' });
    }

    const result = await pool.query<{
      user_id: string;
      display_name: string;
      pseudonym: string | null;
      total_xp: number;
      level: number;
      avatar_url: string | null;
    }>(
      `SELECT
         u.id AS user_id,
         u.display_name,
         cp.pseudonym,
         COALESCE(cp.total_xp, 0) AS total_xp,
         COALESCE(cp.level, 1) AS level,
         NULL::text AS avatar_url
       FROM public.users u
       LEFT JOIN connect.connected_profiles cp ON cp.user_id = u.id
       WHERE u.id = ANY($1::uuid[])`,
      [userIds]
    );

    return res.json({ profiles: result.rows });
  }
);

export default router;
```

**Notes on the query:**
- `pool.query()` required — connect schema is not PostgREST-exposed (established pattern from Phase 35)
- `avatar_url` returns `null` for now — avatars not yet stored anywhere; CTC continues using colored circle
- `display_name` included alongside `pseudonym` — CTC can choose which to display
- `COALESCE(cp.level, 1)` — users who haven't leveled up yet default to level 1
- `LEFT JOIN` — users without a connected_profile (inform-tier) still appear with null pseudonym/0 xp/1 level

**Check `connected_profiles` column names** before writing: verify `total_xp`, `level`, `pseudonym` are the actual column names. Read `backend/src/routes/account.ts` or an existing migration to confirm. Adjust the query if column names differ.
