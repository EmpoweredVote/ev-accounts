# Phase 999.1 (BACKLOG): Speaker Identification for All Meeting Participants

**Status:** Backlog — not yet scheduled to a milestone
**Captured:** 2026-04-12
**Origin:** Discussion during Phase 111 verification run — uncovered regressions and design gaps when Phase 111's roster gate was applied to a real meeting

## Problem

CouncilScribe's Phase 111 roster-gated identification correctly rejects phantom council names (e.g. Whisper mishearing "Piedmont-Smith" as "Piafra") but creates a regression for legitimate non-council speakers:

1. **Invited presenters** — city staff, department heads, outside experts presenting to council
2. **Recurring staff attendees** — city attorney, clerk, mayor's liaison, department heads who attend most/all meetings
3. **Public commenters** — citizens speaking during public comment periods

The Phase 111 roster gate in `apply_pattern_matching` rejects ANY pattern-matched name whose surname doesn't fuzzy-match the 9-member council roster. This blocks legitimate L2 identifications like "Thank you, Jane Smith" or "As the planning director...". We temporarily worked around this for the City Clerk by adding Nicole Bolden directly to the council chamber via an `offices` row, but this is a hack — she's staff, not an elected member.

Additionally, the LLM (Layer 3) has no roster gating at all, so phantom hallucinations like "Piafra" still slip through L3 without being rejected. In our Phase 111 test run on the 2026-02-25 Bloomington meeting, the LLM produced "Piafra" for SPEAKER_01 and SPEAKER_07 even after all Phase 111 fixes.

## Gap in current design

The `SpeakerMapping` model has no `speaker_type` field to distinguish:
- `council_member` — elected, has `politician_slug`
- `staff` — recurring non-elected attendees (clerk, attorney, department heads)
- `presenter` — one-time invited speakers
- `public_commenter` — citizens speaking during public comment
- `unknown` — unidentified

Downstream consumers (transcript display, summary generation, speaker cards) can't differentiate these roles today.

## Target design

Extend the data model and identification logic to properly represent all meeting participants.

### 1. Schema changes in `essentials` and/or `meetings` schema

**Chamber attendees / staff:**
- Add an `essentials.chamber_attendees` table OR an `is_staff: boolean` flag on `essentials.offices`
- Represents recurring non-elected attendees (city clerk, city attorney, mayor's liaison, department heads)
- These should appear in the roster API response, flagged as staff
- Populates roster cache so CouncilScribe's L2 pattern matcher accepts "City Clerk Bolden", "City Attorney Jones", etc.
- Lets us roll back the Bolden-in-council-chamber hack

**Rolling public commenter record:**
- Many councils have a "same 10 people" pattern — recurring public commenters who speak at most meetings
- Proposed: `meetings.recurring_commenters` table keyed on `(body_slug, name)` with fields like:
  - `first_seen_at`, `last_seen_at`, `meeting_count`
  - `aliases` (Whisper variations of their name — normalized forms Whisper misheard them as)
  - `affiliation` (optional — "Bloomington Environmental Commission", etc.)
  - `classification` — some way to group them (activist, business owner, neighborhood rep, etc.) — design TBD, but we need something beyond name-only
- Auto-populated as CouncilScribe processes meetings and identifies public commenters
- Used as a secondary roster during identification: if Whisper mishears "Jane Smith" as "Jain Smyth", fuzzy-match against recurring commenters before giving up
- After N appearances, promote to "known commenter" status

### 2. Speaker type taxonomy

Add `speaker_type` to `SpeakerMapping` with values:
- `council_member` — matches elected member in roster
- `staff` — matches chamber_attendees (clerk, attorney, etc.)
- `presenter` — one-time self-identified speaker (matches `self_identification` pattern, not in roster)
- `public_commenter` — speaks during public comment section, may match recurring_commenters
- `unknown` — unidentified

Each L1/L2/L3 identification layer sets `speaker_type` based on the evidence used for identification.

### 3. Pattern-aware L2 gating

The current Phase 111 L2 gate is indiscriminate. Fix to apply roster-gating only to patterns that imply a council member:
- **Gate:** `roll_call`, `chair_recognition`, `name_addressing` when title is Councilmember/Council President/Mayor
- **Don't gate:** `self_identification`, `title_context`, `name_addressing` with staff/civilian titles

### 4. L3 (LLM) phantom defense

In `correct_mappings`, if LLM-produced name:
- Doesn't fuzzy-match any roster member AND
- Doesn't appear in `recurring_commenters` AND
- Has no strong `self_identification` context in the transcript

...then downgrade the mapping to unidentified. Prevents "Piafra"-style hallucinations surviving through L3.

### 5. Classification for recurring commenters

**Open design question:** how to classify recurring commenters beyond just names.

Options to explore:
- **Manual tagging** — admin UI to label recurring commenters with affiliation/role
- **Self-declared context** — extract from their own speech ("I'm Jane from the Chamber of Commerce")
- **Stance mining** — cluster commenters by the topics/positions they frequently express across meetings
- **Signature phrases** — track phrases each commenter uses repeatedly (could aid voice-profile identification on top of embeddings)

**Goal:** when displaying a transcript, show "Jane Smith (frequent commenter, environmental topics)" instead of just "Jane Smith" or "Speaker 7".

## Why this matters

- **Trust & accuracy:** Public-facing transcripts that identify everyone correctly (council + staff + presenters + commenters) are more valuable than ones that only name council members
- **Civic engagement:** Recurring commenters are often the most engaged citizens — showing their participation history across meetings highlights community voices
- **Downstream features:** Speaker cards, topic attribution, stance tracking all benefit from knowing who's a council member vs. a citizen
- **Scales across bodies:** Same infrastructure works for Bloomington Common Council, Monroe County Council, school boards, etc.
