## Section 2: Base URL

```
Production: https://accounts.empowered.vote/api
```

Note: All paths below are relative to this base URL.

## Section 3: Authentication

**Method:** Bearer token (JWT from Supabase Auth)

```
Authorization: Bearer <access_token>
```

How to get a token: `POST /auth/login` returns `access_token`. Use it on all authenticated endpoints.

Anonymous access: compass read endpoints and answer submission work without a token. Unauthenticated calls receive empty data, not 401 errors.

Endpoints that require auth (will 401 without token):
- `DELETE /compass/answers/me`
- `GET /compass/progress`
- All `/account/*` endpoints
- All `/admin/*` endpoints

## Section 4: Account Endpoints

### GET /account/me

Returns the authenticated user's full profile.

**Auth required:** Yes

**Response:**
```json
{
  "id": "uuid",
  "email": "user@example.com",
  "display_name": "string | null",
  "avatar_url": "string | null",
  "tier": "inform | connected | empowered",
  "completed_onboarding": false,
  "account_standing": "active | suspended",
  "created_at": "ISO8601",
  "updated_at": "ISO8601",
  "connected_profile": {
    "display_name": "string | null",
    "verification_status": "string",
    "tolerance_rating": "number",
    "xp": {
      "total": 0,
      "level": 1,
      "xp_in_level": 0,
      "xp_to_next_level": 100
    },
    "gem_balance": 0,
    "completed_onboarding": false,
    "created_at": "ISO8601"
  },
  "empowered_profile": null
}
```

Notes:
- `completed_onboarding` appears at ROOT for all tiers. Inform-tier users always get `false`.
- `connected_profile` is `undefined` (omitted) for inform-tier users.
- `empowered_profile` is `undefined` (omitted) for non-empowered users.
- `xp` is a structured object, NOT a raw integer.

### GET /admin/me

Returns the authenticated admin's identity.

**Auth required:** Yes (admin JWT)

**Response:**
```json
{
  "isAdmin": true,
  "id": "uuid",
  "email": "admin@example.com"
}
```

## Section 5: Auth Endpoints

### POST /auth/login

**Request:**
```json
{
  "email": "user@example.com",
  "password": "password"
}
```

**Response (200):**
```json
{
  "access_token": "eyJ...",
  "refresh_token": "eyJ...",
  "expires_in": 3600,
  "expires_at": 1234567890,
  "token_type": "bearer",
  "user": {
    "id": "uuid",
    "email": "user@example.com",
    "display_name": null,
    "tier": "inform",
    "account_standing": "active"
  }
}
```

### POST /auth/signup

Creates a new account. Optional `guest_state` migrates anonymous compass answers into the new account atomically.

**Request:**
```json
{
  "email": "user@example.com",
  "password": "minimum8chars",
  "guest_state": {
    "answers": [
      {
        "topic_id": "uuid",
        "value": 3.5,
        "write_in_text": "Optional text for write-in placement"
      }
    ],
    "selected_topics": ["uuid", "uuid"]
  }
}
```

`guest_state` is optional. When omitted, behavior is identical to before.

**Response (201):**
```json
{
  "id": "uuid",
  "message": "Check your email to confirm your account"
}
```

**Notes:**
- Guest state migration is best-effort — if it fails, signup still returns 201. The user can re-select topics after confirming their email.
- `answers[].value` must be a 0.5-increment number between 0.5 and 5.5 (e.g., 1, 1.5, 2, 2.5, 3, 3.5, 4, 4.5, 5).

## Section 6: Compass Endpoints

### GET /compass/topics

Returns all live topics with nested stances.

**Auth:** Optional

**Response (200):** Array of topic objects.
```json
[
  {
    "id": "uuid",
    "title": "string",
    "short_title": "string",
    "question_text": "string",
    "stances": [
      { "value": 1, "text": "Strongly Oppose" },
      { "value": 2, "text": "Oppose" },
      { "value": 3, "text": "Neutral" },
      { "value": 4, "text": "Support" },
      { "value": 5, "text": "Strongly Support" }
    ]
  }
]
```

### GET /compass/categories

Returns categories with nested live topics.

**Auth:** Optional

### GET /compass/answers

Returns the authenticated user's compass responses. Returns `[]` for unauthenticated requests.

**Auth:** Optional (unauthenticated returns `[]`)

**Response (200):**
```json
[
  {
    "topic_id": "uuid",
    "value": 3.5,
    "write_in_text": "string | null",
    "visibility": "private | public",
    "inverted": false,
    "created_at": "ISO8601",
    "updated_at": "ISO8601"
  }
]
```

Note: `value` is NUMERIC — may be an integer (1.0) or half-integer (1.5). CompassV2 should treat it as a float.

### POST /compass/answers

Upserts a single compass response.

**Auth:** Optional (unauthenticated returns `null` — answer is not persisted)

**Request:**
```json
{
  "topic_id": "uuid",
  "value": 3.5,
  "write_in_text": "Optional write-in text",
  "inverted": false
}
```

Constraints:
- `value`: 0.5-increment float, range 0.5–5.5 (use integers 1–5 for predefined stances, half-integers for write-in placements)
- `write_in_text`: max 500 chars, optional
- `inverted`: boolean, default false

**Response (200):** The upserted response object.

**Error (404):** `{ "code": "TOPIC_NOT_FOUND" }` — topic does not exist or is not live.

### POST /compass/answers/batch

Returns answers for a specific list of topic IDs.

**Auth:** Optional (unauthenticated returns `[]`)

**Request:**
```json
{ "ids": ["uuid", "uuid"] }
```

**Response (200):**
```json
[
  { "topic_id": "uuid", "value": 3.5, "write_in_text": "string | null" }
]
```

### GET /compass/selected-topics

Returns the user's saved topic IDs.

**Auth:** Optional (unauthenticated returns `{ topic_ids: [] }`)

**Response (200):**
```json
{ "topic_ids": ["uuid", "uuid"] }
```

Note: Previously returned 403 NOT_CONNECTED for unauthenticated requests. Now returns empty list.

### PUT /compass/selected-topics

Saves the user's selected topic IDs (server-validates all IDs are live topics).

**Auth:** Optional (unauthenticated returns `{ topic_ids: [] }` — selection not persisted)

**Request:**
```json
{ "topic_ids": ["uuid", "uuid"] }
```

**Response (200):**
```json
{ "topic_ids": ["uuid", "uuid"] }
```

**Error (403):** `{ "code": "NOT_CONNECTED" }` — authenticated user has not completed the Connect enrollment flow.

**Error (422):** `{ "code": "INVALID_TOPIC_IDS", "invalid_ids": ["uuid"] }` — one or more topic IDs do not exist or are not live.

### GET /compass/politicians

Returns all politicians.

**Auth:** Optional

### GET /compass/politicians/:id/answers

Returns a politician's stances on all topics they have answered.

**Auth:** Optional

### GET /compass/politicians/:id/:topicId/context

Returns reasoning and sources for a politician's stance on a topic.

**Auth:** Optional

## Section 7: Error Codes

Standard error response shape:
```json
{ "code": "ERROR_CODE", "message": "Human-readable description" }
```

| Code | HTTP | Meaning |
|------|------|---------|
| VALIDATION_ERROR | 422 | Request body failed schema validation |
| INVALID_TOPIC_IDS | 422 | One or more topic IDs invalid or not live |
| TOPIC_NOT_FOUND | 404 | Topic does not exist or is not live |
| NOT_CONNECTED | 403 | User has not completed Connect enrollment |
| AUTH_ERROR | 401 | JWT invalid, expired, or revoked |
| INVALID_CREDENTIALS | 401 | Wrong email or password |
| EMAIL_NOT_VERIFIED | 403 | Email confirmation pending |
| EMAIL_EXISTS | 409 | Account already exists with this email |
| RATE_LIMIT_EXCEEDED | 429 | Too many requests — back off and retry |
| INTERNAL_ERROR | 500 | Unexpected server error |

## Section 8: Anonymous Mode Implementation Notes

CompassV2 anonymous mode design:
1. Show compass to unauthenticated users — GET /compass/topics and GET /compass/categories work without auth.
2. Store answers locally in browser localStorage — do NOT call POST /compass/answers for anonymous users (the server returns null and does not persist).
3. On signup, pass all locally-stored answers in `guest_state.answers` and selected topic IDs in `guest_state.selected_topics`.
4. The accounts API migrates them atomically — if migration fails, signup still succeeds (user loses their anonymous progress, but account creation is not blocked).
