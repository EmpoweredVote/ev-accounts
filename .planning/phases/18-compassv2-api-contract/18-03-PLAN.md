In `backend/src/routes/auth.ts`, extend the signup flow to accept an optional `guest_state` field and migrate it atomically after account creation.

**Step 1: Add guest_state to Zod schema**

The existing `authBodySchema` only validates `email` and `password`. Replace it with a signup-specific schema:

```typescript
const signUpBodySchema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
  guest_state: z.object({
    answers: z.array(z.object({
      topic_id: z.string().uuid(),
      value: z.number().multipleOf(0.5).min(0.5).max(5.5),
      write_in_text: z.string().max(500).optional(),
    })).optional().default([]),
    selected_topics: z.array(z.string().uuid()).optional().default([]),
  }).optional(),
});
```

Keep `authBodySchema` for login (it only needs email + password). The signup route should now use `signUpBodySchema` instead of `authBodySchema`.

**Step 2: Parse guest_state in signup handler**

Change the signup route to use `signUpBodySchema`:

```typescript
router.post('/signup', authLimiter, async (req: Request, res: Response): Promise<void> => {
  const parsed = signUpBodySchema.safeParse(req.body);
  // ... existing error handling unchanged ...

  const { email, password, guest_state } = parsed.data;
  const { data, error } = await signUpWithEmail(email, password);
```

**Step 3: Call migrate_guest_compass_state RPC after successful signup**

After the existing `if (!data.user)` guard and before the `res.status(201).json(...)` call, add:

```typescript
// Migrate guest compass state if provided
if (guest_state && data.user) {
  try {
    await adminRpc('migrate_guest_compass_state', {
      p_user_id: data.user.id,
      p_answers: guest_state.answers ?? [],
      p_selected_topics: guest_state.selected_topics ?? null,
    });
  } catch (migrationErr) {
    // Non-fatal: log error but do not fail signup
    // Guest state migration failure is recoverable — user can re-enter preferences
    console.error('[auth/signup] Guest state migration failed:', migrationErr);
  }
}
```

**Step 4: Add adminRpc import if not already imported**

`adminRpc` is already imported in account.ts. Check auth.ts imports — if `adminRpc` is not yet imported from `'../lib/supabase.js'`, add it:

```typescript
import { signUpWithEmail, signInWithEmail, signOutUser, recordLogout } from '../lib/authService.js';
import { adminRpc } from '../lib/supabase.js';  // add this line
```

**Important design constraints:**
- guest_state is entirely optional. Existing signup calls without it work identically.
- Migration failure does NOT fail signup. The try/catch swallows errors and logs them.
- The RPC call passes `p_selected_topics: null` when `selected_topics` is empty/absent (so the RPC's null guard skips the UPDATE).
- Do NOT validate guest_state answers against live topics in the signup handler — the RPC handles topic FK violations per-row.
