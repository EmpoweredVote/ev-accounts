**Script 1: `audit-112-stances.ts`** (AUDIT-03)

Use the standard boilerplate. Per D-09, report stance coverage as ratios, not binary.

**CSV columns:** `full_name,politician_id,is_linked,live_topic_count,answered_topic_count,pct`

**Main logic:**

1. Election validation (same as other scripts — query essentials.elections WHERE election_date = '2026-05-05' AND state = 'IN', log count, exit if 0).

2. First, get the total live topic count:
```sql
SELECT COUNT(*) AS cnt FROM inform.compass_topics WHERE is_live = true
```
Log to stderr: `Live compass topics: N`

3. Query stance coverage per candidate:
```sql
SELECT
  rc.full_name,
  rc.politician_id,
  CASE WHEN rc.politician_id IS NOT NULL THEN 'linked' ELSE 'stub' END AS is_linked,
  COUNT(DISTINCT pa.topic_id) AS answered_topic_count
FROM essentials.race_candidates rc
JOIN essentials.races r ON r.id = rc.race_id
JOIN essentials.elections e ON e.id = r.election_id
LEFT JOIN inform.politician_answers pa ON pa.politician_id = rc.politician_id
LEFT JOIN inform.compass_topics ct ON ct.id = pa.topic_id AND ct.is_live = true
WHERE e.election_date = '2026-05-05' AND e.state = 'IN'
  AND rc.candidate_status = 'active'
GROUP BY rc.full_name, rc.politician_id
ORDER BY answered_topic_count DESC, rc.full_name
```

4. For each row, compute `pct` as `ROUND(answered / live_topics * 100, 1)`. For stubs (politician_id IS NULL), output `is_linked=stub`, `answered_topic_count=0`, `pct=N/A` — NOT "0%".

5. DRY_RUN: log total candidates, linked count, stubs count, candidates with any stances.

6. Summary to stderr: `Candidates with stances: N/M linked, Stubs (no politician record): N`

**Script 1: `audit-112-headshots.ts`** (AUDIT-05)

This is a SIMPLER version of the existing `auditHeadshots.ts` — it only classifies photo source (cdn/local/none), no HTTP checks.

**CSV columns:** `full_name,politician_id,is_linked,photo_source,cdn_url,stub_photo_url`

**Main logic:**

1. Election validation (same pattern).

2. Query headshot coverage per candidate (per RESEARCH.md AUDIT-05 pattern):
```sql
SELECT
  rc.full_name,
  rc.politician_id,
  CASE WHEN rc.politician_id IS NOT NULL THEN 'linked' ELSE 'stub' END AS is_linked,
  pi.url AS cdn_photo,
  rc.photo_url AS stub_photo,
  CASE
    WHEN pi.url IS NOT NULL THEN 'cdn'
    WHEN rc.photo_url IS NOT NULL THEN 'local'
    ELSE 'none'
  END AS photo_source
FROM essentials.race_candidates rc
JOIN essentials.races r ON r.id = rc.race_id
JOIN essentials.elections e ON e.id = r.election_id
LEFT JOIN essentials.politician_images pi
  ON pi.politician_id = rc.politician_id AND pi.type = 'default'
WHERE e.election_date = '2026-05-05' AND e.state = 'IN'
  AND rc.candidate_status = 'active'
ORDER BY rc.full_name
```

3. DRY_RUN: log total candidates, cdn count, local count, none count.

4. Summary to stderr: `Photos: N cdn, N local, N none (of N total candidates)`



**Script 2: `audit-112-profile.ts`** (AUDIT-06)

Per D-08, report profile completeness as individual fields, NOT a rolled-up percentage.

**CSV columns:** `full_name,politician_id,has_bio,contact_count,degree_count,experience_count`

**Main logic:**

1. Election validation (same pattern).

2. This script ONLY reports on linked candidates (politician_id IS NOT NULL) since stub candidates have no politician record to measure. Log to stderr how many stubs are skipped.

3. Query profile completeness (per RESEARCH.md AUDIT-06 pattern):
```sql
SELECT
  p.id,
  p.full_name,
  CASE WHEN p.bio_text IS NOT NULL AND p.bio_text != '' THEN 'Y' ELSE 'N' END AS has_bio,
  COUNT(DISTINCT pc.id) AS contact_count,
  COUNT(DISTINCT d.id) AS degree_count,
  COUNT(DISTINCT ex.id) AS experience_count
FROM essentials.race_candidates rc
JOIN essentials.politicians p ON p.id = rc.politician_id
JOIN essentials.races r ON r.id = rc.race_id
JOIN essentials.elections e ON e.id = r.election_id
LEFT JOIN essentials.politician_contacts pc ON pc.politician_id = p.id
LEFT JOIN essentials.degrees d ON d.politician_id = p.id
LEFT JOIN essentials.experiences ex ON ex.politician_id = p.id
WHERE e.election_date = '2026-05-05' AND e.state = 'IN'
  AND rc.candidate_status = 'active'
  AND rc.politician_id IS NOT NULL
GROUP BY p.id, p.full_name, p.bio_text
ORDER BY p.full_name
```

4. DRY_RUN: log linked candidate count, candidates with bio, candidates with any contacts, candidates with any degrees, candidates with any experiences.

5. Summary to stderr:
   - `Linked candidates: N`
   - `With bio: N/N`
   - `With contacts: N/N`
   - `With education: N/N`
   - `With experience: N/N`
