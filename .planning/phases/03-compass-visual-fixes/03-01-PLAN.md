**In `ev-ui/src/RadarChartCore.jsx`:**

1. Modify the label rendering block (lines 120-163, the second `spokes.map`) to cap labels at 2 lines with font-size fallback. Replace the current label computation:

```js
const lines = wrapLabel(shortTitle, 10);
const fSize = labelFontSize || 16;
```

With a stepped fallback that tries progressively smaller font sizes:

```js
const baseFSize = labelFontSize || 16;
let lines = wrapLabel(shortTitle, 10);
let fSize = baseFSize;
if (lines.length > 2) {
  // Try wider wrap at smaller font — more chars fit per line
  lines = wrapLabel(shortTitle, 14);
  fSize = 13;
  if (lines.length > 2) {
    lines = wrapLabel(shortTitle, 18);
    fSize = 11;
    if (lines.length > 2) {
      lines = lines.slice(0, 2);
    }
  }
}
```

The logic: at 13px font, allow 14 chars/line. At 11px, allow 18 chars/line. If still >2 lines at 11px, hard-cap at 2 lines. This preserves readability while preventing overflow.

2. Update the `lineHeight` calculation that follows to use the dynamic `fSize`:
```js
const lineHeight = fSize * 1.1;
```
(This line already references `fSize`, so it should pick up the new value automatically. Verify it does.)

3. Update the `<text>` element's inline style to use the dynamic `fSize` instead of only applying it when `labelFontSize` is passed:
```js
style={{ cursor: "pointer", userSelect: "none", fontSize: fSize }}
```
Remove the old conditional: `...(labelFontSize ? { fontSize: labelFontSize } : {})` — always set fontSize to `fSize`.

4. Increase the `labelOffset` for multi-line labels to reduce collision potential. After computing `lines` and `fSize`, add:
```js
const dynamicLabelOffset = lines.length > 1 ? labelOffset + 8 : labelOffset;
```
Then use `dynamicLabelOffset` instead of `labelOffset` when computing label position:
```js
const offset = radius + dynamicLabelOffset;
```
