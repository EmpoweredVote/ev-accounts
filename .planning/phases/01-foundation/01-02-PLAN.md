**Step 8: Create `backend/src/middleware/auth.ts`** (FOUND-05)

Per RESEARCH.md Pattern 3 (UPDATED for jose).

Use `jose` library (`jwtVerify`, `createRemoteJWKSet`). The JWKS URL is `${env.SUPABASE_URL}/auth/v1/.well-known/jwks.json`. JWKS is fetched once by `createRemoteJWKSet` and cached automatically (no network call per request).

Verification options: `issuer: '${env.SUPABASE_URL}/auth/v1'`, `audience: 'authenticated'`.

After JWT verification, extract `payload.sub` as `userId`. Then check `account_standing`:
- Query `connected_profiles.account_standing` via `supabaseAdmin` (this is a trusted server-side internal check -- it does NOT populate any data in the response body; it only gates access)
- If no connected_profiles row exists, user is Inform tier -- allow through (tier guards handle elevation)
- If connected_profiles row exists and `account_standing !== 'active'`, return 403 `{ error: 'Account suspended' }`
- If active or no profile, attach `userId` and `accessToken` to request and call `next()`

Export `requireAuth` middleware and `AuthenticatedRequest` interface.

**JWT algorithm note:** Add a comment in auth.ts explaining the ES256/HS256 situation:
```typescript
// Supabase projects created after May 2025 use ES256 (asymmetric) by default.
// This middleware uses JWKS-based verification which works for ES256 and RS256.
// If the project uses HS256 (legacy symmetric), replace createRemoteJWKSet with:
//   new TextEncoder().encode(env.SUPABASE_JWT_SECRET)
// Check: Supabase Dashboard > Auth > JWT Configuration
```

**Step 9: Create `backend/src/middleware/tierGuards.ts`**

Per RESEARCH.md tier guard pattern. Two exports:
1. `requireConnected(req, res, next)` -- queries `connected_profiles` via `supabaseAdmin` for `req.userId`. Returns 403 if no row or `verification_status !== 'verified'`.
2. `requireEmpowered(req, res, next)` -- queries `empowered_profiles` via `supabaseAdmin` for `req.userId`. Returns 403 if no row or `is_active !== true`.

Note: These guards use `supabaseAdmin` because they are doing a trusted server-side check, not returning data to the user. The data returned to the user in the route handler uses `createUserClient`. The `supabaseAdmin` usage in `src/middleware/` is intentionally excluded from the dual-client architecture enforcement check (which scans only `src/routes/`).
