<task type="auto">
  <name>Task 1: Fix LibraryDrawer crash — null stances guard + full topic lookup</name>
  <files>CompassV2/src/components/LibraryDrawer.jsx, CompassV2/src/pages/Library.jsx</files>
  <action>
**Root cause:** The `/compass/categories` endpoint (CategoryHandler at handlers.go line 260) preloads `Topics` but NOT `Topics.Stances`. When Library.jsx renders categories and the user clicks a card, it passes the category-embedded topic object (which has `stances: null`) to `setDrawerTopic`. LibraryDrawer then calls `.map()` and `[...spread]` on null stances, crashing.

**Fix approach — two layers of defense:**

**Layer 1: Library.jsx — look up full topic from context instead of using category-embedded topic.**

In Library.jsx, the card onClick at line 446 currently does:
```jsx
onClick={() => setDrawerTopic(topic)}
```
where `topic` comes from `category.topics` (which lacks stances).

Change to look up the full topic from the `topics` array in CompassContext, which DOES have stances loaded (from GET /compass/topics with Preload("Stances")):
```jsx
onClick={() => {
  const fullTopic = topics.find(t => t.id === topic.id) || topic;
  setDrawerTopic(fullTopic);
}}
```

**Layer 2: LibraryDrawer.jsx — defensive null guard on stances.**

At LibraryDrawer.jsx line 10-14, change:
```jsx
const displayStances = topic
  ? isInverted
    ? [...topic.stances].reverse()
    : topic.stances
  : [];
```
to:
```jsx
const stances = topic?.stances ?? [];
const displayStances = isInverted ? [...stances].reverse() : stances;
```

This ensures that even if a topic somehow arrives without stances, the component renders an empty list instead of crashing.

**Do NOT modify the backend CategoryHandler** — adding Preload("Topics.Stances") there would be wasteful since the Library page already has full topics from the topics endpoint. The frontend fix is the correct layer.

<task type="auto">
  <name>Task 2: Fix stance randomization — Quiz.jsx must consume invertedSpokes for display order</name>
  <files>CompassV2/src/pages/Quiz.jsx</files>
  <action>
**Root cause:** Quiz.jsx line 346 sets `const ordered = currentTopic.stances;` which always uses the original order. The `invertedSpokes` state IS computed correctly by `initRandomInversions` (confirmed working in CompassContext), but Quiz.jsx never reverses the stance button list based on it. The `invertedSpokes` prop is only passed to RadarChart for visual chart display — not used for the stance button rendering order.

**Fix at Quiz.jsx line 346:**

Change:
```jsx
const ordered = currentTopic.stances;
```
to:
```jsx
const isFlipped = invertedSpokes[currentTopic.short_title];
const ordered = isFlipped ? [...currentTopic.stances].reverse() : currentTopic.stances;
```

This mirrors the exact same pattern already used in LibraryDrawer.jsx (lines 9-14), ensuring consistent stance display across both quiz and drawer.

**Important:** The `stanceContent` JSX block (lines 411-489) references `ordered` for both the regular stance buttons (line 419) and the write-in drag-and-drop items (line 479). Since `ordered` is used in both paths, this single change covers both rendering modes.

**Also important:** The write-in flow at line 442 builds `orderedItems` from `ordered.map((s) => s.id)`. Since `ordered` is now the flipped array when appropriate, the write-in drag list will also reflect the correct stance order.

No other files need changes. The `initRandomInversions` call (lines 200-216) is already correct.
