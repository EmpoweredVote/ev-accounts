<objective>
Extend the existing `admin/src/pages/ProfilePage.tsx` so that an authenticated Inform-tier user landing on `/profile` sees a complete, yellow-themed, personally-relevant page that matches the structural layout of the Connected profile but uses the `ev-yellow` color system, displays their compass calibration count and last Essentials location, surfaces locked Connected/Empowered tiles with visible lock indicators, and provides an invitational path to Connected via a clickable "Inform Account" badge and a subtle bottom-of-page CTA — both opening the `ConnectedExplainerModal` from Plan 01.

Purpose: Phase 66 made `inform_profile` available on `/me` and Phase 67 routes new Inform users to `/profile`. The current ProfilePage already has partial Inform theming (yellow border on header card, yellow tab underline) but defers most of the Inform experience: it does not fetch compass stats for Inform users, does not render `last_essentials_location`, does not lock the Connected/Empowered tiles visually, and the "Inform Account" badge is a non-clickable `<span>`. This plan completes the Inform branch in-place, satisfying IPRO-01 through IPRO-06 and CEXP-01.

Output: A modified `ProfilePage.tsx` with: (a) `MeInformProfile` type extended with `last_essentials_location`, (b) compass-stats fetch enabled for Inform users, (c) the "Inform Account" badge converted to a clickable button for Inform tier, (d) lock indicator badges on Connected/Empowered tiles for Inform users, (e) the Essentials tile augmented with the user's last searched location for Inform users, (f) a subtle bottom "Connect your account" section gated to Inform tier, (g) the `ConnectedExplainerModal` imported, state-managed via `explainerOpen`, and rendered at page level.
</objective>

    Recommended structure:
    ```tsx
    if (data.connected_profile) {
      apiFetch<InviteesData>('/invites/my-invitees').then(setInviteesData).catch(() => {});
      apiFetch<{ roles: UserRoleGrant[] }>('/roles/me')
        .then((r) => setRoles(r.roles))
        .catch(() => {});

      if (token && data.id) {
        fetch(`https://readrank.empowered.vote/api/users/${data.id}/stats`, {
          headers: { Authorization: `Bearer ${token}` },
        })
          .then((r) => r.ok ? r.json() as Promise<ReadRankStats> : null)
          .then((d) => { if (d && typeof d.ranked === 'number') setReadRankStats(d); })
          .catch(() => {});
      }
    }
    if (data.connected_profile || data.tier === 'inform') {
      Promise.all([
        apiFetch<unknown>('/compass/answers'),
        apiFetch<unknown>('/compass/topics'),
      ]).then(([answersData, topicsData]) => {
        const answered = Array.isArray(answersData)
          ? answersData.length
          : ((answersData as { answers?: unknown[] })?.answers?.length ?? 0);
        const total = Array.isArray(topicsData)
          ? topicsData.length
          : ((topicsData as { topics?: unknown[] })?.topics?.length ?? 21);
        setCompassStats({ answered, total });
      }).catch(() => {});
    }
    ```

    Why: Both `/compass/answers` and `/compass/topics` use `optionalAuth` middleware (confirmed in `backend/src/routes/compass.ts`) and work for Inform-tier users.
