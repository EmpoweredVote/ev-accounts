**Step 1: Create the Vault Secret**

This MUST happen before any RPC call. The RPCs raise an exception if the secret is not found.

Two options — pick one:

Option A (SQL — run in Supabase Dashboard SQL Editor or psql):
```sql
SELECT vault.create_secret(
  'your-strong-random-key-here',   -- Replace with a real 32+ character random string
  'location_encryption_key',       -- This exact name is what the RPCs look up
  'AES256 symmetric key for coordinate encryption'
);
```

Option B (Supabase Dashboard):
Database → Vault → "Add new secret" → Name: `location_encryption_key`, Value: your key

IMPORTANT NOTES in this section:
- The secret name must be exactly `location_encryption_key` — the RPCs look it up by this exact name
- Use a cryptographically random key, minimum 32 characters (e.g., `openssl rand -base64 32`)
- Never commit the key value to git or include it in any migration file
- The same key must be used in every environment where the RPCs are called; coordinates encrypted with one key cannot be decrypted with a different key

**Step 3: Load Boundary Data**

One ogr2ogr command per district type. All 5 append to the same `inform.district_boundaries` table.

Flags used in every command:
- `-f PostgreSQL` — output format
- `PG:"$DATABASE_URL"` — connection string (direct, not pooler)
- `-nln district_boundaries` — target table name
- `-lco SCHEMA=inform` — target schema
- `-lco GEOMETRY_NAME=geom` — geometry column name
- `-nlt PROMOTE_TO_MULTI` — forces Polygon → MultiPolygon to match column type
- `-s_srs EPSG:4269 -t_srs EPSG:4326` — reprojects NAD83 → WGS84
- `-append -update` — appends to existing table instead of replacing
- `-sql "SELECT ..."` — selects and renames columns to match table schema, injects district_type constant

Include all 5 commands verbatim (replacing `/path/to/*.shp` with the operator's actual paths):

```bash
# 1. Congressional Districts (Indiana has 9 seats — 119th Congress)
ogr2ogr -f PostgreSQL \
  "PG:$DATABASE_URL" \
  -nln district_boundaries \
  -lco SCHEMA=inform \
  -lco GEOMETRY_NAME=geom \
  -nlt PROMOTE_TO_MULTI \
  -s_srs EPSG:4269 -t_srs EPSG:4326 \
  -append -update \
  -sql "SELECT GEOID AS geoid, NAMELSAD AS name, 'congressional' AS district_type FROM tl_2024_18_cd119" \
  /path/to/tl_2024_18_cd119.shp

# 2. State Senate
ogr2ogr -f PostgreSQL \
  "PG:$DATABASE_URL" \
  -nln district_boundaries \
  -lco SCHEMA=inform \
  -lco GEOMETRY_NAME=geom \
  -nlt PROMOTE_TO_MULTI \
  -s_srs EPSG:4269 -t_srs EPSG:4326 \
  -append -update \
  -sql "SELECT GEOID AS geoid, NAMELSAD AS name, 'state_senate' AS district_type FROM tl_2024_18_sldu" \
  /path/to/tl_2024_18_sldu.shp

# 3. State House
ogr2ogr -f PostgreSQL \
  "PG:$DATABASE_URL" \
  -nln district_boundaries \
  -lco SCHEMA=inform \
  -lco GEOMETRY_NAME=geom \
  -nlt PROMOTE_TO_MULTI \
  -s_srs EPSG:4269 -t_srs EPSG:4326 \
  -append -update \
  -sql "SELECT GEOID AS geoid, NAMELSAD AS name, 'state_house' AS district_type FROM tl_2024_18_sldl" \
  /path/to/tl_2024_18_sldl.shp

# 4. Counties (national file — filter to Indiana FIPS 18 only; Indiana has 92 counties)
ogr2ogr -f PostgreSQL \
  "PG:$DATABASE_URL" \
  -nln district_boundaries \
  -lco SCHEMA=inform \
  -lco GEOMETRY_NAME=geom \
  -nlt PROMOTE_TO_MULTI \
  -s_srs EPSG:4269 -t_srs EPSG:4326 \
  -append -update \
  -where "STATEFP='18'" \
  -sql "SELECT GEOID AS geoid, NAMELSAD AS name, 'county' AS district_type FROM tl_2024_us_county WHERE STATEFP='18'" \
  /path/to/tl_2024_us_county.shp

# 5. Unified School Districts
ogr2ogr -f PostgreSQL \
  "PG:$DATABASE_URL" \
  -nln district_boundaries \
  -lco SCHEMA=inform \
  -lco GEOMETRY_NAME=geom \
  -nlt PROMOTE_TO_MULTI \
  -s_srs EPSG:4269 -t_srs EPSG:4326 \
  -append -update \
  -sql "SELECT GEOID AS geoid, NAMELSAD AS name, 'school_district' AS district_type FROM tl_2024_18_unsd" \
  /path/to/tl_2024_18_unsd.shp
```

**Step 4: Post-Load Verification**

Run all 4 queries and confirm expected results:

```sql
-- 1. SRID must be 4326 (not 4269). If this returns 4269, the reprojection failed.
SELECT DISTINCT ST_SRID(geom) FROM inform.district_boundaries;
-- Expected: 4326

-- 2. Row counts by district type
SELECT district_type, count(*)
FROM inform.district_boundaries
GROUP BY district_type
ORDER BY district_type;
-- Expected:
--   congressional   | 9      (Indiana 119th Congress seats)
--   county          | 92     (Indiana counties)
--   school_district | ~290   (varies by year; confirm > 200)
--   state_house     | 100
--   state_senate    | 50

-- 3. Bloomington, IN smoke test
-- Bloomington coordinates: lat=39.1653, lng=-86.5264
-- Indiana 9th congressional district GEOID: '1809'
SELECT geoid, name, district_type
FROM inform.district_boundaries
WHERE ST_Covers(
  geom,
  ST_SetSRID(ST_MakePoint(-86.5264, 39.1653), 4326)
)
ORDER BY district_type;
-- Expected: 5 rows covering congressional (1809), county (Monroe County),
--   state_house, state_senate, and school_district for Bloomington area.
-- If congressional row is missing or shows wrong GEOID, check SRID and coordinate order.
```

Note: In psql outside a SECURITY DEFINER RPC, ST_Covers/ST_MakePoint/ST_SetSRID resolve from the `extensions` schema automatically (no prefix needed). Inside an RPC with SET search_path = '', the `extensions.` prefix is mandatory — this is already in the migration 032 RPCs.
