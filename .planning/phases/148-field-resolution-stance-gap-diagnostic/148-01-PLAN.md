<objective>
Produce the database half of the Phase 148 field table: a per-district map of each Wave-1 (CA/TX/FL/NY) US House district's seated incumbent to its existing `essentials.politicians.id`, that incumbent's current compass stance count (with a top-up tier), and explicit enumeration of the two confirmed vacancies. This is the read-only diagnostic that prevents the two costliest milestone traps before any seeding: (1) duplicate-incumbent records (reuse the resolved `politician_id`, never INSERT a new politician row for a sitting rep) and (2) the stale milestone assumption that incumbents are already stanced (live data shows ~133/144 are below the federal-24 bar, 73 at zero).

Purpose: Phases 149 (CA) / 150 (TX+NY) / 151 (FL) read `incumbent_pid` to reuse records and `incumbent_top_up_tier` to scope incumbent stance work. Without this map, the seeding phases would guess incumbent identity (the v2.4 Andy-Barr duplication vector) and silently under-research incumbents.

Output: `148-incumbent-map.csv` (the DB-derived per-district rows) + a re-runnable read-only diagnostic script `diag-148-incumbent-stance-gap.ts`. The external-field overlay + final assembled `148-FIELD-TABLE.md` / `148-field-table.csv` are produced in Plan 148-02, which joins onto this CSV by `geo_id`.
</objective>

Schema facts (live-verified):
- `essentials.districts`: columns include `id`, `district_type` (Wave-1 House = `'NATIONAL_LOWER'`), `geo_id` (string `SSCC`, e.g. `'0612'` = CA-12; first 2 chars = state FIPS), `mtfcc` (`'G5200'` for House).
- `essentials.offices`: `id`, `district_id`, `politician_id` (NULLABLE — NULL or no-office = vacancy).
- `essentials.politicians`: `id` (UUID), `external_id` (int, scheme is INCONSISTENT across states — see below), `full_name`, `is_active`.
- `inform.politician_answers`: keyed `(politician_id, topic_id)` — there is **NO `id` column**. Use `COUNT(*)`, never `COUNT(pa.id)` (errors).

Wave-1 state FIPS prefixes: CA=`06`, TX=`48`, FL=`12`, NY=`36`.

external_id schemes (verified — DO NOT compute external_id; join on geo_id):
  CA CD-01 = -6000301 ; TX CD-01 = -100301 ; FL CD-01 = -12001 ; NY CD-10 = -36010
