## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, icon-to-label spacing, inline tight padding |
| sm | 8px | Intra-card element spacing (name-to-title, icon row gaps) |
| md | 16px | Card internal padding, grid gap between cards |
| lg | 24px | Section padding within page, gap between CategorySection groups |
| xl | 32px | Page horizontal padding on desktop |
| 2xl | 48px | Major section breaks (banner to first tier section) |
| 3xl | 64px | Page-level top/bottom padding |

Exceptions:
- Variant toggle (SegmentedControl): 4px internal pill padding (matches existing SegmentedControl.jsx pattern)
- Placeholder radar SVG stroke: 1.5px — not a spacing value, visual only
- Touch targets for card click: minimum 44px height per WCAG 2.5.5 (applies to Variant C horizontal card name/title area)

Source: ev-ui/src/tokens.js spacing scale, CONTEXT.md D-09 (consistent card sizing), existing SegmentedControl.jsx

## Card Variant Specifications

All variants use the same data and state model. The variant prop controls layout geometry only.

### Variant A — Tall / Spacious (default)

- Card width: ~50% column on desktop (2-column grid), 100% on mobile
- Radar size: 200px × 200px
- Layout: vertical stack — radar → name → title → icon row
- Card padding: 16px all sides
- Card border-radius: 12px (borderRadius.xl from tokens.js)
- Card shadow: `0 4px 6px -1px rgba(0,0,0,0.1)` (shadows.md)
- Name font: 18px/600/line-height 1.4
- Title font: 14px/400/line-height 1.5, line-clamp-2, min-height 2.5rem
- Icon row: 8px gap, positioned below title, 8px margin-top

### Variant B — Compact / Dense

- Card width: ~33% column on desktop (3-column grid), 50% on mobile (2-column), 100% on smallest mobile
- Radar size: 150px × 150px
- Layout: vertical stack — radar → name → title → icon row
- Card padding: 12px all sides
- Card border-radius: 10px (borderRadius.lg from tokens.js)
- Card shadow: `0 1px 2px 0 rgba(0,0,0,0.05)` (shadows.sm)
- Name font: 16px/600/line-height 1.4
- Title font: 12px/400/line-height 1.4, line-clamp-1
- Icon row: 6px gap, below title, 6px margin-top

### Variant C — Wide Horizontal

- Card width: 100% column (1-column grid, full width)
- Radar size: 140px × 140px (left side, fixed width)
- Layout: horizontal flex — radar (left, fixed 140px) | name + title + icon row (right, flex-1)
- Card padding: 16px all sides
- Card border-radius: 12px (borderRadius.xl)
- Card shadow: `0 4px 6px -1px rgba(0,0,0,0.1)` (shadows.md)
- Right-side name font: 18px/600/line-height 1.4
- Right-side title font: 14px/400/line-height 1.5, line-clamp-2
- Icon row: 8px gap, below title, 8px margin-top
- Horizontal gap between radar and right content: 16px

Mobile (all variants): collapse to 1-column grid, full-width cards.
Breakpoint for column expansion: `md` (768px) for Variant A/C; `sm` (640px) for Variant B.

## Placeholder Radar (no mock data state)

Applies when a politician is not included in the mock data file.

- SVG polygon inscribed in a circle matching the radar's dimensions
- Polygon shape: regular octagon (8-spoke positions) at ~70% of max radius
- Stroke: #D3D7DE (gray-200), 1.5px width, stroke-dasharray: "4 3"
- Fill: none (transparent interior)
- Background of radar area: #F5F9FA (teal-050) — extremely subtle
- No initials, no icon. Name displayed below handles identification.

Source: CONTEXT.md D-08 (dashed outline, no initials), D-09 (consistent sizing)

## Interaction Contract

| Interaction | Behavior |
|-------------|----------|
| Click card (any variant) | `navigate('/politician/:id')` — same as PoliticianCard |
| Hover card (desktop) | box-shadow upgrades to shadows.cardHover, transition 200ms ease |
| Click variant toggle | Swaps grid layout and card dimensions instantly (no animation). Data and radar content unchanged. |
| Page load | Fetch /api/essentials/search with address "100 W Kirkwood Ave, Bloomington, IN 47404". Apply mock compass data on response. Render loading skeleton during fetch. |
| Loading state | Show CategorySection headers immediately (no skeleton), card areas show a 120px × 120px gray-100 rounded placeholder per card position (no spinner) |
| Compass overlay | If user has compass data (CompassContext.userAnswers.length > 0): coral + blue dual overlay. If no user data: blue politician-only overlay. Same as CompassCard profile pattern. |
| Icon tooltip | Inherit IconOverlay behavior from Phase 103 — hover (desktop) / tap (mobile) shows label tooltip |

Radar is view-only — no spoke clicks, no inversion toggle in card view. Full interactive radar is on the politician profile page.

Source: CONTEXT.md D-03 (static radar), D-02 (dual/single overlay), D-16 (live API fetch)

## Mock Data Strategy (Visual Contract Implications)

The mock data file (`src/data/mockCompassData.js`) must produce 4 visually distinct radar shapes. Each shape profile is assigned to politicians to ensure the grid never looks uniform.

| Profile | Shape Description | Visual Character |
|---------|-------------------|-----------------|
| Progressive | High scores on social/environment topics, low on economic/security | Asymmetric, heavy upper-left |
| Moderate | Mid-range across all topics | Near-circular, small |
| Conservative | High scores on security/economic, low on social/environment | Asymmetric, heavy lower-right |
| Mixed | High on 2-3 specific topics, low on others | Spiky, 2-3 protruding spokes |

Topic IDs: use the 8 active topic short_titles from `compass.topics` (executor must query `SELECT id, short_title FROM compass.topics WHERE active = true ORDER BY display_order`). Topic order determines spoke position — must match the order used by RadarChartCore across CompassCard and CompassPreview.

Source: CONTEXT.md D-12 (4 distinct profiles), D-13 (real topic IDs for dual overlay compatibility)

## Accessibility Contract

| Requirement | Implementation |
|-------------|----------------|
| WCAG AA contrast — all text | All text colors from tokens.js pass AA (verified in token file comments) |
| Keyboard navigation | Cards are focusable divs with tabIndex=0 and onKeyDown Enter/Space → navigate |
| Screen reader — card | role="article", aria-label="{name}, {title}" |
| Screen reader — variant toggle | SegmentedControl already uses role="radiogroup" + role="radio" + aria-checked |
| Screen reader — radar | role="img" aria-label="{name} compass alignment chart" |
| Screen reader — placeholder radar | role="img" aria-label="{name} — compass data unavailable" |
| Focus ring | box-shadow: 0 0 0 2px #FFFFFF, 0 0 0 4px #00657C (focus token from tokens.js) |
| Touch targets | Minimum 44px height for all interactive elements |

Source: CONTEXT.md D-21 (use frontend-design skill for polished design), WCAG 2.1 AA
