**Section 2: connect.confirm_vq_stance RPC**

Function signature:
```sql
CREATE OR REPLACE FUNCTION connect.confirm_vq_stance(
  p_politician_id    UUID,
  p_topic_id         UUID,
  p_confirmed_value  INTEGER,
  p_correct_users    UUID[],
  p_incorrect_users  UUID[],
  p_idempotency_key  TEXT,
  p_gems_amount      INTEGER
) RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = ''
AS $$
```

RPC logic (single transaction, all-or-nothing):

1. **Validate confirmed_value** — must be 1-5. RAISE EXCEPTION 'INVALID_VALUE' if not.

2. **Idempotency pre-check** — SELECT result_json FROM connect.vq_confirmation_results WHERE idempotency_key = p_idempotency_key. If found, add `"replayed": true` to the JSONB and RETURN immediately (no locks, no writes).

3. **Validate politician/topic pair** — SELECT 1 FROM inform.politicians p WHERE p.id = p_politician_id AND EXISTS (SELECT 1 FROM inform.compass_topics t WHERE t.id = p_topic_id). If NOT FOUND, RAISE EXCEPTION 'QUESTION_NOT_FOUND'.

4. **Collect and sort all user IDs** — combine p_correct_users and p_incorrect_users into a single sorted UUID array. Loop over sorted array acquiring pg_advisory_xact_lock(hashtext(uid::text)) for each. This prevents deadlocks when concurrent calls share users.

5. **Process correct users** — For each user_id in p_correct_users:
   - SELECT user_id, verification_rating, gem_balance_red FROM connect.connected_profiles WHERE user_id = uid FOR UPDATE
   - If NOT FOUND: add to unresolved_users array, CONTINUE
   - Compute new_rating = LEAST(verification_rating + 3, 150)
   - Compute rating_delta = new_rating - verification_rating
   - UPDATE connect.connected_profiles SET verification_rating = new_rating WHERE user_id = uid
   - INSERT INTO connect.gem_transactions (user_id, gem_type, amount, transaction_type, idempotency_key, balance_after) VALUES (uid, 'red', p_gems_amount, 'vq_correct', p_idempotency_key || ':' || uid::text, gem_balance_red + p_gems_amount)
   - UPDATE connect.connected_profiles SET gem_balance_red = gem_balance_red + p_gems_amount WHERE user_id = uid
   - Build user result row: { user_id, result: 'correct', gems_awarded: p_gems_amount, rating_delta, new_rating }

6. **Process incorrect users** — For each user_id in p_incorrect_users:
   - SELECT user_id, verification_rating FROM connect.connected_profiles WHERE user_id = uid FOR UPDATE
   - If NOT FOUND: add to unresolved_users array, CONTINUE
   - Compute new_rating = GREATEST(verification_rating - 10, 0)
   - Compute rating_delta = new_rating - verification_rating (will be negative or 0)
   - If new_rating = 0: SET vq_hold_until = now() + interval '30 days' (always overwrite, resets the clock)
   - UPDATE connect.connected_profiles SET verification_rating = new_rating, vq_hold_until = (CASE WHEN new_rating = 0 THEN now() + interval '30 days' ELSE vq_hold_until END) WHERE user_id = uid
   - Build user result row: { user_id, result: 'incorrect', gems_awarded: 0, rating_delta, new_rating }

7. **Upsert politician stance** — INSERT INTO inform.politician_answers (politician_id, topic_id, value) VALUES (p_politician_id, p_topic_id, p_confirmed_value) ON CONFLICT (politician_id, topic_id) DO UPDATE SET value = EXCLUDED.value

8. **Build result JSON:**
```json
{
  "politician_id": p_politician_id,
  "topic_id": p_topic_id,
  "confirmed_value": p_confirmed_value,
  "correct_count": <length of processed correct>,
  "incorrect_count": <length of processed incorrect>,
  "users": [ ...user result rows... ],
  "unresolved_users": [ ...skipped UIDs... ]
}
```

9. **Cache result** — INSERT INTO connect.vq_confirmation_results (idempotency_key, result_json) VALUES (p_idempotency_key, result_json)

10. RETURN result_json

GRANT EXECUTE ON FUNCTION connect.confirm_vq_stance to authenticated;

**Critical details:**
- SET search_path = '' — all table refs must be fully qualified (connect.connected_profiles, inform.politician_answers, etc.)
- Advisory locks MUST be acquired in sorted order across ALL users (correct + incorrect combined) before any writes
- gem_transactions INSERT needs a per-user idempotency_key derived from the main key (p_idempotency_key || ':' || uid::text) to prevent double-crediting if a user appears in multiple calls
- The balance_after field in gem_transactions must be the NEW balance after the award
- Do NOT call the credit_gems RPC from inside this function — do the INSERT + UPDATE inline (cannot nest SECURITY DEFINER calls reliably)
