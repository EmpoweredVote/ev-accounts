<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| FEC API → script | External JSON response from `api.open.fec.gov`. Untrusted: numeric fields may be missing, types may vary, `employer` field may be null/empty. |
| congress-legislators YAML → script | External YAML from `raw.githubusercontent.com`. Untrusted: schema may drift; `id.fec` may be missing for some legislators. |
| DC OCF site → assessment / script | External HTML/JSON from `ocf.dc.gov` (and possibly `opendata.dc.gov`). Untrusted source format. |
| script → essentials.politicians | DB write boundary. Script uses service-role pool. Only `finance_summary` column updated; only the EHN UUID (DCFI-01) or known DC official UUIDs (DCFI-02 Branch A) are targeted. |
| process env → script | `FEC_API_KEY`, `DATABASE_URL` loaded from `backend/.env`. Risk: secret accidentally logged to stdout. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-107-01 | Tampering | FEC API response | mitigate | Coerce all numeric fields with `Number(...)` before storing (per analog pattern, lines 281, 318); filter null/empty `employer` before include; never spread raw FEC response into `finance_summary`. |
| T-107-02 | Tampering | DC OCF response (Branch A only) | mitigate | Same coercion + null-filter pattern as FEC; never store raw OCF response; validate cycle string before write. |
| T-107-03 | Information Disclosure | FEC_API_KEY logged | mitigate | Never log `apiKey` directly; pass via `URLSearchParams` so it appears only in the outbound URL, not in console output. Confirm by grepping the script for `console.log.*apiKey` (must return zero hits). |
| T-107-04 | Tampering | SQL injection via politician ID or summary JSON | mitigate | Use parameterized `pool.query(sql, [JSON.stringify(summary), politicianId])` exclusively — never string concatenation. EHN UUID is hardcoded; DC official UUIDs come from a parameterized DB query, not user input. |
| T-107-05 | Denial of Service | FEC rate limit (1000 req/hr) | mitigate | 1500ms sleep before EVERY FEC call (3+ calls total for EHN, more if multiple DC officials in Branch A). Single-politician scope for DCFI-01 makes exhaustion impossible. |
| T-107-06 | Repudiation | Provenance of populated finance data | mitigate | `source` field is a discriminated literal (`'FEC'` or `'DC_OCF'`) stored in every finance_summary JSONB row — frontend and audit queries can verify origin. |
| T-107-07 | Elevation of Privilege | DB write scope creep | accept | Script uses service-role pool. Acceptable because: (1) write is targeted to a specific column (`finance_summary`) and specific UUID(s), (2) parameterized SQL prevents row scope expansion, (3) script is operator-run not API-exposed. |
| T-107-SC | Tampering | npm/pip/cargo installs | mitigate | No new package installs in this plan. Script reuses `js-yaml`, `pg`, `dotenv` already pinned in `backend/package.json`. Acceptance criteria asserts this via grep. |
</threat_model>
