**Routes to implement (7 total):**

**1. POST /topics/create** — atomic create topic + stances + optional category assignments.
- Body schema: `{ title: string, short_title: string, question_text: string, level: string[], is_live: boolean, stances: [{value: number, text: string}], category_ids?: string[] }`
- Call existing `adminCreateTopicWithStances()` from adminService.ts — read how it works in admin.ts and replicate the same call pattern
- If category_ids provided, call `adminAssignTopicCategories()` after topic creation
- Return 201 with created topic data

**2. PATCH /topics/update** — update topic metadata.
- Body must include `id` (UUID) plus any fields to update: title, short_title, question_text, is_live, level
- Call existing `adminUpdateTopic()` from adminService.ts
- Return 200 with updated topic

**3. DELETE /topics/delete/:id** — delete topic, blocked if responses exist.
- Validate :id as UUID
- Check: `SELECT COUNT(*)::text AS count FROM inform.compass_responses WHERE topic_id = $1` via pool.query
- If count > 0, return 422 `{ code: 'TOPIC_HAS_RESPONSES', message: 'Cannot delete topic with existing responses. Set is_live=false to archive.' }`
- If count = 0, delete topic: `DELETE FROM inform.compass_topics WHERE id = $1` via pool.query
- Also delete related stances and topic-category mappings (CASCADE should handle stances via FK, but explicitly delete topic_categories: `DELETE FROM inform.compass_topic_categories WHERE topic_id = $1`)
- Return 204

**4. PATCH /topics/categories/update** — reassign topic-category mappings.
- Body: `{ topic_id: string, category_ids: string[] }`
- Call existing `adminAssignTopicCategories()` from adminService.ts
- Return 200

**5. PATCH /stances/update** — update stance text.
- Body: `{ id: string, text: string }` (stance ID + new text)
- Call existing `adminUpdateStance()` from adminService.ts
- Return 200

**6. PUT /politicians/:id/answers** — full replacement of politician answers.
- Body schema: `{ answers: [{topic_id: string, value: number}] }` — value validated with `z.number().multipleOf(0.5).min(0.5).max(5.5)`
- Validate :id as UUID
- Call `adminRpc('admin_update_politician_answers', { p_politician_id: politicianId, p_answers: JSON.stringify(parsed.data.answers) })`
- The RPC (updated in Plan 01 migration) handles DELETE + upsert atomically
- Return 200 `{ replaced: answers.length }`

**7. POST /politicians/context** — add/update politician reasoning + sources.
- Body: `{ politician_id: string, topic_id: string, reasoning: string, sources: string[] }`
- Call existing `adminSetPoliticianContext()` from adminService.ts
- Return 200

**Route ordering within this router:** Register `/politicians/:id/answers` AFTER any other `/politicians/*` path routes. Since the batch route is on the main compass router (Plan 02), no collision risk here. But still register `/politicians/context` (POST, no :id param) BEFORE `/politicians/:id/answers` (PUT, has :id param) to be safe.

Add Zod schemas for each route body. Follow the same error handling pattern as existing compass.ts routes (422 for validation, 500 for unexpected).

Update `backend/src/index.ts` to import and mount the compassAdmin router.

1. Add import near the existing compass import:
```typescript
import compassAdminRouter from './routes/compassAdmin.js';
```

2. Mount AFTER the existing compassRouter (order matters — Express tries routers in order, and the admin router has blanket auth that would block public routes if mounted first):
```typescript
app.use('/api/compass', compassRouter);      // existing line
app.use('/api/compass', compassAdminRouter);  // NEW — admin routes at /api/compass/*
```

The two routers share the same mount prefix `/api/compass`. Express will try the first router's routes, and if none match, fall through to the second router. This is safe because:
- compassRouter handles public routes (GET /topics, GET /answers, POST /compare, etc.)
- compassAdminRouter handles admin routes (POST /topics/create, PUT /politicians/:id/answers, etc.)
- No URL+method collisions between the two routers

Add a comment above the new mount line explaining the dual-router pattern.
