  <name>Task 1: Add deleted_at filter to both compass response read paths</name>
  <files>backend/src/routes/compass.ts</files>
  <action>
    Two read queries on inform.compass_responses are missing the soft-delete guard. The RLS policy does NOT filter deleted rows — the filter must be applied in code.

    Fix 1 — GET /compass/answers (around line 151):
    The query ending with:
      .select('topic_id, value, write_in_text, visibility, inverted, created_at, updated_at');
    becomes:
      .select('topic_id, value, write_in_text, visibility, inverted, created_at, updated_at')
      .is('deleted_at', null);

    Fix 2 — POST /compass/answers/batch (around line 192):
    The query ending with:
      .in('topic_id', parsed.data.ids);
    becomes:
      .in('topic_id', parsed.data.ids)
      .is('deleted_at', null);

    IMPORTANT: Use .is('deleted_at', null) NOT .eq('deleted_at', null). The .eq() method generates incorrect PostgREST syntax for NULL comparison. .is() generates IS NULL which is what PostgREST requires.

    No other changes to this file.
  </action>
