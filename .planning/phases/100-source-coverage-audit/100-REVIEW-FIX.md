### WR-01: v2.3 Senators Cohort Query Missing DISTINCT

**Files modified:** `backend/scripts/run-source-coverage-audit.ts`
**Commit:** 70621fd
**Applied fix:** Replaced the inner `JOIN essentials.offices` + `JOIN essentials.districts` in the senators cohort query with a `WHERE EXISTS (SELECT 1 FROM essentials.offices o JOIN essentials.districts d ...)` subquery. This prevents fan-out if any senator has multiple `NATIONAL_UPPER` office records, matching the EXISTS pattern used by Queries B and D. The `JOIN essentials.politicians` for `is_active` filter was retained.

### WR-02: `DATABASE_URL` Not Validated Before Pool Construction

**Files modified:** `backend/scripts/run-source-coverage-audit.ts`
**Commit:** c9d10e3
**Applied fix:** Added an explicit `if (!process.env.DATABASE_URL)` guard immediately after `dotenv.config()` that logs a clear fatal error message and calls `process.exit(1)` before the `pg.Pool` constructor. This surfaces the missing env var at startup with a helpful diagnostic rather than deferring to a generic connection error at first query.

### WR-03: `writeFileSync` Throws Unhelpful `ENOENT` If Output Directory Absent

**Files modified:** `backend/scripts/run-source-coverage-audit.ts`
**Commit:** 470514c
**Applied fix:** Added `mkdirSync` to the `node:fs` import and inserted `mkdirSync(phaseDir, { recursive: true })` before the two `writeFileSync` calls in `main()`. The `{ recursive: true }` option makes this a no-op when the directory already exists and prevents `ENOENT` on fresh clones or renamed phase directories.

### WR-04: Unsourced Detection CASE Expression Duplicated Four Times in Query D

**Files modified:** `backend/scripts/run-source-coverage-audit.ts`
**Commit:** 90930ba
**Applied fix:** Extracted a module-level `UNSOURCED_CASE` constant (the logical inverse of the existing `SOURCED_CASE`) with explanatory comments. Replaced all four inline copies in `queryTargetList()` with `${UNSOURCED_CASE}` template interpolation: `unsourced_count` SUM, `unsourced_pct` SUM (the `1.0`/`0.0` variant was normalized to `1`/`0` — PostgreSQL promotes to numeric via the division expression), `majority_unsourced` SUM, `HAVING SUM`, and the two `ORDER BY SUM` expressions.
