  <files>backend/src/lib/meetingsService.ts</files>
  <action>
Create `backend/src/lib/meetingsService.ts` following the exact pattern of `essentialsService.ts` and `treasuryService.ts`:

- `import { pool } from './db.js'` — NEVER use supabaseAdmin.schema('meetings'), it will fail at runtime
- Explicit camelCase field mapping — NEVER spread DB rows
- `Number()` wrapper on all bigint columns: duration_seconds, segment_count, speaker_count, segment_index, sort_order
- `Number()` on numeric columns: start_time, end_time, timestamp (these are numeric/decimal in schema)

**TypeScript interfaces** at the top:
- `Meeting` — id, city, state, date, meetingType, durationSeconds, videoUrl, audioSource, status, segmentCount, speakerCount, createdAt, updatedAt
- `Speaker` — id, meetingId, label, displayName, confidence, idMethod, politicianId, createdAt
- `Segment` — id, meetingId, speakerId, segmentIndex, startTime, endTime, text
- `MeetingSummary` — id, meetingId, summaryType, model, createdAt, sections: SummarySection[]
- `SummarySection` — id, summaryId, sectionType, title, content, startTime, endTime, sortOrder
- `Vote` — id, meetingId, resolution, description, result, voteType, timestamp, createdAt, records: VoteRecord[]
- `VoteRecord` — id, voteId, speakerId, position

**Functions to implement:**

1. `getMeetings(filters?: { city?: string; state?: string; status?: string })` — `SELECT id, city, state, date, meeting_type, duration_seconds, video_url, audio_source, status, segment_count, speaker_count, created_at, updated_at FROM meetings.meetings` + dynamic WHERE clauses from filters + `ORDER BY date DESC`. Use parameterized queries ($1, $2...) for filter values — NEVER interpolate strings.

2. `getMeetingById(id: string)` — Fetch meeting row + speakers in two queries. Return `{ ...meeting, speakers: Speaker[] }` or null if meeting not found. Speakers query: `SELECT * FROM meetings.speakers WHERE meeting_id = $1 ORDER BY label`.

3. `getTranscriptByMeetingId(meetingId: string, page: number)` — Paginated segments. `SELECT * FROM meetings.segments WHERE meeting_id = $1 ORDER BY segment_index LIMIT 200 OFFSET $2`. Return `{ segments: Segment[], page, totalCount }` where totalCount is from a separate COUNT query. page parameter is 1-indexed; OFFSET = (page - 1) * 200.

4. `getSummaryByMeetingId(meetingId: string)` — Fetch summary row + sections. Two queries: summary from meetings.meeting_summaries, sections from meetings.summary_sections WHERE summary_id = summary.id ORDER BY sort_order. Return `MeetingSummary` with embedded sections array, or null if no summary exists.

5. `getVotesByMeetingId(meetingId: string)` — Fetch votes + vote_records. First query: `SELECT * FROM meetings.votes WHERE meeting_id = $1 ORDER BY timestamp`. Second query: `SELECT * FROM meetings.vote_records WHERE vote_id = ANY($1)` with vote IDs from first query. Nest records into their parent votes. Return `Vote[]` with embedded records arrays.

6. `createMeeting(data: { city: string; state: string; date: string; meetingType: string; durationSeconds?: number; videoUrl?: string; audioSource?: string; status?: string })` — INSERT INTO meetings.meetings RETURNING * — map result.

7. `updateMeeting(id: string, data: Partial<{ city: string; state: string; date: string; meetingType: string; durationSeconds: number; videoUrl: string; audioSource: string; status: string }>)` — Dynamic SET clause from non-undefined fields. Use parameterized query. Add `updated_at = NOW()`. Return updated row or null if not found.

8. `deleteMeeting(id: string)` — Hard delete: `DELETE FROM meetings.meetings WHERE id = $1 RETURNING id`. Return boolean (true if deleted, false if not found). Note: CASCADE should handle related rows (speakers, segments, etc.) — but verify CASCADE exists in schema; if not, delete child rows first in order: vote_records, votes, summary_sections, meeting_summaries, segments, speakers, then meeting.

<task type="auto">
  <name>Task 2: Meetings routes and registration</name>
  <files>backend/src/routes/meetings.ts, backend/src/index.ts</files>
  <action>
Create `backend/src/routes/meetings.ts` following the established route patterns:

```
import { Router } from 'express';
import { optionalAuth, requireAuth } from '../middleware/auth.js';
import { requireAdmin } from '../middleware/requireAdmin.js';
import type { Request, Response } from 'express';
import { z } from 'zod';
```

Import all service functions from meetingsService.

**UUID validation:** `const UUID_REGEX = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i;`

**Public read routes (optionalAuth):**

1. `GET /` (maps to /api/meetings) — parse optional query params `?city=`, `?state=`, `?status=`. Pass as filters to getMeetings(). Return 200 with array.

2. `GET /:id` — validate UUID. Call getMeetingById. Return 200 with meeting+speakers, or 404.

3. `GET /:id/transcript` — validate UUID. Parse `?page=` as integer (default 1, min 1). Call getTranscriptByMeetingId. Return 200 with `{ segments, page, totalCount }`.

4. `GET /:id/summary` — validate UUID. Call getSummaryByMeetingId. Return 200 with summary, or 404 if no summary.

5. `GET /:id/votes` — validate UUID. Call getVotesByMeetingId. Return 200 with votes array.

**Admin write routes (requireAuth + requireAdmin on each):**

6. `POST /` — Zod validate body:
```typescript
z.object({
  city: z.string().min(1),
  state: z.string().min(1),
  date: z.string().min(1),
  meetingType: z.string().min(1),
  durationSeconds: z.number().int().positive().optional(),
  videoUrl: z.string().url().optional(),
  audioSource: z.string().optional(),
  status: z.string().optional(),
})
```
Call createMeeting. Return 201.

7. `PATCH /:id` — validate UUID param. Zod validate body (all fields optional, at least one required). Call updateMeeting. Return 200 or 404.

8. `DELETE /:id` — validate UUID param. Call deleteMeeting. Return 204 if deleted, 404 if not found.

**Error handling:** Same pattern as treasury routes. try/catch, log prefix, INTERNAL_ERROR/INVALID_ID/VALIDATION_ERROR codes.

**Register in index.ts:**
- Add import: `import meetingsRouter from './routes/meetings.js';`
- Add mount: `app.use('/api/meetings', meetingsRouter);` — place after treasury route

**IMPORTANT:** Do NOT add user-action routes (RSVP, agenda items). The meetings schema has NO user-linked tables. This was confirmed in the research phase.
