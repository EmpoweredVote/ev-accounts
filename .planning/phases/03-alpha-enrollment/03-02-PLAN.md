**Create `backend/src/lib/inviteService.ts`:**

This file uses `pool` from `./db.js` for all database writes (atomic transactions). It also uses `supabaseAdmin` for non-transactional reads (e.g., checking remaining invite count). Follow the authService.ts pattern: file-level comment explaining WHY this file exists and why it uses supabaseAdmin.

Functions to implement:

1. `generateInviteCode(): string` — Generate an 8-character code in `A3B7-XK29` format (4 chars, hyphen, 4 chars).
   - Character set: `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (32 chars — no 0, O, 1, I, L to avoid ambiguity).
   - Use `crypto.randomBytes(16)` and pick characters via `byte % 32`. Since 256/32 = 8 exactly, there is no modulo bias.
   - Return format: `${code.slice(0,4)}-${code.slice(4,8)}`

2. `createInviteCodes(userId: string, count: number): Promise<string[]>` — Batch-create invite codes for a user.
   - Uses pg pool. INSERT `count` rows into `connect.invite_codes` with `created_by = userId`, `expires_at = now() + interval '30 days'`.
   - Returns the generated code strings.
   - Retry logic: if a code collides on UNIQUE(code), regenerate and retry (max 3 attempts per code).

3. `getMyInviteCodes(userId: string): Promise<InviteCode[]>` — Fetch all invite codes created by this user.
   - Uses supabaseAdmin `.schema('connect').from('invite_codes').select('*').eq('created_by', userId).order('created_at', { ascending: false })`.
   - Returns array of invite code objects.

4. `claimInviteCode(code: string, claimantUserId: string): Promise<ClaimResult>` — Atomic claim via pg pool.
   - Full implementation from RESEARCH.md Pattern 1:
     - BEGIN
     - SELECT ... FROM connect.invite_codes WHERE code = $1 FOR UPDATE
     - Validate: exists, not claimed, not expired, not self-invite (created_by !== claimantUserId)
     - UPDATE set is_claimed = true, claimed_by, claimed_at
     - INSERT into connect.invite_chains (inviter_id = created_by, invitee_id = claimantUserId, invite_code_id = id). If created_by is NULL (admin-created), still record the chain with inviter_id = NULL... Actually, invite_chains.inviter_id is NOT NULL. For admin-created codes, skip the chain insert entirely (no inviter to track).
     - COMMIT
   - Return type: `{ success: true, inviterId: string | null } | { success: false, error: 'INVALID_CODE' | 'CODE_ALREADY_CLAIMED' | 'CODE_EXPIRED' | 'SELF_INVITE_BLOCKED' }`
   - IMPORTANT: The `FOR UPDATE` lock is blocking (not NOWAIT). Second concurrent request blocks until first completes, then sees the updated `is_claimed = true` and returns CODE_ALREADY_CLAIMED.
   - On any exception: ROLLBACK and re-throw.
   - Always `client.release()` in finally block.

Define TypeScript types at the top of the file:
```typescript
interface InviteCode {
  id: string;
  code: string;
  created_by: string | null;
  claimed_by: string | null;
  is_claimed: boolean;
  claimed_at: string | null;
  expires_at: string | null;
  created_at: string;
  updated_at: string;
}

type ClaimResult =
  | { success: true; inviterId: string | null }
  | { success: false; error: 'INVALID_CODE' | 'CODE_ALREADY_CLAIMED' | 'CODE_EXPIRED' | 'SELF_INVITE_BLOCKED' };
```

**Create `backend/src/routes/invites.ts`:**

This file MUST NOT reference supabaseAdmin anywhere (not even in comments — the architecture test does a raw string `includes('supabaseAdmin')` check). All admin-level operations go through inviteService and enrollService imports.

Import `express-rate-limit` (already in package.json). Import service functions from `../lib/inviteService.js` and `../lib/enrollService.js`.

Routes:

1. **POST /api/invites/send** — Connected user generates an invite code to share.
   - Middleware: `requireAuth`, `requireConnected`, `inviteSendLimiter`
   - Rate limiter config:
     ```typescript
     const inviteSendLimiter = rateLimit({
       windowMs: 24 * 60 * 60 * 1000, // 24 hours
       max: 10,
       keyGenerator: (req) => (req as AuthenticatedRequest).userId ?? req.ip ?? 'unknown',
       message: { code: 'RATE_LIMIT_EXCEEDED', message: 'Invite limit reached for today' },
       standardHeaders: true,
       legacyHeaders: false,
     });
     ```
   - Handler logic:
     - Check how many unclaimed codes the user currently has. Query via `getMyInviteCodes(userId)` and count unclaimed ones. If unclaimed count >= 5, return 409 `{ code: 'INVITE_LIMIT_REACHED', message: 'You already have 5 pending invite codes' }`.
     - Call `createInviteCodes(userId, 1)` to generate 1 new code.
     - Return 201 `{ code: generatedCode, expires_at: <30 days from now> }`.

2. **POST /api/invites/claim** — Any authenticated user claims an invite code.
   - Middleware: `requireAuth` only (user does NOT need to be Connected — they are becoming Connected via this flow)
   - Body validation via Zod: `{ code: z.string().min(9).max(9) }` (format: `XXXX-XXXX`, 9 chars with hyphen)
   - Handler logic:
     - Normalize the code to uppercase and trim: `const normalizedCode = body.code.toUpperCase().trim();`
     - Call `claimInviteCode(normalizedCode, userId)`
     - If `success: false`, map error to HTTP status:
       - `INVALID_CODE` -> 404 `{ code: 'INVALID_CODE', message: 'Invite code not found' }`
       - `CODE_ALREADY_CLAIMED` -> 409 `{ code: 'CODE_ALREADY_CLAIMED', message: 'This invite code has already been used' }`
       - `CODE_EXPIRED` -> 410 `{ code: 'CODE_EXPIRED', message: 'This invite code has expired' }`
       - `SELF_INVITE_BLOCKED` -> 403 `{ code: 'SELF_INVITE_BLOCKED', message: 'You cannot claim your own invite code' }`
     - If `success: true`, return 200 `{ claimed: true, inviter_id: result.inviterId }`.

3. **GET /api/invites/mine** — Connected user sees their own invite codes.
   - Middleware: `requireAuth`, `requireConnected`
   - Handler: call `getMyInviteCodes(userId)`, return 200 with the array.
   - Whitelist-serialize each code object: only return `{ id, code, is_claimed, claimed_at, expires_at, created_at }`. Do NOT return `created_by` or `claimed_by` UUIDs to the client.

Export as `invitesRouter`.
