  <name>Task 2: Create usePoliticianData custom hook</name>
  <files>essentials/src/hooks/usePoliticianData.js</files>
  <action>
Create a new file `essentials/src/hooks/usePoliticianData.js` implementing the core polling + data-fetching hook.

**Imports:**
- `useState, useEffect, useRef` from "react"
- `checkCacheStatus, fetchPoliticiansSingle, searchPoliticians` from "../lib/api"

**Hook signature:** `export function usePoliticianData(query, options = {})`

**Options (with defaults):**
- `enabled = true` -- gate to prevent fetching (e.g., when query is empty or sessionStorage hit)
- `maxAttempts = 10` -- max cache-status polls before timeout (generous: 10 polls at exponential backoff ~= 25s total)
- `baseInterval = 1000` -- starting backoff interval in ms
- `initialData = []` -- allows pre-populating from sessionStorage

**State:**
- `data` (array, default: initialData) -- politician list
- `phase` (string: "idle" | "checking" | "warming" | "loading" | "fresh" | "error") -- current state
- `error` (string | null) -- error message

**Refs:**
- `controllerRef` -- stores current AbortController for cleanup
- `latestRequestRef` -- incrementing counter to ignore stale responses (race condition prevention per research Pitfall 2)

**Core useEffect (deps: [query, enabled, maxAttempts, baseInterval]):**

1. Guard: if `!enabled || !query`, set phase to "idle" and return
2. Abort any previous in-flight request: `controllerRef.current?.abort()`
3. Create new AbortController, store in controllerRef
4. Increment latestRequestRef, capture as local `requestId`
5. Define async `pollAndFetch()`:

   a. Determine if query is ZIP: `/^\d{5}$/.test(query)`

   b. **ZIP path:**
      - Set phase to "checking"
      - Loop up to maxAttempts:
        - Check `signal.aborted` before each iteration, return if true
        - Call `checkCacheStatus(query, signal)`
        - Check `signal.aborted` after response, return if true
        - Check `requestId === latestRequestRef.current`, return if stale
        - If `status.allFresh === true`:
          - Set phase to "loading"
          - Call `fetchPoliticiansSingle(query, signal)`
          - Guard against abort/stale again
          - `setData(result)`, `setPhase("fresh")`
          - Return (done)
        - If `status.warming === true`: set phase to "warming"
        - Calculate backoff delay: `Math.min(baseInterval * Math.pow(1.5, attempt), 5000)`
        - Add jitter: `+ Math.random() * 200`
        - `await new Promise(resolve => setTimeout(resolve, delay))`
        - Increment attempt
      - If loop exhausts: `setError("Request timed out...")`, `setPhase("error")`

   c. **Address path (non-ZIP):**
      - Set phase to "loading"
      - Call `searchPoliticians(query)` (existing function, no signal param -- it doesn't support it)
      - Guard against abort/stale
      - If `result.error`: `setError(result.error)`, `setPhase("error")`, return
      - `setData(Array.isArray(result.data) ? result.data : [])`, `setPhase("fresh")`

   d. **Error handling (wraps entire pollAndFetch):**
      - Catch block: if `err.name === "AbortError"`, return silently (intentional cancellation)
      - Otherwise: `setError(err.message)`, `setPhase("error")`

6. Call `pollAndFetch()`
7. Return cleanup: `() => controller.abort()`

**Return value:** `{ data, phase, error }`

**Important implementation notes:**
- Reset `setError(null)` at the start of pollAndFetch (clear previous errors)
- Reset `setData(initialData)` at the start of pollAndFetch only for ZIP queries (address queries don't clear)
- Phase "error" is distinct from "idle" -- "error" means something went wrong, "idle" means no search active
- The sleep/delay should NOT use AbortController signal (setTimeout is not abortable) -- but the loop checks `signal.aborted` at the TOP of each iteration, so the abort is picked up after the sleep completes
