**Create `backend/src/lib/inviteQuotaService.ts`:**

Import `pool` from `./db.js`. All functions use `pool.query()` — never PostgREST for connect schema.

Functions:

1. `generateInviteCodeIfAllowed(userId: string)` — calls `connect.generate_invite_code_if_allowed($1)`. Returns `{ ok: boolean; code: string | null; error: string | null; active_count: number; cap: number }`.

2. `getMyInvitees(userId: string)` — calls `connect.get_my_invitees($1)`. The RPC returns rows with `active_count` and `effective_cap` columns on every row (computed server-side in the RPC — single source of truth, no JS recomputation). Read `active_count` and `effective_cap` from the first row. If no rows returned (no invitees), make a separate query to get the effective cap:
   ```sql
   SELECT connect.get_invite_cap_for_level(cp.current_level) as level_cap, cp.invite_cap_override
   FROM connect.connected_profiles cp WHERE cp.user_id = $1
   ```
   Then compute effective_cap with the same -1/GREATEST logic client-side for the empty case only.
   - `can_generate`: `active_count < effective_cap`
   - Return shape: `{ active_count, cap, can_generate, invitees: InviteeEntry[] }`

3. `sanctionInvitee(inviteeId: string, trDelta?: number)` — calls `connect.sanction_invitee($1, $2)` with `trDelta ?? -0.25`. Note: flat -0.25 is the Phase 59 default. Severity-scaled TR penalties are deferred until the sanctioning system exposes severity (see CONTEXT.md Deferred Ideas).

4. `clearSlotLock(inviteeId: string)` — clears slot_locked_until when an invitee is reinstated (unsuspended):
   ```typescript
   await pool.query(
     'UPDATE connect.invite_chains SET slot_locked_until = NULL WHERE invitee_id = $1',
     [inviteeId]
   );
   ```
   This frees the inviter's slot immediately on reinstatement, implementing the CONTEXT.md "whichever comes first" condition (60-day expiry OR unsuspension).

5. `setInviteCapOverride(userId: string, cap: number | null)` — direct `pool.query()` UPDATE on `connect.connected_profiles SET invite_cap_override = $2 WHERE user_id = $1`. Note: `cap` can be null (clear override), -1 (unlimited), or a positive integer.

6. `getInviteOverrides()` — query all users with non-null `invite_cap_override`:
   ```sql
   SELECT cp.user_id, u.display_name, u.email, cp.current_level,
          connect.get_invite_cap_for_level(cp.current_level) as level_cap,
          cp.invite_cap_override,
          CASE WHEN cp.invite_cap_override = -1 THEN 2147483647
               ELSE GREATEST(connect.get_invite_cap_for_level(cp.current_level), COALESCE(cp.invite_cap_override, 0))
          END as effective_cap
   FROM connect.connected_profiles cp
   JOIN public.users u ON u.id = cp.user_id
   WHERE cp.invite_cap_override IS NOT NULL
   ORDER BY u.display_name
   ```

```typescript
router.post(
  '/generate',
  requireAuth,
  requireConnected,
  inviteSendLimiter,  // reuse existing rate limiter (10/day is fine)
  async (req, res) => {
    const { userId } = req as AuthenticatedRequest;
    const result = await generateInviteCodeIfAllowed(userId);
```

   ```typescript
   router.post('/accounts/:userId/invite-cap-override', async (req, res) => {
     const parsed = InviteCapSchema.safeParse(req.body);
     if (!parsed.success) { res.status(422).json({ code: 'VALIDATION_ERROR', message: parsed.error.issues[0]?.message }); return; }
     const { userId } = req.params;
     await setInviteCapOverride(userId, parsed.data.cap);
     await logAdminAction(actorId(req), 'set_invite_cap_override', userId, { cap: parsed.data.cap });

   });
   ```
