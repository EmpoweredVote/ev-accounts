Function signature:

    p_user_id UUID,
    p_full_reset BOOLEAN DEFAULT false
  )
  RETURNS void
  LANGUAGE plpgsql
  SECURITY DEFINER
  SET search_path = ''

Function body must:
1. Soft-delete active compass responses for the user:
   UPDATE inform.compass_responses
     SET deleted_at = now()
     WHERE user_id = p_user_id AND deleted_at IS NULL;

2. Clear selected_topic_ids on connected_profiles:
   UPDATE connect.connected_profiles
     SET selected_topic_ids = '[]'::jsonb, updated_at = now()
     WHERE user_id = p_user_id;

3. Conditionally reset completed_onboarding (full reset mode only):
   IF p_full_reset THEN
     UPDATE connect.connected_profiles
       SET completed_onboarding = false, updated_at = now()
       WHERE user_id = p_user_id;
   END IF;

Exception handling:
  EXCEPTION WHEN OTHERS THEN RAISE;

This wraps all three steps in a single PL/pgSQL block — PostgreSQL PL/pgSQL BEGIN/END provides implicit transaction scope within the function. If any UPDATE fails, the exception propagates to the caller and the entire function is rolled back.

No GRANT needed — supabase's `postgres` role owns the function via SECURITY DEFINER.

  <name>Task 3: import_compass_calibrations RPC migration (028)</name>
  <files>backend/migrations/028_rpc_import_compass_calibrations.sql</files>
  <action>
Create migration file 028 containing a single SECURITY DEFINER RPC function: public.import_compass_calibrations.

Function signature:
  CREATE OR REPLACE FUNCTION public.import_compass_calibrations(
    p_user_id UUID,
    p_calibrations JSONB,
    p_set_onboarding_complete BOOLEAN DEFAULT false
  )
  RETURNS void
  LANGUAGE plpgsql
  SECURITY DEFINER
  SET search_path = ''

Function body:
1. Validate each calibration element using a dedicated FOR loop over jsonb_array_elements(p_calibrations). Check that topic_id is a valid UUID present in inform.compass_topics and value is between 1 and 5. If any element fails validation, RAISE EXCEPTION 'INVALID_CALIBRATION' immediately. This loop must complete fully before any writes begin — do NOT interleave validation and upserts in a single loop. Atomicity guarantee: if any element fails, nothing is written.

2. Bulk upsert into inform.compass_responses using a second, separate FOR loop over jsonb_array_elements(p_calibrations). This loop runs only after the entire validation loop above completes without error:
   INSERT INTO inform.compass_responses (user_id, topic_id, value, write_in_text, inverted, updated_at, deleted_at)
   VALUES (p_user_id, elem->>'topic_id', (elem->>'value')::int,
           elem->>'write_in_text', COALESCE((elem->>'inverted')::boolean, false),
           now(), NULL)
   ON CONFLICT (user_id, topic_id) DO UPDATE
     SET value = EXCLUDED.value,
         write_in_text = EXCLUDED.write_in_text,
         inverted = EXCLUDED.inverted,
         updated_at = now(),
         deleted_at = NULL;  -- un-soft-delete if previously reset

3. Conditionally complete onboarding:
   IF p_set_onboarding_complete THEN
     UPDATE connect.connected_profiles
       SET completed_onboarding = true, updated_at = now()
       WHERE user_id = p_user_id AND completed_onboarding = false;
   END IF;

EXCEPTION WHEN OTHERS THEN RAISE;

Implementation note: Two separate FOR loops are required — first a full validation pass (raises on any failure before any writes), then a separate upsert pass. A single combined loop would allow partial writes before a validation failure is encountered, which violates the atomicity guarantee.
