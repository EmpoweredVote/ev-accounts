# Phase 108.1 Plan 01: Essentials client non-JSON hardening Summary

One-liner: `fetch_body_roster` now wraps `resp.json()` parse failures in `EssentialsClientError` with a `"Non-JSON response from {url}: {snippet}"` message, closing gap G2 from Phase 108 HUMAN-UAT where an HTTP 200 + `text/html` body (admin SPA catch-all) leaked a raw `requests.exceptions.JSONDecodeError` up the stack.

## What Was Built

- **`CouncilScribe/src/essentials_client.py`** — Final `return resp.json()` at the end of `fetch_body_roster` replaced with a `try`/`except ValueError` block. On parse failure it raises `EssentialsClientError(f"Non-JSON response from {url}: {resp.text[:200]}", status=resp.status_code)` with `from exc` chaining. No other branch modified — 404/422/5xx/network-error paths are byte-identical. `ValueError` was chosen (over `requests.exceptions.JSONDecodeError`) to stay consistent with the existing 404/422 branches in the same file, which already use that pattern because `requests.exceptions.JSONDecodeError` inherits from `json.JSONDecodeError` → `ValueError`.

- **`CouncilScribe/tests/test_essentials_client.py`** — Added `test_fetch_body_roster_non_json_200_wrapped` regression. Patches `src.essentials_client.requests.get` to return a `MagicMock` with `status_code=200`, `headers={"Content-Type": "text/html; charset=utf-8"}`, `text=<!doctype html>...`, and `json.side_effect = requests.exceptions.JSONDecodeError("Expecting value", "doc", 0)`. Asserts `EssentialsClientError` is raised with `"Non-JSON response"` in the message and a `"<!doctype html"` snippet of the body. Existing `_mock_response` helper untouched — the new test inlines its mock so the existing helper's semantics are not complicated by the edge case.
