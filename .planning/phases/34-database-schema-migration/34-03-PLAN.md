Write the migration file following this pattern (differs from Plan 02 — authenticated only, no anon):

```sql
BEGIN;

-- =============================================================================
-- Migration 049: RLS policies and grants for the staging schema
-- =============================================================================
-- Staging contains volunteer data entry and review workflow data.
-- Access: authenticated users only (no anon). Reviewer/admin role gating
-- is enforced at the route middleware layer, not the RLS layer.
-- NO INSERT/UPDATE/DELETE policies — all writes via service role (pool.query()).
-- =============================================================================

-- Section 1: Enable RLS
ALTER TABLE staging.{table1} ENABLE ROW LEVEL SECURITY;
ALTER TABLE staging.{table2} ENABLE ROW LEVEL SECURITY;
-- ... all staging tables from 34-01-SUMMARY

-- Section 2: Authenticated-only read policies
CREATE POLICY "{table1}: authenticated read"
  ON staging.{table1}
  FOR SELECT
  TO authenticated
  USING (true);
-- ... repeat for each staging table

-- Section 3: Grants (authenticated only — NO anon)
GRANT USAGE ON SCHEMA staging TO authenticated;
GRANT SELECT ON ALL TABLES IN SCHEMA staging TO authenticated;
ALTER DEFAULT PRIVILEGES IN SCHEMA staging GRANT SELECT ON TABLES TO authenticated;

-- Also grant service_role full access explicitly
GRANT USAGE ON SCHEMA staging TO service_role;
GRANT ALL ON ALL TABLES IN SCHEMA staging TO service_role;

COMMIT;
```

**CRITICAL differences from Plan 02:**
- `TO authenticated` only (never `TO anon, authenticated`)
- `GRANT USAGE ON SCHEMA staging TO authenticated` (not `TO anon, authenticated`)
- `GRANT SELECT ON ALL TABLES ... TO authenticated` (not `TO anon, authenticated`)

Use the EXACT table names from 34-01-SUMMARY. Do NOT guess.

Apply via Supabase MCP `apply_migration`.
