  <name>Task 1: Create PrimaryButton component (DSGN-04 primary)</name>
  <files>app/src/components/PrimaryButton.tsx</files>
  <action>
    Create a new file `app/src/components/PrimaryButton.tsx` containing a single named export `PrimaryButton`. The component is the v2.0 replacement for the inline submit button at `app/src/pages/LoginPage.tsx:116-122` — same shape and weight, but `bg-ev-blue text-white` instead of `bg-ev-teal-light text-ev-black`.

    Implementation:

    ```typescript
    import type { ReactNode } from 'react';

    interface PrimaryButtonProps {
      children: ReactNode;
      onClick?: () => void;
      type?: 'button' | 'submit' | 'reset';
      disabled?: boolean;
      className?: string;
    }

    export function PrimaryButton({
      children,
      onClick,
      type = 'button',
      disabled = false,
      className = '',
    }: PrimaryButtonProps) {
      return (
        <button
          type={type}
          onClick={onClick}
          disabled={disabled}
          className={`w-full bg-ev-blue text-white rounded-xl py-3 font-bold text-base hover:bg-ev-blue/90 disabled:opacity-40 disabled:cursor-not-allowed transition-colors ${className}`.trim()}
        >
          {children}
        </button>
      );
    }
    ```

    Key constraints:
    - `type` defaults to `'button'` (NOT submit). Forms must explicitly opt in via `type="submit"`. This prevents accidental form submission when the button is used outside a form.
    - `bg-ev-blue text-white` (NOT `bg-ev-blue text-ev-black` — text on blue must be white for contrast). NOT `bg-ev-teal-light text-ev-black` (the old token).
    - `hover:bg-ev-blue/90` — Tailwind v4 opacity modifier. ev-blue at 90% opacity for the hover state. Confirmed working with Tailwind v4 `@theme` tokens.
    - `disabled:opacity-40 disabled:cursor-not-allowed` — visual + cursor feedback when disabled.
    - `transition-colors` — smooth state transitions.
    - DO NOT include a `loading` prop with a built-in spinner. Loading text is the consumer's responsibility (e.g., children = `loading ? 'Saving…' : 'Save'`); keeping the component simple matches the existing LoginPage pattern.
    - DO use named export. DO use `interface` for props.

    WHY w-full as the default: the v2.0 design uses full-width buttons everywhere. If a consumer needs a non-full-width button, they pass `className="w-auto"` to override (Tailwind's last-class-wins behavior).

    WHY rounded-xl not rounded-full: matches existing button pattern in LoginPage; rounded-full implies pill shape which is not the v2.0 design.

  <files>app/src/components/SecondaryButton.tsx</files>

There is NO existing secondary button in the codebase to extract from — this is a fresh design call. Per 60-RESEARCH.md "Open Question 3", the resolved design is `bg-gray-800 text-white border border-gray-700` with a slightly lighter hover state.

    Implementation:

    ```typescript
    import type { ReactNode } from 'react';

    interface SecondaryButtonProps {
      children: ReactNode;
      onClick?: () => void;
      type?: 'button' | 'submit' | 'reset';
      disabled?: boolean;
      className?: string;
    }

    export function SecondaryButton({
      children,
      onClick,
      type = 'button',
      disabled = false,
      className = '',
    }: SecondaryButtonProps) {
      return (
        <button
          type={type}
          onClick={onClick}
          disabled={disabled}
          className={`w-full bg-gray-800 text-white border border-gray-700 rounded-xl py-3 font-bold text-base hover:bg-gray-700 disabled:opacity-40 disabled:cursor-not-allowed transition-colors ${className}`.trim()}
        >
          {children}
        </button>
      );
    }
    ```

    Key constraints:
    - Same prop shape as PrimaryButton — keeps consumer ergonomics consistent. Both buttons drop into the same slot.
    - Same defaults: `type='button'`, `disabled=false`. Same w-full, rounded-xl, py-3, font-bold, text-base — same visual weight as PrimaryButton, just different palette.
    - `bg-gray-800` (slightly lighter than `bg-gray-900` used by AuthCard) so that when SecondaryButton appears INSIDE an AuthCard, it has visual layering. `border border-gray-700` provides additional definition.
    - `hover:bg-gray-700` — one step lighter on hover.
    - `text-white` — full white for legibility on dark background.
    - DO NOT use `bg-transparent` or outline-only style. The v2.0 design (per research) calls for filled secondary, not ghost.
    - DO use named export. DO use `interface` for props.

    WHY same prop shape as PrimaryButton: when the design needs to swap primary→secondary (e.g., changing CTA hierarchy), the consumer changes only the import name. No prop migration.

    WHY bg-gray-800 not bg-ev-navy: when SecondaryButton is on a page with `bg-ev-navy` page background AND inside an `AuthCard` with `bg-gray-900`, the button needs to be visually distinct from BOTH surfaces. gray-800 is lighter than both, providing layering.
