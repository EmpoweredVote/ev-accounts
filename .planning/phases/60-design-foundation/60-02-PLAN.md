  <action>
    Create a new file `app/src/components/AuthCard.tsx` containing a single named export `AuthCard`. The component is a thin wrapper that produces the dark rounded bordered card pattern currently inlined at `app/src/pages/LoginPage.tsx:80` (the div with classes `w-full max-w-sm bg-gray-900 rounded-2xl border border-gray-800 p-6 space-y-5`).

    Implementation:

    ```typescript
    import type { ReactNode } from 'react';

    interface AuthCardProps {
      children: ReactNode;
      className?: string;
    }

    export function AuthCard({ children, className = '' }: AuthCardProps) {
      return (
        <div
          className={`bg-gray-900 rounded-2xl border border-gray-800 p-6 space-y-5 ${className}`.trim()}
        >
          {children}
        </div>
      );
    }
    ```

    Key constraints:
    - DO NOT include `w-full` or `max-w-sm` in the base class string. Width is the parent's responsibility (LoginPage uses `max-w-sm`, but onboarding steps may want wider). Consumer passes width via `className` prop or a containing wrapper.
    - DO NOT add `bg-ev-navy` as the card background. The card SITS ON `bg-ev-navy` (Phase 61 page bg); the card itself uses `bg-gray-900` (slightly lighter) to provide visual layering. This is the resolved decision in 60-RESEARCH.md "Open Question 1".
    - DO use a named export `export function AuthCard`. NOT `React.FC<AuthCardProps>`. NOT default export. Named exports match the codebase convention (see AuthGuard.tsx, OnboardingGuard.tsx).
    - DO use a TypeScript `interface` for props, not `type`. Match the codebase style.
    - Trim trailing whitespace in the className concatenation so an empty `className` prop does not produce a trailing space.

    WHY no max-width: see research pitfall #5. Hardcoding width forces every page to the same size; the v2.0 design has at least one wider step screen.

    WHY bg-gray-900 not bg-ev-navy: contrast against the page bg. Same color = the card disappears against the background.

<task type="auto">
  <name>Task 2: Create AuthInput component (DSGN-03)</name>
  <files>app/src/components/AuthInput.tsx</files>
  <action>
    Create a new file `app/src/components/AuthInput.tsx` containing a single named export `AuthInput`. The component renders label + controlled `<input>` + optional inline error message, extracted from the inline pattern at `app/src/pages/LoginPage.tsx:90-100` and adapted to the new blue focus ring.

    Implementation:

    ```typescript
    import type { InputHTMLAttributes } from 'react';

    interface AuthInputProps {
      label: string;
      type?: string;
      value: string;
      onChange: (value: string) => void;
      placeholder?: string;
      error?: string;
      autoComplete?: string;
      required?: boolean;
      autoFocus?: boolean;
      inputProps?: Omit<
        InputHTMLAttributes<HTMLInputElement>,
        'type' | 'value' | 'onChange' | 'placeholder' | 'autoComplete' | 'required' | 'autoFocus'
      >;
    }

    export function AuthInput({
      label,
      type = 'text',
      value,
      onChange,
      placeholder,
      error,
      autoComplete,
      required,
      autoFocus,
      inputProps,
    }: AuthInputProps) {
      const borderClass = error
        ? 'border-ev-red focus:ring-ev-red'
        : 'border-gray-700 focus:ring-ev-blue';

      return (
        <div>
          <label className="block text-sm font-medium text-gray-300 mb-1.5">{label}</label>
          <input
            {...inputProps}
            type={type}
            value={value}
            onChange={(e) => onChange(e.target.value)}
            placeholder={placeholder}
            autoComplete={autoComplete}
            required={required}
            autoFocus={autoFocus}
            className={`w-full bg-gray-800 border ${borderClass} rounded-xl px-4 py-3 text-white placeholder-gray-500 focus:outline-none focus:ring-2 text-base`}
          />
          {error && <p className="mt-1.5 text-ev-red text-sm">{error}</p>}
        </div>
      );
    }
    ```

    Key constraints:
    - The component is FULLY CONTROLLED: `value` and `onChange` are required props. DO NOT accept `defaultValue`. DO NOT have internal `useState` for the input value. See research pitfall #3.
    - The `onChange` prop signature is `(value: string) => void` — the component extracts `e.target.value` and passes the string. This matches the convention used in onboarding step components.
    - Focus ring uses `focus:ring-ev-blue` (NOT `focus:ring-ev-teal-light` — the old token). This requires plan 60-01 to have shipped the ev-blue token first.
    - Error state: replace `border-gray-700 focus:ring-ev-blue` with `border-ev-red focus:ring-ev-red` AND render an inline error paragraph below the input.
    - `inputProps` is a pass-through escape hatch for less common attributes (`inputMode`, `pattern`, `spellCheck`, `maxLength`, etc.) WITHOUT colliding on already-named props. Use TypeScript `Omit` to make this explicit.
    - DO use named export. DO use `interface` for props.

    WHY explicit Omit on inputProps: prevents a consumer from passing `value` or `onChange` through `inputProps` and silently overriding the controlled props. TypeScript catches this at compile time.

    WHY focus:ring-ev-blue not focus:ring-ev-blue/50 or similar opacity variant: the design spec calls for a solid blue ring; opacity variants are reserved for hover/disabled states.
