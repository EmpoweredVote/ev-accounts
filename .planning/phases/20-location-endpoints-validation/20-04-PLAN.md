Create `backend/tests/architecture/coordinateLeakage.test.ts` using Vitest (already in devDependencies).

The test must use Node's `fs` module to read route source files as plain text and assert forbidden patterns are absent.

**Forbidden patterns to detect:**

1. `encrypted_lat` — the raw encrypted column name should never appear in a route SELECT list or API response
2. `encrypted_lng` — same as above
3. Raw float coordinate patterns in `res.json()` calls: look for `lat:` or `lng:` keys adjacent to numeric values in response objects that are NOT the jurisdiction response shape (which uses `congressional_district`, `county`, etc. keys — none named `lat` or `lng`)

Use these specific regexes:
```typescript
const FORBIDDEN_PATTERNS = [
  { pattern: /encrypted_lat/, description: 'encrypted_lat column in route file' },
  { pattern: /encrypted_lng/, description: 'encrypted_lng column in route file' },
  // Detect res.json({ ... lat: ..., ... }) or { lat, lng } spread patterns
  // This catches direct lat/lng key inclusion in response objects
  { pattern: /res\.json\([^)]*\blat\b/, description: 'lat coordinate in res.json() call' },
  { pattern: /res\.json\([^)]*\blng\b/, description: 'lng coordinate in res.json() call' },
];
```

**Note on the res.json patterns:** These use a simplified regex. For multiline res.json calls (which is the common pattern), a line-by-line scan is not sufficient. Use a multiline approach: read the whole file as a string and test against the full content. The `lat` and `lng` variable names are used only in the set-location handler where they are passed to `adminRpc` — they should never appear inside a `res.json(` call.

**Test structure:**

```typescript
import { describe, it, expect } from 'vitest';
import * as fs from 'fs';
import * as path from 'path';
import { fileURLToPath } from 'url';

const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);

const ROUTES_DIR = path.resolve(__dirname, '../../src/routes');

const FORBIDDEN_PATTERNS = [
  { pattern: /encrypted_lat/, description: 'encrypted_lat column reference' },
  { pattern: /encrypted_lng/, description: 'encrypted_lng column reference' },
  { pattern: /res\.json\([\s\S]*?\blat\b[\s\S]*?\)/, description: 'lat coordinate in res.json() response' },
  { pattern: /res\.json\([\s\S]*?\blng\b[\s\S]*?\)/, description: 'lng coordinate in res.json() response' },
];

describe('Architecture: coordinate leakage', () => {
  const routeFiles = fs
    .readdirSync(ROUTES_DIR)
    .filter((f) => f.endsWith('.ts'))
    .map((f) => path.join(ROUTES_DIR, f));

  it('should have route files to scan', () => {
    expect(routeFiles.length).toBeGreaterThan(0);
  });

  for (const filePath of routeFiles) {
    const fileName = path.basename(filePath);
    const content = fs.readFileSync(filePath, 'utf-8');

    for (const { pattern, description } of FORBIDDEN_PATTERNS) {
      it(`${fileName}: must not contain "${description}"`, () => {
        const match = content.match(pattern);
        expect(match, `Violation in ${fileName}: found "${description}"\nPattern: ${pattern}\nMatch: ${match?.[0]?.slice(0, 100)}`).toBeNull();
      });
    }
  }
});
```

**Important implementation notes:**

The `res.json()` multiline regex patterns are intentionally broad to catch any case where `lat` or `lng` appear as argument content in a `res.json(` call. However, this may produce false positives if a route legitimately has a field called `lat_verified` or similar. In this codebase, no such fields exist — the patterns are safe.

If the tests fail on the newly written routes (connect.ts or account.ts), that indicates a real coordinate leakage issue that must be fixed before this test passes. Do NOT add exceptions or allowlist logic — fix the route instead.

Create the `backend/tests/architecture/` directory if it does not exist (the `fs.readdirSync` call will create no files, but the test file itself goes in this directory).
