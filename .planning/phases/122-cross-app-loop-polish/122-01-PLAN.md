### Task 1.1 — INTG-01: Fix CompassCard relay for returning guests
`type="checkpoint:human-verify"`

**What was built in Wave 0:**

**INTG-01 Root Cause Identified (from code trace):**
The `clearGuestCompass()` call at `CompassContext.jsx:128` is unconditional — it runs whenever `authedUser` is present, wiping the guest compass cache regardless of whether the API returned answers. A logged-in user with zero API answers will have their guest data destroyed.

For the pure-guest path (no `authedUser`), the code is correct: `loadGuestCompass()` is called at line 141 and should work. The question is whether the guest flow actually reaches that branch on a return visit with no fragment.

**Checkpoint: Verify Wave 0 baseline before implementing INTG-01 fix**

### Task 2.1 — INTG-01: Implement fix for logged-in user with empty API answers
`type="auto"`

Fix `essentials/src/contexts/CompassContext.jsx` in the `authedUser` branch:

**Current behavior (line 128):** `clearGuestCompass()` always called when user is logged in.

**Fix:** Before clearing, check if API returned empty answers AND `loadGuestCompass()` has data. If so, use the guest data as the display data instead of clearing it. This preserves the user's compass experience when they've calibrated as a guest but haven't yet saved API answers.

```js
// In the authedUser block, after fetching answersResult:
if (answersResult.length === 0) {
  // API has no answers — try guest cache before clearing
  const guestCache = loadGuestCompass();
  if (guestCache) {
    answers = convertGuestAnswersToApiFormat(guestCache.answers, topics);
    selected = guestCache.selectedTopics;
    inverted = guestCache.invertedSpokes || {};
    // Don't clear — preserve guest cache for future visits
  } else {
    clearGuestCompass();
  }
} else {
  [answers, selected] = [answersResult, selectedResult];
  clearGuestCompass(); // Has API answers — clean separation
}
```

Also remove the `import.meta.env.DEV` probe log added in Task 0.1 (it served its diagnostic purpose).

**Done criteria:**
- `CompassContext.jsx` patched with guest-cache fallback for logged-in users with empty API answers
- Probe log removed

**Municipality matching rule** (from research):
```js
function normalize(s) {
  return s.toLowerCase().replace(/\s+/g, ' ').trim();
}
function findMatchingMunicipality(bodyTitle, municipalities) {
  const titleLower = normalize(bodyTitle);
  const matches = municipalities.filter(m =>
    m.available_datasets.length > 0 &&
    titleLower.startsWith(normalize(m.name))
  );
  // Use longest match if overlapping names
  matches.sort((a, b) => b.name.length - a.name.length);
  return matches[0] || null;
}
function toSlug(m) {
  return `${m.name.toLowerCase().replace(/\s+/g, '-')}-${m.state.toLowerCase()}`;
}
```
