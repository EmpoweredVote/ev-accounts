    **1. Create migration 013** (`supabase/migrations/20260225000013_rls_update_policies.sql`):

    ```sql
    BEGIN;

    -- public.users: owner can update display_name and avatar_url
    CREATE POLICY "users: owner update"
      ON public.users
      FOR UPDATE
      TO authenticated
      USING ((select auth.uid()) = id AND deleted_at IS NULL)
      WITH CHECK ((select auth.uid()) = id AND deleted_at IS NULL);

    GRANT UPDATE (display_name, avatar_url, updated_at) ON public.users TO authenticated;

    -- connect.connected_profiles: owner can update display_name only
    CREATE POLICY "connected_profiles: owner update"
      ON connect.connected_profiles
      FOR UPDATE
      TO authenticated
      USING ((select auth.uid()) = user_id AND deleted_at IS NULL)
      WITH CHECK ((select auth.uid()) = user_id AND deleted_at IS NULL);

    GRANT UPDATE (display_name, updated_at) ON connect.connected_profiles TO authenticated;

    COMMIT;
    ```

    **2. Create `backend/src/lib/authService.ts`:**

    A thin wrapper that delegates auth operations to supabaseAdmin. This keeps supabaseAdmin out of route files (architecture test enforcement). The wrapper must:

    - Import `supabaseAdmin` from `./supabase.js`
    - Export `signUpWithEmail(email: string, password: string)` — calls `supabaseAdmin.auth.signUp({ email, password })`
    - Export `signInWithEmail(email: string, password: string)` — calls `supabaseAdmin.auth.signInWithPassword({ email, password })`
    - Export `signOutUser(accessToken: string)` — calls `supabaseAdmin.auth.admin.signOut(accessToken, 'global')` (global scope revokes all sessions — appropriate for civic auth)
    - Each function returns the raw Supabase `{ data, error }` result (no transformation — let the route handler decide how to map errors)
    - Add JSDoc comments explaining WHY this wrapper exists (architecture constraint, not abstraction for its own sake)

    **3. Create `backend/src/routes/auth.ts`:**

    Express Router with three POST endpoints. Follow established patterns from `routes/health.ts` (Router export, consistent style).

    **POST /api/auth/signup:**
    - Validate body with Zod: `{ email: z.string().email(), password: z.string().min(8) }`
    - On Zod validation failure: return 422 `{ code: 'VALIDATION_ERROR', message: '<first issue as human-readable string>' }`
    - Call `signUpWithEmail(email, password)` from authService
    - IMPORTANT: When email confirmation is ON (Supabase default), `data.session` will be `null`. This is NOT an error. Check `data.user` instead.
    - On success (data.user exists): return 201 `{ id: data.user.id, message: 'Check your email to confirm your account' }`
    - On Supabase error `email_exists` or message containing "already registered": return 409 `{ code: 'EMAIL_EXISTS', message: 'An account with this email already exists' }`
    - On Supabase error `weak_password`: return 422 `{ code: 'VALIDATION_ERROR', message: 'Password is too weak' }`
    - On other Supabase error: return 500 `{ code: 'INTERNAL_ERROR', message: 'An unexpected error occurred' }`
    - Apply `authLimiter` rate limiter (see below)

    **POST /api/auth/login:**
    - Validate body with Zod: same schema as signup `{ email, password }`
    - On Zod validation failure: same 422 pattern
    - Call `signInWithEmail(email, password)` from authService
    - On success (data.session exists): return 200 with:
      ```json
      {
        "access_token": data.session.access_token,
        "refresh_token": data.session.refresh_token,
        "expires_in": data.session.expires_in,
        "expires_at": data.session.expires_at,
        "token_type": "bearer",
        "user": {
          "id": data.user.id,
          "email": data.user.email,
          "display_name": null,
          "tier": "inform",
          "account_standing": "active"
        }
      }
      ```
      Note: Login response returns a minimal profile stub. Full tier detection happens in GET /api/account/me (Plan 02-02). The login profile is always `tier: 'inform'` and `account_standing: 'active'` — accurate for a brand-new user who just logged in. The client should call GET /api/account/me for authoritative tier data.
    - On Supabase error code `invalid_credentials`: return 401 `{ code: 'INVALID_CREDENTIALS', message: 'Invalid email or password' }` — do NOT distinguish email vs password (OWASP enumeration protection)
    - On Supabase error code `email_not_confirmed`: return 403 `{ code: 'EMAIL_NOT_VERIFIED', message: 'Please verify your email before logging in' }`
    - On other Supabase error: return 500 `{ code: 'INTERNAL_ERROR', message: 'An unexpected error occurred' }`
    - Apply `authLimiter` rate limiter

    **POST /api/auth/logout:**
    - This endpoint requires authentication. Apply `requireAuth` middleware from `../middleware/auth.js`
    - Extract `req.accessToken` from the authenticated request (set by requireAuth middleware)
    - Call `signOutUser(req.accessToken)` from authService
    - On success: return 200 `{ message: 'Logged out successfully' }`
    - On error: return 500 `{ code: 'INTERNAL_ERROR', message: 'An unexpected error occurred' }` (logout errors should not block the client — log the error with winston at ERROR level but return 200 anyway if the signOut call fails, since the access token will expire naturally)
    - Actually, on reflection: if signOut fails, still return 200 with the success message. Log the error. The access token has a short TTL and will expire. A failed signOut is not worth blocking the client.

    **Rate limiter (define at top of auth.ts):**
    ```typescript
    import rateLimit from 'express-rate-limit';

    const authLimiter = rateLimit({
      windowMs: 15 * 60 * 1000, // 15 minutes
      max: 10,                   // 10 attempts per window per IP
      standardHeaders: true,
      legacyHeaders: false,
      message: { code: 'RATE_LIMIT_EXCEEDED', message: 'Too many requests, please try again later' },
    });
    ```

    Apply to signup and login only (not logout — authenticated endpoint, already rate-limited by JWT overhead).

    **Error response contract:** All errors use `{ code: string, message: string }` — flat, no nested details. This is a locked decision from CONTEXT.md.

    **Imports:** Import `signUpWithEmail`, `signInWithEmail`, `signOutUser` from `../lib/authService.js`. Import `requireAuth` and `AuthenticatedRequest` from `../middleware/auth.js`. Import `z` from `zod`. Import `Router` from `express`. Import `rateLimit` from `express-rate-limit`.
