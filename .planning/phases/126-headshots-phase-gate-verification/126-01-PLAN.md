Add a `--generate-photos` mode that pre-flights the migration number (MAX(version) in
schema_migrations + backend/migrations/ disk max; expected 740) and writes
backend/migrations/{N}_national_house_rep_photos.sql. The migration is a single
BEGIN;...COMMIT; containing one idempotent UPDATE per batch rep:
  `UPDATE essentials.politicians SET photo_origin_url = '<url>'
     WHERE external_id = <externalId> AND photo_origin_url IS NULL;`

prefer the VALUES-list form for compactness). Only reps whose URL HEAD-check passed get a
photo URL; reps that 404'd are EXCLUDED from the migration and listed in a header comment
as no-photo-found (to be resolved via find-headshots in task 3). The UPDATE must be guarded
`photo_origin_url IS NULL` so it is idempotent and never overwrites a manually-set photo.
</action>

- Header comment lists any excluded (404) reps as no-photo-found
