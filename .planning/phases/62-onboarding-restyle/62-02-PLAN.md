    Rewrite `app/src/pages/onboarding/steps/LocationCelebrationStep.tsx`. The new component is now the FINAL step of onboarding — it owns the `POST /auth/complete-onboarding` API call previously in PseudonymStep.

    **Critical pitfall:** PseudonymStep is the only place that called `complete-onboarding`. PseudonymStep is being deleted in plan 03. If LocationCelebrationStep does NOT absorb that call, the user will tap "Go to dashboard", land on `/`, and `OnboardingGuard` will immediately redirect them back to `/onboarding` because `user.completedOnboarding` is still false — an infinite loop. Absorbing the call here is mandatory.

    Props change:
    - **Before:** `interface Props { result: LocationResult; onContinue: () => void; }`
    - **After:** `interface Props { result: LocationResult; onComplete: () => void; }` — rename `onContinue` to `onComplete` to reflect that this is the terminal step. (OnboardingPage will update its caller in plan 03.)

    Imports to add:
    ```tsx
    import { useState } from 'react';
    import { apiFetch } from '../../../lib/api';
    import { useAuthStore } from '../../../store/authStore';
    import { AppNav } from '../../../components/AppNav';
    import { StepProgress } from '../../../components/StepProgress';
    import { AuthCard } from '../../../components/AuthCard';
    import { PrimaryButton } from '../../../components/PrimaryButton';
    ```
    Keep the existing `import type { LocationResult } from './LocationStep';` — `result` is still passed in (even though we no longer render the district list, it remains part of the type so OnboardingPage doesn't need to change its prop wiring).

    Component body — local state and handler:
    ```tsx
    const { updateUser } = useAuthStore();
    const [loading, setLoading] = useState(false);
    const [error, setError] = useState('');

    async function handleGoToDashboard() {
      setError('');
      setLoading(true);
      try {
        await apiFetch('/auth/complete-onboarding', { method: 'POST' });
        updateUser({ completedOnboarding: true });
        onComplete();
      } catch (err) {
        setError(err instanceof Error ? err.message : 'Something went wrong. Please try again.');
      } finally {
        setLoading(false);
      }
    }
    ```

    Layout — match SignupPage scaffold:

    ```tsx
          <AuthCard>
            {/* checkmark badge + heading + 3 milestones + CTA */}
          </AuthCard>
        </div>
      </div>
    </div>
    ```

The `result` prop stays in the type signature (so OnboardingPage's `result={locationResult}` keeps compiling) but is no longer used inside the component body — that's fine.
