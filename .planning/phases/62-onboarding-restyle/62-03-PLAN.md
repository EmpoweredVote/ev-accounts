  <files>app/src/pages/onboarding/OnboardingPage.tsx</files>
  <action>
    Rewrite `app/src/pages/onboarding/OnboardingPage.tsx`. The new state machine has only TWO steps:
    - `'location'` — initial step for new users (locationConsent=false)
    - `'location-celebration'` — set after successful location submission

    Drop all `'welcome'` and `'pseudonym'` references. Drop the imports of `WelcomeStep` and `PseudonymStep` — those files are deleted in Task 3 below.

    Resumption pitfall — handle this carefully:
    - **Case A (new user, locationConsent=false):** start on `'location'` step. After they submit a valid address, advance to `'location-celebration'`. When the celebration step's `onComplete` fires, navigate to `/`.
    - **Case B (resumption, locationConsent=true, completedOnboarding=false):** the user already has a location set but never finished onboarding. We cannot show the celebration step because `LocationResult` is null on remount (it's only stored in component state, not persisted). Use a `useEffect` that, when `locationConsent === true` on first render, calls `POST /auth/complete-onboarding`, sets `completedOnboarding: true` on the auth store, and navigates to `/`. Do NOT render any onboarding step UI in this case — show a brief loading placeholder.
    - **Case C (already completed):** OnboardingGuard upstream prevents users with `completedOnboarding=true` from reaching `/onboarding`. We do not need to handle that here.

    New file contents (replace the entire file):
    ```tsx
    import { useEffect, useState } from 'react';
    import { useNavigate } from 'react-router-dom';
    import { apiFetch } from '../../lib/api';
    import { useAuthStore } from '../../store/authStore';
    import { LocationStep, type LocationResult } from './steps/LocationStep';
    import { LocationCelebrationStep } from './steps/LocationCelebrationStep';

    type Step = 'location' | 'location-celebration';

    export default function OnboardingPage() {
      const { user, updateUser } = useAuthStore();
      const navigate = useNavigate();

      const initialLocationConsent = user?.locationConsent ?? false;
      const [step, setStep] = useState<Step>('location');
      const [locationResult, setLocationResult] = useState<LocationResult | null>(null);
      const [resuming, setResuming] = useState(initialLocationConsent);

      // Resumption: user already has locationConsent=true but no completedOnboarding —
      // finish onboarding silently and bounce to dashboard. We can't show the celebration
      // step because we don't have a fresh LocationResult on remount.
      useEffect(() => {
        if (!initialLocationConsent) return;
        let cancelled = false;
        (async () => {
          try {
            await apiFetch('/auth/complete-onboarding', { method: 'POST' });
            if (cancelled) return;
            updateUser({ completedOnboarding: true });
            navigate('/', { replace: true });
          } catch {
            // If complete-onboarding fails, fall back to showing the location step
            // so the user has SOMETHING to do; they can re-submit and try again.
            if (!cancelled) setResuming(false);
          }
        })();
        return () => {
          cancelled = true;
        };
        // eslint-disable-next-line react-hooks/exhaustive-deps
      }, []);

      function handleLocationSuccess(result: LocationResult) {
        updateUser({ locationConsent: true });
        setLocationResult(result);
        setStep('location-celebration');
      }

      function handleOnboardingComplete() {
        navigate('/', { replace: true });
      }

      if (resuming) {
        return (
          <div className="min-h-screen bg-ev-navy flex items-center justify-center">
            <p className="text-gray-400 text-sm">Finalizing your account…</p>
          </div>
        );
      }

      return (
        <>
          {step === 'location' && (
            <LocationStep onSuccess={handleLocationSuccess} />
          )}

          {step === 'location-celebration' && locationResult && (
            <LocationCelebrationStep
              result={locationResult}
              onComplete={handleOnboardingComplete}
            />
          )}
        </>
      );
    }
    ```

    Notes on the prop name: LocationCelebrationStep uses `onComplete` (renamed from `onContinue` in plan 02). OnboardingPage must use `onComplete={handleOnboardingComplete}`.

    Notes on the wrapper: the prior version wrapped everything in `<div className="bg-white dark:bg-ev-black min-h-screen">`. The new step components own their own dark-navy background, so OnboardingPage should NOT wrap them in a competing background. Use a fragment.

    Notes on the resumption fallback: if the silent complete-onboarding call fails, set `resuming=false` so the user can interact with LocationStep again. They can re-submit their address (with `force: true` not needed because they're not in update mode) and the celebration step will re-trigger complete-onboarding via the new path.
