**Document structure (from CONTEXT.md decisions — these are locked):**

1. **Table of Contents** — GitHub-compatible anchor links at the top

2. **Quick Reference** — Endpoint table showing the endpoints Essentials will use:
   - GET /api/account/me (Optional auth — returns user profile or 401)
   - GET /api/essentials/candidates/:zip (no auth)
   - GET /api/essentials/politicians (no auth)
   - POST /api/xp/award (service-to-service, X-Service-Key)
   - POST /api/gems/award (service-to-service, X-Service-Key)
   Include base URL, Auth Hub URL, token delivery mechanism.

3. **The Jurisdiction Principle** — "Never ask for an address again" as the opening anchor.
   Frame: Connected users already provided their address once during account setup. Accounts resolved it to legislative districts. Essentials reads jurisdiction from /api/account/me. Asking again is a product violation — it signals the platform doesn't trust its own data.
   Key behavior (from CONTEXT.md): Connected users get jurisdiction pre-populated as default locality; can still explore other areas manually.

4. **Access States** — Define the two UX states clearly:
   - **Inform (anonymous/unauthenticated):** No token, no jurisdiction. User must provide a local address/ZIP input for any location-dependent feature. No persistence of preferences. All public endpoints work without auth.
   - **Connected (authenticated with jurisdiction):** Jurisdiction fields auto-populate locality. No address input needed. XP/gem awards available. Preferences persist.
   - **Connected (no jurisdiction):** User declined location consent. Treat same as Inform for location features — show address input. Do NOT prompt for location consent; that's handled by accounts app.
   Specify the transition: anonymous user performs a persistent action → show "connect your account" prompt → redirect to Auth Hub.

5. **Detection Pattern** — The decision tree using GET /api/account/me:
   - No token in localStorage → Inform (anonymous). Show address input for location features.
   - Token exists → call GET /api/account/me.
     - 401 response → token expired/invalid. Clear token, treat as Inform. This is normal, not an error.
     - 200 with jurisdiction non-null → Connected with jurisdiction. Use jurisdiction fields as default locality.
     - 200 with jurisdiction null → Connected without jurisdiction. Show address input (same as Inform for location).
   Write ONE canonical TypeScript code example showing this full decision tree. Use real field names (jurisdiction.congressional_district, jurisdiction.county, etc.). Include both null and non-null branches. No error handling boilerplate — just the decision logic.

6. **Jurisdiction Fields Reference** — Full interface definition + GEOID format table:
   Use the verified Jurisdiction interface from 33-RESEARCH.md.
   Include a format table:
   | Field | Format | Example Code | Example Name |
   Congressional: 4-char GEOID "1807", "Indiana's 7th Congressional District"
   State senate: 5-char GEOID "18030", "Indiana Senate District 30"
   State house: 5-char GEOID "18097", "Indiana House District 97"
   County: 5-char FIPS "18097", "Marion County"
   School district: 7-char LEAID "1801890", "Metropolitan School District of Pike Township"
   IMPORTANT: Do NOT use "IN-07" format anywhere — that's illustrative from an old doc, not the actual stored value.

7. **Auth Flow** — How Essentials redirects to Auth Hub when an anonymous user wants to connect:
   - Redirect URL: https://accounts.empowered.vote/login?redirect={encodeURIComponent(returnUrl)}
   - Token returned in hash fragment: #access_token=eyJ...
   - Extract token, store in localStorage('ev_token'), clear hash
   - Include the same handleAuthReturn() pattern from COMPASSV2-INTEGRATION.md
   - Domain restriction: only *.empowered.vote redirect targets accepted

8. **Connected Enhancements** — Opt-in framing for XP and gem awards:
   - POST /api/xp/award: document request shape { user_id, source, amount, idempotency_key, metadata? }, response shape, X-Service-Key header
   - POST /api/gems/award: document request shape { user_id, gem_type, amount, idempotency_key }, response shape, X-Service-Key header
   - Frame as OPTIONAL additions on top of the anonymous experience — Essentials works fully without them
   - Note: Essentials needs its own XP source registered and its own gem key provisioned. Include a coordination note (not a blocker — the guide documents the pattern; provisioning is a separate task).
   - Idempotency: stress that idempotency_key is required and should be deterministic (e.g., "essentials:{action}:{user_id}:{identifier}")

9. **Error Handling** — Same error response shape as CompassV2 guide:
   - { code, message } — parse code, not message
   - Key codes: AUTH_ERROR (401), NOT_CONNECTED (403), VALIDATION_ERROR (422), RATE_LIMIT_EXCEEDED (429), INTERNAL_ERROR (500)
   - Anti-pattern: treating 401 on /account/me as an error (it's the normal anonymous state)

10. **Integration Checklist** — Checkboxes mapped to EDOC requirements:
    - EDOC-01: "Never ask address again" principle implemented
    - EDOC-02: Two-state UX pattern (Inform vs Connected)
    - EDOC-03: Auth flow for anonymous→Connected transition
    - EDOC-04: Three-pillar philosophy understood, Inform Pillar emphasis
    - EDOC-05: Jurisdiction field names and formats correct
    - EDOC-06: Connected enhancements documented as opt-in
