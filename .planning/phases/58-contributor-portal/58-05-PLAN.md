  Modify `getContributorPoliticians` in `backend/src/lib/stanceService.ts` to fix two issues:

  **Issue 1: Scoped query uses `home_jurisdiction_geoid` which is NULL everywhere.**

  Change the scoped branch (currently line ~236-269) for `compass_stance_editor` to JOIN through offices and districts instead of filtering on `home_jurisdiction_geoid`:

  Replace:
  ```sql
  WHERE p.is_active = true AND p.home_jurisdiction_geoid = $1
  ```

  With a query that joins through offices -> districts:
  ```sql
  SELECT DISTINCT ON (p.id)
    p.id, p.first_name, p.last_name, p.full_name,
    COALESCE(o.title, '') AS office_title,
    COALESCE(p.photo_custom_url, CASE WHEN p.photo_origin_url LIKE 'http%' THEN p.photo_origin_url END, pi.url, '') AS photo_url,
    p.home_jurisdiction_geoid
  FROM essentials.politicians p
  JOIN essentials.offices o ON o.politician_id = p.id
  JOIN essentials.districts d ON d.id = o.district_id
  LEFT JOIN LATERAL (
    SELECT url FROM essentials.politician_images
    WHERE politician_id = p.id AND type = 'default' LIMIT 1
  ) pi ON true
  WHERE p.is_active = true AND d.geo_id = $1
  ORDER BY p.id
  ```

  KEY CHANGES from the original:
  - `LEFT JOIN essentials.offices` becomes `JOIN essentials.offices` (INNER — politician must have an office)
  - Added `JOIN essentials.districts d ON d.id = o.district_id` (district must exist)
  - Filter is `d.geo_id = $1` instead of `p.home_jurisdiction_geoid = $1`
  - This means: a grant with `jurisdiction_geoid = '0628'` (CA-28 congressional district) will match politicians who hold an office in a district with `geo_id = '0628'`

  The unrestricted branch (NULL jurisdiction_geoid, ~line 204-235) stays unchanged — it already returns ALL active politicians.

  **Issue 2: `essentials_data_editor` grants are silently ignored.**

  - If `grant.jurisdiction_geoid` is non-null: use the same district-join query with `d.geo_id = $1`

  To avoid code duplication, extract the two query strings (unrestricted and scoped) into local `const` variables at the top of the function, then reuse them for both `compass_stance_editor` and `essentials_data_editor` branches.

  **Also update `getMatchingGrant` and `getEditorMatchingGrant`:**

  In `getMatchingGrant` (line ~108-140), the jurisdiction matching logic for `compass_stance_editor` currently checks `grant.jurisdiction_geoid === politicianGeoid` where `politicianGeoid` comes from `getPoliticianJurisdiction` (which reads `home_jurisdiction_geoid`). Since `home_jurisdiction_geoid` is NULL, `getMatchingGrant` currently always hits the "fail-open" branch (console.warn).

  ```sql
  LIMIT 1
  ```

  This fixes grant matching for both single-write routes (PUT /stances/:politicianId/:topicId and PUT /stances/:politicianId/bulk) where `getMatchingGrant` is called.
