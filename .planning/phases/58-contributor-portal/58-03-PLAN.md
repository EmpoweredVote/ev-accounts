**Politician list view (default):**
1. Fetch `GET /api/compass/contributors/politicians` on mount — returns jurisdiction-scoped politicians
2. Show a header with "Compass Editor" title and a jurisdiction scope badge. For Alpha, derive the jurisdiction from the first politician's `home_jurisdiction_geoid` or show "Your Jurisdiction" as fallback
3. Render politician cards in a grid/list — each card shows: full_name (or first_name + last_name), office_title, photo (img with fallback), and an "Edit Stances" button
4. Clicking "Edit Stances" sets the selected politician in state and switches to the stance editor view

**Stance editor view (when politician selected):**
1. Fetch two things in parallel when a politician is selected:
   - `GET /api/compass/topics` — all live topics with stances array
   - `GET /api/compass/politicians/{id}/answers` — existing answers for this politician
2. Show a sub-header: politician name + "back to list" link
3. For each topic, render:
   - Topic title and question_text
   - A stance selector (radio buttons or button group) showing all 5 stances with their text labels
   - Pre-select the existing answer value if one exists (match by topic_id)
   - CRITICAL: Stance values are 1-5 integers from `stance.value`, NOT array indices
4. Track changed stances in local state (a Map or object of topic_id -> new value)
5. "Save All" button at bottom:
   - Calls `PUT /api/compass/stances/{politicianId}/bulk` with body: `{ stances: [{ topic_id, value }] }` for all modified stances
   - Show loading state during save
   - On success: show toast ("Stances saved successfully"), clear dirty state
   - On error: show error toast
6. Toast pattern (copy from DashboardPage):
   ```tsx
   const [showToast, setShowToast] = useState(false);
   const [toastMessage, setToastMessage] = useState('');
   // trigger: setToastMessage('...'); setShowToast(true); setTimeout(() => setShowToast(false), 2500);
   // render: fixed bottom-6 left-1/2 -translate-x-1/2 z-50 bg-gray-900 text-white ...
   ```

**apiFetch for PUT:**

Check `app/src/lib/api.ts` for the exact apiFetch signature — it likely accepts a RequestInit-like options object.

**Error handling:** Wrap each fetch in try/catch. Show a user-friendly error state if the politician list fails to load. If topics/answers fail, show an error message in the editor area.
