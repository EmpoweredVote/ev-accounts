<objective>
Normalize the party string column in essentials.politicians so that "Democrat" and "Democratic" are unified (per SACC-03). Per RESEARCH.md Open Question #1 the canonical form is "Democratic" — it matches the official party name (Democratic Party, not Democrat Party) and aligns with how existing politicians like Alex Padilla and Sherrod Brown are already stored. The DB currently has 496 "Democrat" rows + 280 "Democratic" rows; after this migration, all 776 rows will read "Democratic".

This plan runs in Wave 4 (last) by design — per RESEARCH.md Open Question #2, running normalization after stance corrections (Waves 1-3) ensures all re-research agents work with the pre-normalization party strings as written in the audit report and CSV worksheets. Running it earlier could create transient inconsistencies between research output and DB state.

Purpose: Eliminate the mixed-format party variants so filtering and display queries return consistent results across the platform. This is a pure data-cleanup pass with no FK dependencies and no PostgREST impact (essentials schema is direct-DB only).

Output:
- 1 migration file (number 126) applied to live DB via mcp__supabase-local__execute_sql
- Verification SQL confirming SELECT DISTINCT party returns exactly one Democratic variant
</objective>
