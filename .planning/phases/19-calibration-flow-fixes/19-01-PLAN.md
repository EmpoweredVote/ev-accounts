Rewrite CalibrationOverlay to handle both first-time and resumption flows:

**New prop: `resumeMode` (boolean, default false)**
When `resumeMode` is true:
- Skip "welcome" step entirely
- Skip "pick" step entirely — topics are already selected (from `selectedTopics` in context)
- Start at the answer step with the topic list derived from `selectedTopics` (NOT `pickedTopics` from localStorage)
- `pickedTopics` state initializes from `selectedTopics` when in resume mode

**Topic list with answered/unanswered states:**
- In the answer step, replace the single-topic view with a topic list header showing all picked topics
- Each topic appears as a compact card (similar to pick-step cards but smaller):
  - Answered topics: grayed background (`bg-gray-50`), checkmark icon (green), text in `text-gray-400`, tappable to re-open for re-answering
  - Unanswered topics: white background, no checkmark, text in normal color
  - Current topic: highlighted border (`border-[#59b0c4]`), slightly larger or elevated
- When user taps an answered topic, set `currentIndex` to that topic's index and clear `selectedAnswer` so they can re-answer
- When user taps an unanswered topic, jump to that topic's index
- Auto-start at the first unanswered topic index (find first topic in pickedTopics where answer is null/0)

**Exit gating:**
- The exit (X) button in the header:
  - Hidden entirely when `answeredCount < MIN_TOPICS` (3) — user MUST continue calibrating
  - Visible as "View Compass" text button when `answeredCount >= MIN_TOPICS` — clicking exits calibration and calls `onComplete`
  - When exit is pressed and there are still unanswered topics, remove them from selectedTopics (existing behavior) and complete

**Completion behavior:**
- When the last unanswered topic is answered, immediately call `handleFinish` — no need to press "Next" on the last topic
- `handleFinish` removes unanswered topics from selectedTopics (existing), removes storage key, and transitions to "complete" step
- "complete" step auto-transitions after 3 seconds (existing behavior preserved)

**Topic list rendering (placed above the stance buttons, scrollable horizontally on mobile):**
```jsx
<div className="flex gap-2 px-4 py-2 overflow-x-auto">
  {pickedTopics.map((id, idx) => {
    const topic = topics.find(t => t.id === id);
    const isAnswered = topic && answers[topic.short_title] != null && answers[topic.short_title] > 0;
    const isCurrent = idx === currentIndex;
    return (
      <button key={id} onClick={() => { setCurrentIndex(idx); setSelectedAnswer(null); }}
        className={`shrink-0 px-3 py-1.5 rounded-full text-xs font-medium transition-all ${
          isCurrent ? "border-2 border-[#59b0c4] bg-sky-50" :
          isAnswered ? "bg-gray-100 text-gray-400" : "bg-white border border-gray-200"
        }`}>
        {isAnswered && !isCurrent && <span className="mr-1">&#10003;</span>}
        {topic ? parseTensionTitle(topic).name : "..."}
      </button>
    );
  })}
</div>
```

**First-time flow (resumeMode=false) preserved:**
- Welcome step, pick step, answer step, complete step — all work as before
- The only change: add the topic pill list to the answer step for first-time users too (consistent UX)

**Auto-advance after answering:**
After user selects a stance, auto-advance to the next UNANSWERED topic after a brief delay (300ms). If no unanswered topics remain, trigger `handleFinish`. The "Next/Skip" footer button remains for manual navigation but auto-advance provides a faster flow.

Update `handleNext` to find the next unanswered topic index (not just currentIndex + 1):
```js
const handleNext = () => {
  // Find next unanswered topic
  const nextUnanswered = pickedTopics.findIndex((id, idx) => {
    if (idx <= currentIndex) return false;
    const topic = topics.find(t => t.id === id);
    if (!topic) return false;
    const val = answers[topic.short_title];
    return !(val != null && val > 0);
  });
  if (nextUnanswered !== -1) {
    setCurrentIndex(nextUnanswered);
  } else {
    handleFinish();
  }
};
```

Keep `handleBack` as-is (goes to previous index regardless of answered state) so users can review previous answers.
