  <name>Task 1: Add GET /me/activity endpoint to account.ts</name>
  <files>backend/src/routes/account.ts</files>
  <action>
Insert a new route handler in `backend/src/routes/account.ts` immediately AFTER the existing `GET /me/jurisdiction` handler (which ends at line 315 with the closing `});`) and BEFORE the `// PATCH /api/account/me` divider comment block (starting around line 317).

Endpoint contract:
- Method/path: `GET /me/activity` (full path becomes `/api/account/me/activity` when mounted)
- Middleware chain: `requireAuth, requireConnected` — same pattern used by GET /me/jurisdiction. Inform-tier callers MUST receive 403 from `requireConnected` before any DB work runs. Do NOT add `requireVerified` (read endpoint, parity with /me/jurisdiction).
- Body: none (GET). Query string: none for this iteration (LIMIT is hard-coded to 20 per the requirements).
- Response 200 shape:
  ```json
  {
    "activity": [
      { "source": "compass_calibration", "amount": 50, "description": "compass_calibration", "created_at": "2026-04-20T...Z" }
    ]
  }
  ```
  Empty list (`{ "activity": [] }`) when the user has no XP history — never 404.

Implementation requirements:
1. Use `pool.query()` from `../lib/db.js` — `connect` schema is NOT exposed via PostgREST (see PROJECT memory: pool.query for non-public schema reads/writes). Do NOT use `createUserClient(...).schema('connect')`.
2. SQL:
   ```sql
   SELECT source, amount, created_at
   FROM connect.xp_transactions
   WHERE user_id = $1
   ORDER BY created_at DESC
   LIMIT 20
   ```
   Parameterize `authReq.userId` as `$1`. No interpolation.
3. Type the rows generically: `pool.query<{ source: string; amount: number; created_at: string }>(...)`.
4. Map rows to response objects with `description: row.source` (the `xp_transactions` table has no `description` column — research confirmed; mapping `source` into both fields keeps the API contract from leaking schema details and lets the frontend render `description` without conditional logic).
5. Wrap in `try/catch`. On unexpected error: `res.status(500).json({ code: 'INTERNAL_ERROR', message: 'An unexpected error occurred' })` and `console.error('[GET /api/account/me/activity] Unexpected error:', err)` — match the style used by /me/jurisdiction.
6. Add a JSDoc-style comment block above the route mirroring the format used for /me/jurisdiction:
   ```
   // ---------------------------------------------------------------------------
   // GET /api/account/me/activity
   // Returns the last 20 XP transactions for the authenticated Connected user.
   // Reads connect.xp_transactions directly via pool.query (PostgREST does not
   // expose the connect schema). Inform-tier callers receive 403 from
   // requireConnected before any DB work runs.
   // ---------------------------------------------------------------------------
   ```
7. Do NOT add an explicit empty-array check or `404` — an empty result set is a normal state.
8. Do NOT introduce new imports — `pool`, `requireAuth`, `requireConnected`, and `AuthenticatedRequest` are already imported at the top of the file (verified lines 3–7).

Avoid:
- Do NOT use `db.from('xp_transactions')` or `supabaseAdmin` — both will fail at runtime (PostgREST schema scope, plus the architecture rule banning service-role reads in route handlers).
- Do NOT add a `description` column to the SQL (it does not exist; query will throw).
- Do NOT change the LIMIT — the frontend slices to 4 client-side; 20 is the documented cap.
