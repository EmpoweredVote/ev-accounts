## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Retry" |
| Loading state heading | "Loading budget data..." |
| Error state heading | "Budget data unavailable" |
| Error state body | "The budget API could not be reached. Check your connection and try again." |
| Destructive confirmation | none — no destructive actions in this phase |

**Rationale:**
- "Budget data unavailable" is more specific than the current "Unable to load data" — it tells the user what is missing, not just that something failed.
- "Retry" is the minimum-friction recovery label. No confirmation needed (non-destructive reload action).
- The body copy gives both a diagnosis (API unreachable) and the next step (check connection + retry). This replaces the current "Please check the console for errors" which is developer-facing copy surfaced to end users.

**Source:** CONTEXT.md D-07 — "When API is unavailable, show an error message with a retry button. No empty dashboard shell." RESEARCH.md Pattern 4 / error state code example.

## Component Spec: Error State

The only new UI element in this phase is the upgraded error state in `App.tsx`. Spec:

```
Layout:   centered column, padding 64px top/bottom, 32px left/right
Heading:  "Budget data unavailable" — 20px / weight 700 / color #1c1c1c
Body:     "The budget API could not be reached. Check your connection and try again."
          16px / weight 400 / color #6b7280 (--text-gray) / margin-top 8px
Button:   "Retry" — onClick: () => window.location.reload()
          background #00657c / color #ffffff / padding 12px 24px
          border-radius 8px / font Manrope 14px weight 600
          margin-top 16px
          hover: background #005467 (10% darker)
          focus: 2px solid outline at 2px offset, color #00657c
```

No new component file required. Inline JSX in `App.tsx` error state block is sufficient given the one-off nature. This matches the pattern of the existing loading state (also inline in `App.tsx`).

**Accessibility:** Button must have visible focus ring. `window.location.reload()` is the correct retry mechanism (re-triggers all data loading effects). No ARIA labels required beyond the semantic `<button>` element.
