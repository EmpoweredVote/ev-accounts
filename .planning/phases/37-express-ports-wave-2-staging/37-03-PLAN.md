  <name>Task 1: Stance service functions (CRUD + review + lock + auto-promote)</name>
  <files>backend/src/lib/stagingService.ts</files>
  <action>
Append to `backend/src/lib/stagingService.ts` — add all stance-related types, mapper, and service functions.

**TypeScript interfaces:**

`StagingStance` — camelCase:
- id, contextKey, politicianExternalId, politicianName, topicKey, topicId (string | null)
- value (number), reasoning (string | null), sources (string[])
- status, addedBy, reviewedBy (string[]), lastReviewedAt
- reviewCount (number), lockedBy, lockedAt
- approvedToAnswerId (string | null), approvedAt
- createdAt, updatedAt

`StanceReviewLog` — id, stanceId, reviewerName, action, previousValue (number | null), newValue (number | null), comment, createdAt

**Row mapper `mapStanceRow(row: any): StagingStance`:**
- Explicit field whitelist, Number() cast on: value, review_count
- sources is a Postgres ARRAY — pg driver returns as JS array already

**Service functions (all exported):**

1. `getStances(filters?: { status?: string }): Promise<StagingStance[]>`
   - SELECT with optional status filter, ORDER BY created_at DESC
   - Map through mapStanceRow

2. `getStanceById(id: string): Promise<StagingStance | null>`
   - SELECT WHERE id = $1, return null or mapped row

3. `createStance(data: CreateStanceInput, userId: string): Promise<StagingStance>`
   - CreateStanceInput: contextKey (required), politicianExternalId, politicianName (required), topicKey (required), topicId, value (required), reasoning, sources
   - Server-derives: added_by = await getDisplayName(userId), status = 'pending'
   - INSERT RETURNING *, map result

4. `updateStance(id: string, data: Partial<CreateStanceInput>): Promise<StagingStance>`
   - Fetch, assertPending, dynamic SET, UPDATE RETURNING *

5. `reviewStance(id: string, action: 'approve' | 'reject', userId: string, comment?: string, newValue?: number): Promise<StagingStance>`
   - Fetch record. assertPending(record.status).
   - reviewerName = await getDisplayName(userId)
   - If action === 'approve':
     - **Require topic_id non-null.** If `record.topicId` is null, throw error with httpStatus 422 and message "Cannot approve stance: topic_id is required for promotion to politician_answers"
     - **Resolve politician_id:** Query `SELECT id FROM essentials.politicians WHERE external_id = $1` using Number(record.politicianExternalId). If no match or external_id is non-numeric, throw 422 "Cannot approve stance: politician not found in essentials (external_id: ${record.politicianExternalId})"
     - **Auto-promote:** UPSERT into `inform.politician_answers`:
       ```sql
       INSERT INTO inform.politician_answers (politician_id, topic_id, value)
       VALUES ($1, $2, $3)
       ON CONFLICT (politician_id, topic_id) DO UPDATE SET value = EXCLUDED.value
       ```
     - UPDATE staging.stances SET status = 'approved', approved_at = NOW(), review_count + 1, etc.
     - Store the approved_to_answer_id if useful (can be politician_id::text for reference)
   - If action === 'reject':
     - UPDATE status = 'rejected', review_count + 1, etc.
   - INSERT stance review log. Include previous_value and new_value if newValue was provided (reviewer corrected the value during review).
   - **If newValue provided:** Also update `staging.stances.value = newValue` before promotion. The review log captures old and new values.
   - Return mapped result.

6. `lockStance(id: string, userId: string): Promise<{ locked: boolean; lockedBy?: string; lockedAt?: string }>`
   - Same atomic pattern as lockPolitician

7. `unlockStance(id: string): Promise<void>`
   - Same pattern as unlockPolitician
