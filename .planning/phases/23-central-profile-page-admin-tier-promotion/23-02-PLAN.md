  <action>
Read the existing AccountDetailPage.tsx and extend it significantly. The existing page already has: profile header (tier badge, level, XP, gems), admin-only fields, roles, invite chain, calibration status, XP history, and actions.

**New data to fetch:**

Add new state and fetch calls:

1. **Compass data** — fetch from the new profile endpoint `GET /api/account/profile/:userId` (which is PUBLIC and returns tier-conditional data including `compass_answers` and `selected_topic_ids` for Empowered users, and `selected_topic_ids` for Connected). This supplements the existing admin detail data with compass info.
   - Add state: `profileData` with shape `{ username, tier, level, total_xp, selected_topic_ids?, compass_answers?, empowered_profile? }`.
   - Fetch in `useEffect` alongside the existing `fetchAccount` call.

2. **Promotion history** — fetch `GET /api/admin/accounts/:userId/promotion-history?page=1`.
   - Add state: `promotionData` with shape `{ entries: PromotionEntry[]; total: number; page: number; pages: number }`.
   - Add `promotionPage` state for pagination.
   - Interface `PromotionEntry`: `{ id, admin_id, admin_email, target_user_id, previous_tier, new_tier, note, created_at }`.

**New sections to add (in order, after existing sections):**

1. **Compass Section** (Connected + Empowered only — show when `profileData?.selected_topic_ids` exists):
   - Card with header "Compass".
   - Show "Selected Topics" count: e.g., "3 selected topics".
   - If `profileData.compass_answers` exists (Empowered only): show a table of answers with columns: Topic ID (truncated UUID), Value, Write-in Text (if present). Simple table, no styling complexity needed.
   - If Connected (no compass_answers): show "Compass answers are private for Connected-tier users."

2. **Empowered Profile Section** (Empowered only — show when `profileData?.empowered_profile` exists):
   - Card with header "Empowered Profile".
   - Display fields: legal_name, candidate_page_slug (as a link to `/candidates/:slug`), is_active (badge), empowered_at (formatted date), demoted_at (if present, formatted date).

3. **Promotion History Section** (always show):
   - Card with header "Promotion History".
   - Table with columns: Date, Admin, Previous Tier, New Tier, Note.
   - Date = formatted `created_at`. Admin = `admin_email`. Note = show text or dash if null.
   - Pagination: same Previous/Next pattern as XP History.
   - Empty state: "No promotions recorded."

**Promotion flow (Inform tier only):**

Add to the Actions section (alongside existing suspend/demote buttons):

1. Show "Promote to Connected" button ONLY when `account.tier === 'inform'`. Use conditional rendering (`{account.tier === 'inform' && ...}`). Do NOT render a disabled button for other tiers — the button must be completely absent.

2. Clicking the button sets `showPromoteModal = true`.

3. **Promotion Modal** — render when `showPromoteModal` is true:
   - Fixed overlay (backdrop: `fixed inset-0 bg-black/50 z-50 flex items-center justify-center`).
   - Modal card (`bg-white rounded-lg shadow-xl p-6 max-w-md w-full mx-4`).
   - Header: "Promote to Connected".
   - Body text: "Promote **{account.display_name}** from Inform to Connected tier?"
   - Optional note textarea: `<textarea>` with placeholder "Add a note (optional)", max 500 chars, linked to `promoteNote` state.
   - Footer: "Cancel" button (closes modal, clears note) and "Promote to Connected" button (ev-teal background, white text).
   - Loading state: disable both buttons while `promotionLoading` is true, show spinner text on CTA.

4. **Promote handler** (`handlePromote`):
   - Set `promotionLoading = true`.
   - Call `apiFetch('/admin/accounts/${userId}/promote', { method: 'POST', body: JSON.stringify({ note: promoteNote || undefined }) })`.
   - On success: close modal, clear note, set `promotionSuccess` message ("John Smith promoted to Connected"), call `fetchAccount()` to refresh (tier will change, promote button disappears).
   - On error: if 409, show "User is already Connected or Empowered" in `actionError`. If 404, show "User not found". Otherwise generic error.
   - Set `promotionLoading = false`.

5. **Success toast** — simple inline notification:
   - After successful promotion, set `promotionSuccess` string state.
   - Render a green banner at top of page: `bg-green-50 border border-green-200 rounded p-3 text-green-700 text-sm`.
   - Auto-clear after 5 seconds via `setTimeout`.

**Styling notes:**
- Use existing Tailwind patterns from the page (bg-white rounded-lg shadow p-6 mb-4).
- Tier badge colors already defined in TIER_BADGE constant.
- Brand colors: ev-teal for Connected actions (promote CTA), ev-red for destructive actions.
- Use `bg-ev-teal hover:bg-ev-teal/90` for the Promote CTA button in the modal.
