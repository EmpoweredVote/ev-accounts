**Part A: Create `backend/src/routes/candidates.ts`**

Follow the compass.ts route pattern exactly. File header comment explaining architecture rules (no supabaseAdmin in routes, all DB access through candidateService.ts).

Two endpoints in this router:

1. **`GET /:slug`** — Public candidate profile
   - Middleware: `optionalAuth` (unauthenticated access)
   - Validate slug: must be non-empty string (Express params guarantee non-empty if route matches)
   - Call `getCandidateBySlug(slug)` from candidateService
   - If null: return `res.status(404).json({ code: 'NOT_FOUND', message: 'Candidate not found' })`
   - If found: return `res.status(200).json(candidate)`
   - Error handler: catch, log `[GET /candidates/:slug] error:`, return 500 INTERNAL_ERROR

2. **`GET /:slug/answers`** — Candidate answers for specific topics (viewer comparison)
   - Middleware: `optionalAuth`
   - Required query param: `topics` — comma-separated topic UUIDs (e.g., `?topics=uuid1,uuid2,uuid3`)
   - Optional query param: `inverted` — comma-separated topic UUIDs for inversion (e.g., `?inverted=uuid1,uuid2`)
   - Validation with Zod:
     ```typescript
     const topicsParam = typeof req.query.topics === 'string' ? req.query.topics : '';
     const topicIds = topicsParam.split(',').map(s => s.trim()).filter(Boolean);
     ```
   - If topicIds is empty: return `res.status(422).json({ code: 'VALIDATION_ERROR', message: 'topics query parameter is required' })`
   - Validate each topicId is UUID format (use regex `/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i`)
   - Parse inverted param:
     ```typescript
     const invertedParam = typeof req.query.inverted === 'string' ? req.query.inverted : '';
     const invertedSet = new Set(invertedParam.split(',').map(s => s.trim()).filter(Boolean));
     ```
   - Call `getCandidateAnswers(slug, topicIds, invertedSet)` from candidateService
   - If null (slug not found): return 404 NOT_FOUND
   - If found: return `res.status(200).json(answers)` — this is an array of `{ topic_id, value, write_in_text? }`
   - Error handler: catch, log, return 500

**CRITICAL: Do NOT import or reference supabaseAdmin in this file.** The architecture test will fail. All DB access goes through candidateService.ts imports.

Route ordering: `/:slug/answers` MUST be declared BEFORE `/:slug` to prevent Express from matching `answers` as a slug parameter. This follows the compass.ts pattern where `/politicians/:id/answers` is before any catch-all.

Wait — actually Express matches routes in declaration order and `:slug/answers` vs `:slug` works correctly because `/answers` is a literal path segment AFTER the param. Express will match `/:slug/answers` only when there are exactly two segments. The simpler `/:slug` only matches single-segment paths. So declaration order does not matter here. However, for clarity and consistency with the codebase, declare the more specific route (`/:slug/answers`) first.

Export default router.

**Part B: Create `backend/src/routes/essentialsCandidates.ts`**

Separate router file for the Essentials ZIP lookup. This is mounted at a different prefix (`/api/essentials/candidates`) so it needs its own router.

One endpoint:

1. **`GET /:zip`** — ZIP-based candidate lookup for Essentials frontend
   - Middleware: `optionalAuth`
   - Validate ZIP format: regex `/^\d{5}(-\d{4})?$/` — allows 5-digit and ZIP+4
   - If invalid: return `res.status(422).json({ code: 'VALIDATION_ERROR', message: 'Invalid ZIP code format' })`
   - Normalize: extract first 5 digits (`zip.slice(0, 5)`) for consistency (strip ZIP+4 suffix)
   - Call `getCandidatesByZip(normalizedZip)` from candidateService
   - Return `res.status(200).json(candidates)` — empty array `[]` for valid ZIP with no candidates (NOT 404)
   - Error handler: catch, log `[GET /essentials/candidates/:zip] error:`, return 500 INTERNAL_ERROR

**CRITICAL: Do NOT import supabaseAdmin in this file either.**

Export default router.
