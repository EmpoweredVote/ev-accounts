**Functions to implement:**

1. `splitLegalName(legalName: string): { first_name: string; last_name: string }` — Split on first space. Everything before first space = first_name, everything after = last_name. Single-word name: first_name = name, last_name = ''. Trim input before splitting.

2. `getCandidateBySlug(slug: string): Promise<CandidateProfile | null>` —
   - Cache key: `candidate:slug:${slug}`, TTL 900s
   - Check cache first, return if hit
   - Query `empower.empowered_profiles` via `supabaseAdmin` with explicit column list (NEVER `*`):
     `user_id, legal_name, candidate_page_slug, is_active, empowered_at, demoted_at, representing_city, representing_state, representing_zip, district_type, district_id, government_name, chamber_name, chamber_name_formal, photo_origin_url`
   - Filter: `.eq('candidate_page_slug', slug).maybeSingle()`
   - No `is_active` filter — this endpoint returns ALL candidates (active and inactive)
   - Filter: `.is('deleted_at', null)` — soft-deleted accounts are excluded
   - If no row found, return null (route will 404)
   - Get `selected_topic_ids` from `connect.connected_profiles` via supabaseAdmin: `.select('selected_topic_ids').eq('user_id', data.user_id).maybeSingle()`
   - If selected_topic_ids exist and are non-empty, fetch compass answers: query `inform.compass_responses` via supabaseAdmin for `topic_id, value, write_in_text` WHERE `user_id = data.user_id AND topic_id IN (selected_topic_ids) AND visibility = 'public'`
   - Build response using EXPLICIT WHITELIST (never spread):
     - `splitLegalName(data.legal_name)` for first/last
     - `active: data.is_active`
     - `demoted_at: data.demoted_at ?? null`
     - `empowered_at: data.empowered_at`
     - All jurisdiction fields explicitly
     - `images: data.photo_origin_url ? [{ type: 'default', url: data.photo_origin_url }] : []`
     - `featured_stances`: the compass answers array (empty if no selected topics or no public answers)
   - CRITICAL: `tolerance_rating` must NEVER appear anywhere in this object. Do not query it, do not include it.
   - Cache result and return

3. `getCandidateAnswers(slug: string, topicIds: string[], invertedTopicIds: Set<string>): Promise<CandidateAnswer[] | null>` —
   - NO caching (answers depend on caller's inverted param, making cache keys complex)
   - Look up `user_id` from `empower.empowered_profiles` by slug (maybeSingle, deleted_at IS NULL)
   - If not found, return null
   - Query `inform.compass_responses` for `topic_id, value, write_in_text` WHERE `user_id = X AND topic_id IN (topicIds) AND visibility = 'public'`
   - Apply inversion: for each answer, if `invertedTopicIds.has(answer.topic_id)`, set `value = 6 - value` (1<>5, 2<>4, 3=3)
   - Return array of `{ topic_id, value, write_in_text? }` — include write_in_text only when present (not null/undefined)

4. `getCandidatesByZip(zip: string): Promise<EssentialsCandidate[]>` —
   - Cache key: `candidates:zip:${zip}`, TTL 900s
   - Check cache first, return if hit
   - Query `empower.empowered_profiles` via supabaseAdmin with explicit columns:
     `user_id, legal_name, candidate_page_slug, representing_city, representing_state, representing_zip, district_type, government_name, chamber_name, photo_origin_url`
   - Filter: `.eq('representing_zip', zip).eq('is_active', true).is('deleted_at', null)`
   - CRITICAL: `is_active = true` filter — Essentials NEVER returns inactive candidates
   - Map results through explicit whitelist serializer:
     - `splitLegalName(row.legal_name)` for first/last
     - All jurisdiction fields
     - `images: row.photo_origin_url ? [{ type: 'default', url: row.photo_origin_url }] : []`
   - Cache and return
