**Section 3: Pre-Cutover - Staging Verification Checklist**
Checklist with specific test steps:
- [ ] CompassV2: Navigate to app → redirects to Auth Hub for login → login → returns to CompassV2 with token → calibration flow works → compare flow works → admin routes work (if admin user)
- [ ] Essentials: Navigate to app → Sign In link visible → click → redirects to Auth Hub → login → returns to Essentials with token → auth-protected features work
- [ ] Read & Rank: Navigate to app → sign-in link points to Auth Hub → login → returns with token → verdict syncing works
- [ ] Treasury Tracker: Navigate to app → no console errors → static data loads → no requests to Go server URL
- [ ] Auth Hub: Visit /login?redirect=https://some-app.netlify.app → login → banner shows → after login redirects to that URL with #access_token=
- [ ] Verify no `api.empowered.vote` requests in browser network tab for any app

**Section 4: Production Cutover Steps (Ordered)**
1. Update `CORS_ORIGIN` on Render to include production domains → redeploy ev-accounts
2. Update Netlify dashboard env vars for all 4 apps: `VITE_API_URL=https://accounts.empowered.vote`
3. Merge PRs for all 4 repos → Netlify auto-deploys
4. Verify each app loads and login flow works
5. Post user communication

**Section 5: Rollback Plan**
- Revert `VITE_API_URL` in Netlify dashboard for each app back to Go server URL
- Revert `netlify.toml` proxy targets (revert PR)
- `CORS_ORIGIN` change on Render is harmless — no need to revert
- Old cookie sessions on Go server remain valid for TTL
- No database changes to roll back
- Estimated rollback time: 5 minutes per app

**Section 6: Known Behavior Changes**
- CompassV2 Register.jsx guest-answer migration: dropped. Alpha users who had local quiz answers before registering lose them on re-registration. LOW impact — alpha user base is small.
- Forced re-login: all users must log in again after cutover. Brief banner on Auth Hub login page explains this.
- CompassV2 `data.username` → `data.display_name`: display name source changes from Go server field to ev-accounts field. Should be identical for existing users.

**Section 7: User Communication**
- Timing: just before cutover window
- Channel: user Discord/Slack
- Template message: "We've updated our login system. If you see a login screen, just log in again — your data is safe."

**Section 8: Monitoring (1-3 day window)**
- Monitor Render logs for ev-accounts API errors (especially 401s and CORS errors)
- Monitor Netlify deploy logs for all 4 apps
- Check browser console for CORS errors, 401 loops, undefined display names
- Watch for user reports of login failures
- Go server traffic should drop to zero (verify via Go server's Render logs)
