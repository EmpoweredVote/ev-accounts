<objective>
Add redirect-after-login support and a "please log in again" banner to the Auth Hub login and signup pages.

Purpose: Frontend apps (CompassV2, Essentials, Read & Rank) will redirect unauthenticated users to `https://accounts.empowered.vote/login?redirect={returnUrl}`. After login, the Auth Hub must redirect back to that URL with the access token in the hash fragment so the calling app can extract it. This is the critical plumbing that makes the entire Phase 40 auth migration work.

Modify LoginPage.tsx to:

1. On mount, read `redirect` query param from URL: `new URLSearchParams(window.location.search).get('redirect')`

2. After successful login (after `setAuth(access_token, user)`), check if `redirect` param exists:
   - If YES: redirect to `{redirectUrl}#access_token={access_token}` via `window.location.href = ...`
   - If NO: `navigate('/')` as before (existing Auth Hub dashboard behavior)

3. Add a brief "re-auth" banner that shows ONLY when `?redirect=` param is present. Place it above the form inside the card div. Use this JSX:
   ```tsx
   {redirectUrl && (
     <div className="p-3 bg-ev-teal/10 border border-ev-teal/30 rounded-lg text-sm text-gray-300 text-center">
       We've made some improvements. Please log in again to continue.
     </div>
   )}
   ```

4. Store the redirect URL in a `const` or state variable parsed from search params on mount — do NOT re-parse on every render.

5. Security: validate the redirect URL starts with `https://` before redirecting. If it doesn't match, fall back to `navigate('/')`. This prevents open redirect attacks.

IMPORTANT: The token is passed via hash fragment (`#access_token=`), NOT as a query parameter. This matches the established pattern in `app/src/App.tsx` lines 27-37 which already extracts tokens from hash fragments.
