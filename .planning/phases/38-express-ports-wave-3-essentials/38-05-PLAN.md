**Add to essentialsService.ts — three entity lookup functions:**

1. **`getGovernmentById(id: string): Promise<GovernmentDetail | null>`**
   - Query essentials.governments WHERE id = $1
   - JOIN with essentials.chambers to include chambers in this government
   - JOIN with essentials.building_photos for government building photo (if table exists — check 38-01-SUMMARY)
   - Return: id, name, state, city, type, level, url, building_photo (null if none), chambers (array)
   - Return null if not found

2. **`getChamberById(id: string): Promise<ChamberDetail | null>`**
   - Query essentials.chambers WHERE id = $1
   - JOIN with essentials.governments for parent government info
   - JOIN with essentials.districts to include districts in this chamber
   - Return: id, name, formal_name, type, government (nested), districts (array)
   - Return null if not found

3. **`getDistrictById(id: string): Promise<DistrictDetail | null>`**
   - Query essentials.districts WHERE id = $1
   - JOIN with essentials.chambers and essentials.governments for parent info
   - JOIN with essentials.offices and essentials.politicians for current officeholder(s)
   - Return: id, name, type, geoid, mtfcc, chamber (nested), government (nested), politicians (array of current officeholders)
   - Return null if not found

All functions: pool.query(), explicit field whitelists, null strings -> "" (Go convention).

Add TypeScript interfaces: GovernmentDetail, ChamberDetail, DistrictDetail.

**Add to essentials.ts router — three entity routes:**

Add these routes to the essentials.ts router created in Plan 02. These are mounted at `/api/essentials` so the paths are:

```
GET /governments/:id    -> getGovernmentById
GET /chambers/:id       -> getChamberById
GET /districts/:id      -> getDistrictById
```

Each route:
- Apply `optionalAuth` middleware
- Extract `id` from `req.params.id as string`
- Call service function
- If null, return 404 `{ code: 'NOT_FOUND', message: '{Entity} not found' }`
- data_level: userId ? 'connected' : 'inform'
- Return 200 with `{ ...entity, data_level }`
- Error handling: 500 for unexpected errors

ROUTE ORDERING in essentials.ts: Entity routes with /:id params are fine here because they're under different path prefixes (/governments/, /chambers/, /districts/). No conflict with /address-search.
