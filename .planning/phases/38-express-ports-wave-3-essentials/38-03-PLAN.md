Add a new exported function `getPoliticianById(id: string): Promise<PoliticianDetail | null>`.

This function assembles a full politician profile by querying multiple essentials tables. Since the Go server's /:id route is broken, derive the response shape from the schema + the flat list shape established in Plan 02.

**Base politician query:**
Query essentials.politicians by id. JOIN with offices, districts, chambers, governments (same joins as getPoliticiansFlatList but for a single record). If no row found, return null.

**Nested data queries** (run in parallel with Promise.all for performance):

1. **Contact info**: Query `essentials.politician_contacts` WHERE politician_id = $1. Return as array. Fields: type, value, notes, etc.

2. **URLs/websites**: If not already on the politician row, query `essentials.politician_urls` or similar table (check 38-01-SUMMARY for table names). Return as string array.

3. **Images/photos**: Query `essentials.politician_images` or similar WHERE politician_id = $1. Return as array with url, caption, etc.

4. **Office history**: Query `essentials.offices` WHERE politician_id = $1 (may already have from base query). Include term dates if available.

5. **Education/degrees**: Query `essentials.politician_degrees` or similar WHERE politician_id = $1 if table exists.

6. **Experience**: Query `essentials.politician_experiences` or similar WHERE politician_id = $1 if table exists.

For any nested table that doesn't exist (check 38-01-SUMMARY column inventory from Phase 34), skip that query. Return empty array [] for missing nested data, not null.

**Response shape** (PoliticianDetail interface):
Extends PoliticianFlatRecord (from Plan 02) with additional nested objects:
```typescript
interface PoliticianDetail extends PoliticianFlatRecord {
  contacts: Array<{ type: string; value: string; notes: string | null }>;
  images: Array<{ url: string; caption: string | null }>;
  degrees: Array<{ degree: string; institution: string; year: number | null }>;
  experiences: Array<{ title: string; organization: string; start_year: number | null; end_year: number | null }>;
  // Additional nested data based on what tables exist in the schema
}
```

Adjust the interface based on actual table structure from 38-01-SUMMARY. Use explicit field whitelists — never spread DB rows.

All string fields null in DB -> empty string "" in response (Go convention).

Use `pool.query()` only — never PostgREST for essentials schema.
