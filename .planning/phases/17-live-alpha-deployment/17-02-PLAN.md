Create `backend/scripts/smokeTest.ts`. This is a standalone Node.js script (not an Express route or test file — no Vitest imports).

**Base URL:** Read from `process.env.SMOKE_TEST_URL`. Default to `http://localhost:3000` if not set. Trim any trailing slash. Print the resolved base URL at the top of output: `Smoke testing: <url>`.

**Checks (run sequentially, not in parallel — order matters for diagnostics):**

Define each check as an object with `{ name: string, run: () => Promise<CheckResult> }` where `CheckResult = { pass: boolean; detail: string }`.

Check 1 — Health:
- `GET <base>/api/health`
- Pass: status 200 AND response body contains `"status":"ok"` (or `status: 'ok'` after JSON parse)
- Fail detail: `Expected 200 with {status:'ok'}, got <status>`

Check 2 — Auth reachability:
- `POST <base>/api/auth/login` with body `{ email: "smoke-test@invalid.example", password: "not-a-real-password" }`, Content-Type: application/json
- Pass: status 401 (Supabase auth is reachable — it correctly rejected bad credentials)
- Fail detail: `Expected 401 (auth reachable), got <status>`. Note: 500 means auth is unreachable. 200 would be catastrophic.
- Do NOT use 200 as a passing condition. 401 is the only pass.

Check 3 — Compass topics:
- `GET <base>/api/compass/topics`
- Pass: status 200 AND response body parses as JSON array (Array.isArray)
- Fail detail: `Expected 200 with JSON array, got <status>` or `Expected array, got <type>`

Check 4 — Essentials politicians (is_candidate column verification):
- `GET <base>/api/essentials/politicians`
- Pass: status 200 AND response body parses as JSON array
- This check proves migration 026 applied successfully (the endpoint queries `is_candidate`). Note this in a comment in the code.
- Fail detail: `Expected 200 with JSON array, got <status>` or `Expected array, got <type>`

Check 5 — Admin UI (skipped in programmatic check, human-only):
- Add a hardcoded "SKIP (human verify)" entry in the results array for the admin UI check. Mark as pass: true, detail: "Verify manually: admin UI loads at <admin-ui-url> with no JS errors".
- This keeps the check visible in output without failing the automated run.

**Output format (print for each check):**
```
[PASS] Health: GET /api/health → 200 {status:'ok'}
[PASS] Auth reachability: POST /api/auth/login → 401 (Supabase auth reachable)
[PASS] Compass topics: GET /api/compass/topics → 200 array(12)
[PASS] Essentials politicians: GET /api/essentials/politicians → 200 array(5)
[SKIP] Admin UI: Verify manually: admin UI loads at <admin-ui-url> with no JS errors
```

Use `[PASS]`, `[FAIL]`, `[SKIP]` prefixes. For arrays, print `array(<count>)` not the full body.

**Exit behavior:**
- After all checks, print summary: `Results: 4/4 passed (1 skipped)`
- If any check FAILED: print `SMOKE TEST FAILED` and `process.exit(1)`
- If all non-skip checks passed: print `SMOKE TEST PASSED` and `process.exit(0)`

**Error handling:**
- Wrap each check's `run()` in try/catch. A network error (ECONNREFUSED, timeout) counts as fail with detail: `Network error: <message>`. Do not crash the script.
- Set fetch timeout: 10 seconds per request (use AbortController with setTimeout).

**TypeScript:** strict mode, no `any`. Use built-in `fetch` (Node 18+ includes it). Do NOT import node-fetch or axios. Add `// @ts-ignore` only if absolutely necessary (prefer proper types).

Script is run with: `SMOKE_TEST_URL=https://<domain> npx tsx backend/scripts/smokeTest.ts`
