<task type="checkpoint:human-action" gate="blocking">
  <name>Task 2: Configure Google Cloud Monitoring alert for Maps API request volume</name>
  <action>
Set up a Google Cloud Monitoring alerting policy per the user's locked decisions:

**Pre-step: Identify the correct GCP project**

1. Open Google Cloud Console (console.cloud.google.com)
2. Navigate to APIs & Services -> Credentials
3. Find the API key used for Google Maps (`***REMOVED-SECRET***` per .env.local)
4. Note which project owns this key — all subsequent steps must be in THIS project

**Option A: Cloud Monitoring Alerting Policy (recommended)**

1. Navigate to Monitoring -> Alerting -> Create Policy
2. Click "Select a metric"
3. Resource type: `Consumed API`
4. Metric: `serviceruntime.googleapis.com/api/request_count`
5. Add filter: `service = maps-backend.googleapis.com` (or leave unfiltered to capture all Google Maps API calls — Places API, Geocoding API, Maps JavaScript API combined)
6. Aggregator: SUM
7. Alignment period: choose the longest available (this determines the rolling window)
8. Set condition: Threshold type "above", value = 5000
9. Notification channel: Add Email -> enter the default GCP project account email
10. Policy name: "Google Maps API - 5000 requests/month alert"
11. Click Save / Create Policy

**Option B: Simpler Quotas Alert (if Option A is too complex)**

1. Navigate to APIs & Services -> Enabled APIs
2. Click on "Places API" (or "Maps JavaScript API")
3. Go to Quotas & System Limits
4. Find the "Requests" quota
5. Three-dot menu -> "Create usage alert"
6. Set threshold percentage that corresponds to roughly 5,000 requests relative to the quota
7. Set notification email

**CRITICAL locked decisions from user:**
- Monitor request VOLUME, not dollar spend
- Threshold: 5,000 calls/month (halfway to 10,000 free tier)
- Email only — no SMS, no PagerDuty, no Slack
- NO daily request quota cap — the API must remain fully open
- This is INFORMATIONAL monitoring only — no automated responses or shutoffs
