  <name>Task 1: Install cookie-parser, add COOKIE_DOMAIN env var, update CORS config</name>
  <files>backend/package.json, backend/src/lib/env.ts, backend/src/index.ts</files>
  <action>
    1. Install cookie-parser and its types:
       ```
       cd backend && npm install cookie-parser && npm install --save-dev @types/cookie-parser
       ```

    2. Add `COOKIE_DOMAIN` to `backend/src/lib/env.ts` envSchema:
       ```typescript
       COOKIE_DOMAIN: z.string().optional().default(''),
       ```
       Place it after the `CORS_ORIGIN` line. Empty string = host-only cookie (correct for local dev). Production value will be `.empowered.vote`.

    3. In `backend/src/index.ts`, add cookie-parser middleware:
       - Import: `import cookieParser from 'cookie-parser';`
       - Register BEFORE `express.json()` and BEFORE routes:
         ```typescript
         app.use(cookieParser());
         ```
         Place it right after `app.use(helmet());` and before the `cors()` call.

    4. Replace the existing `cors()` config in `backend/src/index.ts` with a credentials-aware version:
       ```typescript
       const allowedOrigins = env.CORS_ORIGIN
         ? env.CORS_ORIGIN.split(',').map((o) => o.trim())
         : [];

       app.use(
         cors({
           origin: (origin, callback) => {
             // Allow same-origin / server-to-server (no Origin header)
             if (!origin) return callback(null, true);
             // Dev: allow any origin (Vite proxy + cross-origin testing)
             if (env.NODE_ENV === 'development') return callback(null, true);
             // Prod: exact-match against CORS_ORIGIN list
             if (allowedOrigins.includes(origin)) return callback(null, true);
             callback(new Error(`CORS: origin ${origin} not allowed`));
           },
           credentials: true,
         })
       );
       ```
       WHY: `credentials: true` is required for browsers to send/receive cookies cross-origin. The wildcard `origin: '*'` is forbidden by the CORS spec when credentials are included -- the origin function echoes back the exact requesting origin, which the `cors` package does automatically when the callback receives `true`.

    AVOID: Do NOT use `origin: '*'` anywhere -- it breaks credentialed requests. Do NOT set `domain: 'localhost'` in dev -- browsers reject it; use `undefined` (omit the attribute).
  </action>
  <verify>
    - `cd backend && npx tsc --noEmit` compiles without errors
    - `node -e "require('cookie-parser')"` in backend dir succeeds
    - Grep `backend/src/index.ts` for `credentials: true` and `cookieParser`

<task type="auto">
  <name>Task 2: Set ev_session cookie on login, clear on logout (with expired-JWT handling)</name>
  <files>backend/src/routes/auth.ts</files>
  <action>
    1. Add import at top of `backend/src/routes/auth.ts`:
       ```typescript
       import { env } from '../lib/env.js';
       ```

    2. Create a shared cookie options helper near the top of the file (after imports, before router):
       ```typescript
       /** Shared cookie options -- used for both set and clear to ensure domain/path match */
       function evSessionCookieOptions() {
         return {
           httpOnly: true,
           secure: env.NODE_ENV === 'production',
           sameSite: 'lax' as const,
           domain: env.COOKIE_DOMAIN ? env.COOKIE_DOMAIN : undefined,
           path: '/',
         };
       }
       ```
       WHY a helper: If set and clear use different domain/path values, the browser silently ignores the clear. A single function prevents this pitfall.

    3. In the `POST /login` handler, AFTER the `!data.session` guard and BEFORE the `res.status(200).json(...)` call (around line 314), add:
       ```typescript
       // SSO: set shared session cookie with refresh token
       res.cookie('ev_session', data.session.refresh_token, {
         ...evSessionCookieOptions(),
         maxAge: 30 * 24 * 60 * 60 * 1000, // 30 days in ms
       });
       ```
       The existing JSON response body is UNCHANGED -- `res.cookie()` appends a Set-Cookie header without affecting the JSON body.

    4. Restructure the `POST /logout` handler to clear the cookie BEFORE requireAuth runs. Replace the current logout route definition with:
       ```typescript
       router.post(
         '/logout',
         // SSO: clear session cookie unconditionally BEFORE auth check.
         // If JWT is expired, requireAuth returns 401 but cookie is already cleared.
         (req: Request, res: Response, next: NextFunction) => {
           res.clearCookie('ev_session', evSessionCookieOptions());
           next();
         },
         requireAuth,
         async (req: Request, res: Response): Promise<void> => {
           const { userId, accessToken, tokenExp } = req as AuthenticatedRequest;

           const { error } = await signOutUser(accessToken);

           if (error) {
             console.error('[auth/logout] Supabase signOut error:', error.message);
           }

           await recordLogout(userId, tokenExp);

           res.status(200).json({ message: 'Logged out successfully' });
         }
       );
       ```
       Add `NextFunction` to the express imports if not already present:
       ```typescript
       import type { Request, Response, NextFunction } from 'express';
       ```
       WHY pre-requireAuth clear: If a user's JWT has expired but their ev_session cookie exists, POST /logout would 401 before reaching the cookie-clear code. By clearing in a middleware BEFORE requireAuth, the cookie is always removed -- even on 401. The Supabase session revocation still happens when JWT is valid (best-effort).

    5. Also set the cookie on `POST /signup` when a session is returned. In the signup handler, the response at line 245 (`res.status(201).json(...)`) does NOT return tokens because email confirmation is required (data.session is null). So NO cookie should be set on signup -- the user gets the cookie when they first log in after confirming email. Do NOT add cookie logic to signup.

    - Do NOT change the login response JSON shape -- frontends depend on it.
    - Do NOT add cookie-set to signup -- data.session is null when email confirmation is enabled.
    - Do NOT use `res.clearCookie('ev_session')` without options -- domain/path must match or browser ignores it.
