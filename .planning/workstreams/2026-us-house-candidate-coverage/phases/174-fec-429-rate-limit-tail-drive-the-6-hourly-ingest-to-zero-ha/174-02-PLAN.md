<objective>
Cut FEC API request volume at the root — the actual cause of the residual 429 tail — by (1) resolving committees from the free bulk `ccl` linkage instead of a per-source API call, and (2) fetching only Schedule A rows loaded since the last successful run via the live-confirmed `min_load_date` filter, replacing the whole-cycle-per-source re-pull. All changes live in the FEC adapter + a small exported helper in the bulk loader.

Purpose: FEC-01 eliminates the dominant 429 source (`resolveCommitteeIds`); FEC-02 collapses per-run volume from tens of thousands to an estimated ~1,000–1,500/day. Together they are the root-cause fix; the limiter (174-01/174-03) is only a backstop.
Output: bulk-first committee resolution + incremental `min_load_date` cursor in `fecAdapter.ts`, plus a reusable `buildCandidateCommitteeMap` in `fecBulkLoader.ts`.
</objective>
