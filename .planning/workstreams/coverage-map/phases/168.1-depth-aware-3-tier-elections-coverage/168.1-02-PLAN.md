<objective>
Extend the backend elections service to compute the 3-tier depth metric from live data: enrich the `racesForStateDate` SQL with per-race active/stanced/motivated counts, wire the pure `classifyRaceTier`/`weightedDepthScore` helpers into `getElectionsStateScores`, and extend the `StateElection` contract with the weighted depth score + per-tier tallies (ELEC-04 computation half; ELEC-06 payload half). Lock the SQL-row → tier translation with a behavioral test.

Purpose: This is where the anti-inflation rule meets real data — the min/ALL SQL aggregates and the withdrawn-exclusion (D-02) / null-politician-cap (D-03) make a names-only state read ~33%, satisfying success criterion 3. Reusing the exact completeness-map signal SQL (D-06/07/08) keeps one definition of "has stances"/"has motivations" in the codebase. The new test proves those decisions hold against representative DB row shapes — the one place `admin.test.ts` (which mocks the whole service) cannot cover.

Output: extended `racesForStateDate` query, tier + weighted-score wiring in `getElectionsStateScores`, an additively-extended `StateElection` interface serving through `admin.ts` with no route change, and a `pool.query`-mocked behavioral test asserting the aggregate columns + derived tier.
</objective>
