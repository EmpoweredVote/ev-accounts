# Milestone v1.9: Roles

**Status:** ✅ SHIPPED 2026-04-06
**Phases:** 51–58
**Total Plans:** 19

## Overview

Delegated authority — admins assign geo-scoped and resource-scoped roles to Connected/Empowered accounts, giving them limited contributor capabilities with a full audit trail. A contributor portal serves as the role-holder workspace. Phase 51 also closes an open v1.8 loose end: Essentials XP source provisioning.

## Milestone Summary

**Key Decisions:**

- **requireRole middleware**: NULL-safe jurisdiction check — grant with `jurisdiction_geoid = NULL` matches any jurisdiction (global grants). `IS NULL OR IS NOT DISTINCT FROM` pattern established for all future role checks.
- **Redis role cache**: `roles:uid:{userId}` key with 60–120s TTL (configurable via `ROLE_CACHE_TTL_SECONDS` env var). Invalidated synchronously on every admin grant/revoke.
- **fail-open vs fail-closed**: `compass_stance_editor` + `campaign_manager` fail-open when politician has no `home_jurisdiction_geoid` (intentional Alpha behavior — console.warn). `essentials_data_editor` fails CLOSED — NULL politician geoid always returns 403.
- **District-join over stored column**: `getDistrictGeoidForPolitician` uses `offices→districts JOIN` instead of `home_jurisdiction_geoid` (NULL on all 2,577 rows). Never filter on `home_jurisdiction_geoid` — always JOIN through `essentials.offices → essentials.districts`.
- **Contributor portal deployment**: Portal embedded in `app/` at `app.empowered.vote/contributor`, not a standalone `contributor/` Vite app. ROLE-13 spec deviation accepted for Alpha.
- **CTC integration**: CTC uses `GET /api/roles/me` or `POST /api/roles/check` — NOT `GET /api/contributor/me` (which filters to 3 contributor roles only and excludes `ctc_content_editor`).
- **Dynamic import in test files**: Static `import { checkRole }` hoisted before `process.env` assignments in ESM. Use `beforeAll` + dynamic import for env-sensitive modules in Vitest.
- **Pool.query for all role writes**: No PostgREST for `public.role_audit_log` writes — uses `pool.query()` consistent with project-wide non-public schema pattern.

**Issues Resolved:**

- Pre-existing gap: `grant_role`, `revoke_role`, `get_user_roles` RPCs were missing from all 54 migrations (Phase 52 closed this)
- `get_user_roles` omitted `ur.id` → audit log could not reference specific grant row (migration 057 fixed)
- `home_jurisdiction_geoid` NULL on all `essentials.politicians` rows → jurisdiction-scoped queries returned 0 results (Phase 58 plan 05 fixed with district-join approach)
- `essentials_data_editor` grants silently ignored in `getContributorPoliticians` — fell through all branches without handling
- Bulk stance route shadowed by single-topic route (route ordering fix)

**Issues Deferred:**

- CORS_ORIGIN: `app.empowered.vote` must be verified in Render env vars panel — not committed to any config file
- Admin grant UI → adminRouter → grant_role RPC chain not end-to-end traced by integration checker — smoke-test before v2.0
- `feature_scope` field in `/api/roles/check` body accepts a role slug but is named like a feature scope — naming confusion for future integrators
- Backport district-join approach to `getMatchingGrant` (compass_stance_editor path) — currently uses fail-open with console.warn

**Technical Debt Incurred:**

- `stanceService.ts` `getMatchingGrant`: fail-open for missing `home_jurisdiction_geoid` (compass_stance_editor). Long-term fix: use same district-join pattern as `getEditorMatchingGrant` (Phase 56).
- REQUIREMENTS.md stale checkboxes for ROLE-13–16 (marked pending in traceability table but all complete per audit).
- Phase 57 summary and integration docs claim `/api/contributor/me` exposes CTC grants — incorrect. CTC uses `/api/roles/me` instead.
