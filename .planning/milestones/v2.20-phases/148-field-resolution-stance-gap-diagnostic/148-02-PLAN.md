<objective>
Resolve and lock the verified Nov-3 general-ballot field for all 144 Wave-1 US House districts, then assemble the final Phase 148 reference artifacts that Phases 149-151 consume. This overlays the externally-verified candidate field (from Wikipedia's action=parse API + the registered-key FEC /v1/candidates per-state pull, with Playwright/Ballotpedia/NBC-AP as fallbacks) onto the DB incumbent map produced in Plan 148-01, joining by geo_id. It explicitly flags every district where the incumbent is not the 2026 nominee — re-confirming the inherited milestone claims (NY-10 Goldman lost, NY-13 Espaillat lost, NY-7 Velazquez / NY-12 Nadler retired) from a primary-results source rather than trusting incumbency — and enumerates the genuinely-new candidates each seeding phase must create records for. It also re-queries each CA district's existing_race_id live from essentials.races (never a research placeholder) so Phase 149 inserts race_candidates against verified race UUIDs.

Purpose: This is the source of truth that prevents the milestone's two costliest traps (duplicate incumbents, wrong/lost nominee surfaced) AND removes guessing from the CA seeding path. Phase 149 reads existing_race_id + the candidate list to insert race_candidates; Phases 150/151 read target_election to create races first; all three read incumbent_pid to reuse records and incumbent_top_up_tier to scope incumbent stance work.

Output: 148-FIELD-TABLE.md (reviewable narrative), 148-field-table.csv (machine-readable, 13-column schema), and a lightweight 148-verify.sql read-only assertion. NO production writes, NO migrations, NO application code.
</objective>

- Read the key: awk -F= '/^FEC_API_KEY/{print $2}' backend/.env | tr -d '\r'

CA existing_race_id resolution query (run live in Task 2; do NOT hardcode UUIDs from research):
  SELECT d.geo_id, r.id AS existing_race_id
  FROM essentials.races r
  JOIN essentials.elections e ON e.id = r.election_id
  JOIN essentials.districts d ON d.geo_id = r.geo_id          -- or r.district_id = d.id, whichever the schema joins on
  WHERE e.id::text LIKE '728d0074%'                            -- "CA 2026 Statewide General"
    AND d.district_type = 'NATIONAL_LOWER'
    AND substr(d.geo_id,1,2) = '06'
  ORDER BY d.geo_id;
