## Milestone Summary

**Decimal Phases:** Phase 16 inserted as gap closure after Phase 15 audit identified two integration breaks.

**Key Decisions:**

- Soft-delete via `deleted_at` on compass_responses (rationale: preserves data for recovery; reset is reversible via re-import)
- `SET search_path = ''` on all new SECURITY DEFINER functions (rationale: prevents search_path injection)
- `is_active` excluded from compass_topics INSERT — GENERATED ALWAYS AS column causes Postgres error if included
- Two-pass validation pattern in admin RPCs (validate all inputs before any writes — all-or-nothing atomicity)
- `.is('deleted_at', null)` required for PostgREST null comparisons (`.eq()` does not generate IS NULL)
- PUT → PATCH semantic correction for partial update routes

**Issues Resolved:**

- Stale database.types.ts causing TypeScript errors across inform schema
- JWT revocation not covered by integration test (same-second iat collision risk identified and fixed)
- `DELETE /api/compass/answers/me` not filtering soft-deleted rows on subsequent reads (Phase 16)
- CategoriesPage rendering empty due to `.categories` property access on plain array response (Phase 16)
- Missing `GET /admin/compass/topics/:id/stances` blocking stance editor and politician RadioGroup (Phase 15-05)

**Issues Deferred:**

- CompassV2 frontend API contract updates (bearer tokens, /api/account/me, /api/admin/me) — separate repo, tracked as CV2-01 through CV2-05 in archived REQUIREMENTS.md
- `saveSelectedTopics` JSON.stringify potential double-serialization — verify against live DB `jsonb` column type before Alpha onboarding
- `PATCH /api/admin/compass/politicians/:id` has no React UI caller — profile edit form not in Phase 15 scope
- Migrations 026–029 must be applied manually to live DB (consistent project pattern; explicit deploy runbook step required)

**Technical Debt Incurred:**

- `empowered_profiles` missing columns (representing_city, district_type, district_number, chamber_name, etc.) — live DB never received migration; ZIP candidate discovery non-functional until applied
- Human verification still required on live DB for stance editor populate, RadioGroup render, and create-topic → live → public feed round-trip (cannot confirm without seeded running backend)
