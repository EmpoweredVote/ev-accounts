## Goal

Extract the politician list fetch into a shared hook so both CompareModal and the new inline picker avoid duplicate API calls. Then build the InlinePoliticianPicker component as a self-contained dropdown with search, keyboard navigation, and a "Clear comparison" option.

## Context

**Current state:**
- `CompareModal.jsx` fetches `/compass/politicians` in its own `useEffect` and stores the list in local state (`politicians`)
- `CompareModal` contains an inner `PoliticianPicker` component with search, keyboard nav, and photo+name+title rows
- The inline picker needs the same politician list data and similar row rendering

**User decisions (locked):**
- Share politician list data with CompareModal — avoid duplicate API fetches
- Each row shows photo + name + office title (same richness as CompareModal)
- Full keyboard navigation: arrow keys to navigate, Enter to select, Escape to close
- Include a "Clear comparison" option in the dropdown
- Collapsed trigger shows: politician photo + name + chevron icon

**Files to read before starting:**
- `CompassV2/src/components/CompareModal.jsx` — current PoliticianPicker implementation and fetch logic
- `CompassV2/src/components/ComparePanel.jsx` — politician header section (lines 99-121) that the inline picker replaces
- `CompassV2/src/pages/Compass.jsx` — how comparePol state flows to ComparePanel and CompareModal

## Tasks

<task id="A1">
<title>Create usePoliticianList shared hook</title>
<actions>
1. Create `CompassV2/src/hooks/usePoliticianList.js`
2. Move the politician list fetch logic from `CompareModal.jsx` into this hook:
   - Fetches `${import.meta.env.VITE_API_URL}/compass/politicians` with `credentials: "include"`
   - Returns `{ politicians, loading }` where `politicians` is the array (defaults to `[]`)
   - Use a module-level cache so the fetch only happens once across all consumers (simple: store the promise and resolved value in module scope; subsequent calls return the cached result immediately)
   - Export the hook as default
3. Update `CompareModal.jsx` to use `usePoliticianList()` instead of its local `useEffect` + `useState`:
   - Remove the local `politicians` state and `useEffect` fetch
   - Replace with `const { politicians } = usePoliticianList();`
   - Everything else in CompareModal stays the same
4. Verify CompareModal still works correctly — the PoliticianPicker component inside it receives the same `politicians` array as before
</actions>
</task>

<task id="A2">
<title>Build InlinePoliticianPicker component</title>
<actions>
1. Create `CompassV2/src/components/InlinePoliticianPicker.jsx`
2. **Props interface:**
   - `currentPolitician` — the currently compared politician object (or null)
   - `onSelect(politician)` — called when user picks a politician from the list
   - `onClear()` — called when user chooses "Clear comparison"
   - `onOpenFullModal()` — called when user clicks the expand/browse button
3. **Collapsed state (trigger):**
   - Render as a button/clickable div that looks like a natural part of the ComparePanel header
   - Shows: politician's photo (16x16 rounded-full, same as ComparePanel header), politician's name (bold), office title (neutral-500 text-sm), and a chevron-down icon (▾)
   - Use the same photo fallback chain as ComparePanel: `politician.photo_origin_url || politician.photo_custom_url || placeholder`
   - Import `placeholder` from `../assets/placeholder.png`
   - Import `getPolName` from `../util/name` and `normalizeOfficeTitle` from `../util/name` for display
   - On click, toggle the dropdown open
4. **Expanded state (dropdown):**
   - Position as an absolute overlay below the trigger, matching the trigger's width
   - Render a search input at the top (same style as PoliticianPicker in CompareModal: `placeholder="Search politician by name or office..."`)
   - Below the search input, render a "Clear comparison" row:
     - Icon: an X or clear icon in neutral-400
     - Text: "Clear comparison" in neutral-500
     - On click: calls `onClear()` and closes dropdown
   - Below that, render a divider line
   - Below divider, a small text button or icon for "Browse all" or an expand icon that calls `onOpenFullModal()` and closes dropdown. Style this as a subtle row with an expand/external-link icon.
   - Then render the scrollable politician list (max-h-64 overflow-auto, same as CompareModal's PoliticianPicker)
   - Each row shows: photo (w-10 h-10 rounded-full), name (font-medium), office title (text-gray-500) — same layout as PoliticianPicker rows but slightly more compact for inline use
   - Highlight the currently selected politician with a subtle indicator (e.g., bg-ev-light-blue/10 or a checkmark)
5. **Search filtering:**
   - Use the same `normalize` helper from CompareModal (NFD + strip diacritics + lowercase)
   - Filter on name and office_title, same logic as PoliticianPicker
6. **Keyboard navigation:**
   - Arrow keys move highlight through visible options
   - Enter selects the highlighted option (calls `onSelect(politician)` and closes dropdown)
   - Escape closes the dropdown without selecting
   - Ensure visible scrolling (scroll highlighted item into view)
7. **Click-outside to close:**
   - Use a ref on the container and a `mousedown` document listener (same pattern as PoliticianPicker)
8. **Data source:**
   - Call `usePoliticianList()` inside the component to get `{ politicians, loading }`
   - If loading and list is empty, show a small spinner or "Loading..." text in the dropdown
9. **Styling consistency:**
   - Use Tailwind classes consistent with ComparePanel and CompareModal
   - Rounded corners (`rounded-xl`), border (`border border-neutral-200`), shadow (`shadow-lg`), white background
   - The trigger should have a subtle hover state (e.g., `hover:bg-neutral-50`) and cursor-pointer
</actions>
</task>
