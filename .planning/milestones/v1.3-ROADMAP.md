# Milestone v1.3: Alpha Launch & Location Infrastructure

**Status:** ✅ SHIPPED 2026-03-15
**Phases:** 17–26
**Total Plans:** 26

## Overview

Get Alpha live (migrations to production, CompassV2 contract), establish the location privacy infrastructure (encrypted lat/lng, PostGIS jurisdiction resolution), expand the empowered_profiles politician schema for VQ readiness, extend the gem system to three currencies, centralize the profile page in accounts with admin tier-promotion tooling, and transform accounts into the universal Connected Account portal with public signup flow. Also includes production data seeding (21 compass topics, 30 politicians, 588 stance values, 500 reasoning rows) and partner integration onboarding docs for CTC and Validation Quests.

## Milestone Summary

**Key Decisions:**

- Location: encrypted lat/lng (pgcrypto via Supabase Vault), not formatted address string. Coordinates never returned in any API response.
- PostGIS internal, Indiana-scoped for Alpha. TIGER/Line Indiana boundaries loaded into Supabase PostGIS. No third-party geographic API.
- Multi-currency gems: extend existing ledger. Add gem_type ENUM + 3 balance columns on connected_profiles. Single advisory lock pattern.
- Bearer Authorization header for gem service keys (standard Bearer semantics, not X-Service-Key).
- Service helper pattern: supabaseAdmin ops always in lib/*Service.ts, never in routes/.
- DROP FUNCTION before CREATE OR REPLACE when RETURNS TABLE changes (cannot change return type).
- CREATE POLICY IF NOT EXISTS not supported in Supabase Postgres 17.4 — use DO block checking pg_policies.
- Smoke test auth check: 401 is the only pass (500 = Supabase auth unreachable, 200 = catastrophic).
- isUserAdmin fails closed — returns false on DB error; connectivity issue can never accidentally promote a user.
- Direct DB connection for migrations — db.<ref>.supabase.co:5432 (direct), never the pooler port 6543. Session-mode pooler port 5432 is safe.
- convert_from(bytea,'UTF8') not bytea::text for pgp_sym_decrypt_bytea output.

**Issues Resolved:**

- Windows MINGW64 DNS resolution issue with applyMigrations.ts — documented SQL Editor workaround in DEPLOY.md
- Gem balance-always-0 bug — GET /me was reading legacy xp/gem_balance column instead of total_xp/yellow_gem_balance
- SQL Editor silently drops functions 2+ in multi-function scripts — each function must be pasted separately
- Migration partial-apply states on production (034, 035, 036) — handled by checking function existence before applying
- Compass answer response type mismatch — Supabase select string must be a single literal for TypeScript inference

**Issues Deferred:**

- CompassV2 frontend CV2-01 through CV2-05 — Accounts side complete; CompassV2 repo must implement its side using COMPASS_CONTRACT.md
- Full US TIGER/Line boundary loading — Alpha is Indiana + LA County only
- Location key rotation automation — runbook procedure sufficient for Alpha
- User-to-user compass compare (COMP-05) — deferred

**Technical Debt Incurred:**

- Phase 17 has no VERIFICATION.md (human-interactive deployment phase; execution confirmed in 17-03-SUMMARY.md)
- REQUIREMENTS.md Traceability table DEPLOY rows still show Pending (body checkboxes are authoritative — all satisfied)
