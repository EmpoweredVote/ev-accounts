## Critical Gap Detail

### GEO-14 Gap: Location tab hidden from Inform users

**Location:** `admin/src/pages/ProfilePage.tsx` line 719
**Code:** `if (tab === 'location' && !cp) return null;`
**Problem:** `cp` is `profile?.connected_profile`. Inform users have no `connected_profile` row, so `!cp` is always `true` — the Location tab never renders for them.

**What works:**
- `PATCH /api/account/location-hint` correctly caches user_districts for Inform users
- `GET /api/account/school-district` accepts `requireAuth` (both tiers)
- `schoolDistrict` state IS populated at lines 581–583 (fetch runs unconditionally)
- `SchoolDistrictSection` component is fully implemented

**What doesn't work:**
- Tab bar renders 5 tabs for Connected but hides the 'location' tab entirely for Inform users
- Fetched data (`schoolDistrict` state) is unreachable — no UI path renders it

**Fix:**
```tsx
// Line 719 — replace:
if (tab === 'location' && !cp) return null;

// With:
const hasLocationData = cp !== null || !!profile?.inform_profile?.last_essentials_location;
if (tab === 'location' && !hasLocationData) return null;
```

This shows the Location tab for Inform users who have used Essentials to set a location, while still hiding it for users with no location on file.

Also: The tab bar itself at the tab header render site should conditionally include the 'location' option only when `hasLocationData` is true (or always include it — the tab body guard handles the no-data case with 204 → null state).
