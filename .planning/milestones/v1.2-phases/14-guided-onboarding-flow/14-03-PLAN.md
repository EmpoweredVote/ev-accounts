  <action>
Integrate the CalibrationOverlay into Compass.jsx so it appears as a full-screen takeover when the user has fewer than 3 answered compass topics.

1. Import CalibrationOverlay:
   ```javascript
   import CalibrationOverlay from "../components/CalibrationOverlay";
   ```

2. Add state for tracking overlay dismissal:
   ```javascript
   const [calibrationSkipped, setCalibrationSkipped] = useState(
     () => localStorage.getItem("calibration_skipped") === "true"
   );
   ```

3. Determine whether to show the overlay:
   ```javascript
   // Show calibration overlay if:
   // - User has fewer than 3 answered compass topics AND
   // - User hasn't explicitly skipped the overlay
   // - There IS no saved calibration_progress (don't show welcome if they're mid-flow — the overlay will resume)
   const showCalibration = answeredCompassCount < 3 && !calibrationSkipped;
   ```
   Actually, simpler: `showCalibration` should be true when `answeredCompassCount < 3 && !calibrationSkipped`. The CalibrationOverlay internally handles resuming from saved progress.

4. Render the overlay conditionally. Place it BEFORE the normal compass content:
   ```jsx
   {showCalibration && (
     <CalibrationOverlay
       onComplete={() => {
         setCalibrationSkipped(false);
         localStorage.removeItem("calibration_skipped");
         localStorage.removeItem("calibration_progress");
         // The compass page will now show the chart since answeredCompassCount >= 3
       }}
       onSkip={() => {
         setCalibrationSkipped(true);
         localStorage.setItem("calibration_skipped", "true");
         localStorage.removeItem("calibration_progress");
       }}
     />
   )}
   ```

5. When `showCalibration` is true, hide the normal compass content (the overlay is full-screen fixed, but we should also not render the content behind it to avoid confusion):
   ```jsx
   {showCalibration ? (
     <CalibrationOverlay onComplete={...} onSkip={...} />
   ) : (
     <div className="px-4 py-6 flex flex-col items-center overflow-hidden">
       {/* ... existing compass content ... */}
     </div>
   )}
   ```

6. When the user resets their compass (via handleResetCompass from Plan 02), also clear calibration_skipped so the overlay re-appears:
   In the handleResetCompass function, add:
   ```javascript
   localStorage.removeItem("calibration_skipped");
   localStorage.removeItem("calibration_progress");
   setCalibrationSkipped(false);
   ```

7. Important edge case: If user drops below 3 topics AFTER completing onboarding (by removing topics from Library), they should see Phase 13's MinimumProgress, NOT re-trigger the overlay. This is handled by `calibrationSkipped` staying false after onComplete — the user completed onboarding, so the overlay won't show. The MinimumProgress component in the normal compass view handles <3 topics.

   Wait — after completing, `calibrationSkipped` is false AND `answeredCompassCount` could drop below 3 if they remove topics. To prevent re-triggering:
   - Track completion separately: `const [calibrationCompleted, setCalibrationCompleted] = useState(() => localStorage.getItem("calibration_completed") === "true");`
   - Show overlay: `answeredCompassCount < 3 && !calibrationSkipped && !calibrationCompleted`
   - On complete: `localStorage.setItem("calibration_completed", "true"); setCalibrationCompleted(true);`
   - On reset: `localStorage.removeItem("calibration_completed"); setCalibrationCompleted(false);`
   - This ensures: completed onboarding + removed topics = MinimumProgress (not overlay)
