The script performs these checks and writes results to `FEASIBILITY_LOCAL_DATA.md`:

**1. LA County Legistar API Probes:**
- GET `https://webapi.legistar.com/v1/LACounty/Bodies` — log status, count active bodies (BodyActiveFlag=1)
- GET `https://webapi.legistar.com/v1/LACounty/OfficeRecords?$filter=OfficeRecordPersonId eq 799 and OfficeRecordEndDate gt datetime'2025-01-01'&$top=100` — test committee memberships for Hilda Solis (PersonId 799). Log count of active records.
- GET `https://webapi.legistar.com/v1/LACounty/Matters?$filter=MatterBodyId eq 76&$top=50&$orderby=MatterLastModifiedUtc desc` — test BOS matters. Count how many have non-NULL MatterRequester. Log the NULL percentage.
- For 5 recent matters (from the above), GET `https://webapi.legistar.com/v1/LACounty/Matters/{id}/Histories` — check MoverName population. Log how many have non-NULL MoverName.
- GET `https://webapi.legistar.com/v1/LACounty/VoteRecords` — confirm 404 (no individual vote records)
- GET `https://webapi.legistar.com/v1/LACounty/Matters/{recent_id}/Sponsors` — confirm empty array
- Loop through all 5 supervisor PersonIds, fetch OfficeRecords for each, count total active committee memberships

**2. Bloomington OnBoard HTML Probes:**
- GET `https://bloomington.in.gov/onboard/committees/1/members` — parse HTML with BeautifulSoup, extract member names from page (names appear as link text or heading text near member entries). Log each found name.
- GET `https://bloomington.in.gov/onboard/committees/1/legislation?page=1` — check if legislation listing loads without login, count items found
- For 3 legislation items, GET individual detail pages and attempt sponsor extraction using regex: `r"[Ss]ponsored by (.+?)(?:\s+(?:allows|consolidates|renames|updates|amends|directs|is|\.)|$)"` — log matches and non-matches
- Check sub-committees: GET `/onboard/committees/77/members`, `/onboard/committees/81/members`, `/onboard/committees/49/members` — log member counts

**3. Politician Name Matching Verification (requires DATABASE_URL):**
- Connect to PostgreSQL via psycopg2
- For each of the 5 LA County supervisors: query `SELECT id, full_name FROM essentials.politicians WHERE full_name ILIKE '%{last_name}%' AND is_active = true LIMIT 5`. Use RapidFuzz `fuzz.token_sort_ratio` with threshold 80 if ILIKE returns 0 or 2+ results. Log: matched/unmatched/ambiguous.
- For each of the 9 Bloomington council members: same approach. Log results.
- Report: "X of 5 LA County supervisors matched, Y of 9 Bloomington members matched"

**4. Write FEASIBILITY_LOCAL_DATA.md** with the following sections:
- Header with date and script version
- Capability Matrix table (rows: committee assignments, committee roles, sub-committees, legislation listing, legislation sponsor attribution, legislation mover attribution, vote records, individual vote positions; columns: Bloomington, LA County)
- LA County Legistar Findings (endpoint-by-endpoint results with HTTP status codes, sample data counts)
- Bloomington OnBoard Findings (URL-by-URL results with scraping success/failure)
- Politician Name Matching Results (per-politician match table)
- Importable Data Summary (what 58-02 and 58-03 can actually import)
- Gaps and Limitations (what cannot be imported and why)
- Recommendations for import plans

- `--dry-run`: Skip database queries (only probe external APIs/HTML)
- `--verbose`: Print all HTTP responses
- `--output PATH`: Override output file path (default: same directory as script)

- Use `from rapidfuzz import fuzz` for name matching (already installed in .venv)

- OnBoard HTML parsing: member names may appear as text in heading tags, link text, or paragraph text. Parse robustly — look for `/onboard/members/{id}` links and extract text content.
- Handle HTTP errors gracefully — log and continue, do not abort on a single 404
- Timeouts: 30 seconds per request
- Write the Markdown file programmatically (not manually) using Python f-strings or template
