**Library.jsx — GAP-01: Guard batch fetch for guests**

In the second `useEffect` (line ~146, the one that fetches `/compass/answers/batch`), add an `isLoggedIn` guard at the top of the effect body, right after the existing early return for empty arrays:

```javascript
useEffect(() => {
  if (!selectedTopics.length || !topicsRef.current.length) return;
  if (!isLoggedIn) return;  // ← ADD THIS LINE — guests have no server answers to fetch
  // ... rest of fetch logic unchanged
}, [selectedTopics, isLoggedIn]);  // ← ADD isLoggedIn to dependency array
```

This matches the pattern already used by the first `useEffect` (line ~75) which guards with `if (!isLoggedIn) { /* localStorage path */ return; }` and by `handleDrawerSelect` (line ~256) which guards server saves with `if (isLoggedIn)`.

**Register.jsx — GAP-02: Fix sign-in link navigation**


This matches Login.jsx which uses `navigate("/register")` for its mode switch.

**Register.jsx — GAP-03: Guard buildGuestState against empty topics**

The `buildGuestState` function (lines 18-37) maps localStorage answers to topic_ids using `topics.find()`. If topics haven't loaded from the API yet (empty array), every `.find()` returns undefined, all entries are filtered out by `.filter(Boolean)`, and the guest silently loses all answers.

Fix: In the `handleSubmit` function, add a guard before calling `buildGuestState()`. If `topics.length === 0`, log a warning and send `guest_state` with an empty answers array and only `selected_topics` from localStorage. The backend RegisterHandler already handles empty `guest_state.answers` gracefully (it skips the upsert loop).

Replace the body construction in handleSubmit:
```javascript
body: JSON.stringify({ username, password, guest_state: buildGuestState() }),
```
with:
```javascript
body: JSON.stringify({
  username,
  password,
  guest_state: topics.length > 0
    ? buildGuestState()
    : {
        answers: [],
        selected_topics: safeParse(localStorage.getItem("selectedTopics"), []),
      },
}),
```

This ensures registration never silently drops answers — if topics haven't loaded, the registration still succeeds (account is created, login works) and the raw localStorage answers survive for a future sync. The selected_topics IDs (which are numeric, not dependent on topic lookup) are still sent.
