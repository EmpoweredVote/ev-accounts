  <files>CompassV2/src/pages/Library.jsx</files>
  <action>
Fix the answeredTopicIDs useEffect (currently lines 75-85) so guests are not blocked:

**Current problem:** The fetch to `/compass/answers` fires unconditionally. For guests (no session cookie), the backend returns 401. The `.then(res => res.json())` chain never resolves successfully, so `setAnsweredLoaded(true)` never runs. Since `answeredLoaded` gates the entire category card grid (line 429: `answeredLoaded && categories.map(...)`), guests see a completely blank Library page.

**Fix:** Wrap the fetch in an `isLoggedIn` check. For guests, derive answeredTopicIDs from the localStorage-backed `answers` context object instead:

```jsx
useEffect(() => {
  if (!isLoggedIn) {
    // Guest: derive answered IDs from localStorage-backed answers in context
    const localAnswerIds = topics
      .filter(t => answers[t.short_title] != null && answers[t.short_title] > 0)
      .map(t => t.id);
    setAnsweredTopicIDs(localAnswerIds);
    setAnsweredLoaded(true);
    return;
  }

  fetch(`${import.meta.env.VITE_API_URL}/compass/answers`, {
    credentials: "include",
  })
    .then((res) => {
      if (!res.ok) throw new Error("Failed to fetch answers");
      return res.json();
    })
    .then((data) => {
      const ids = data.map((a) => a.topic_id);
      setAnsweredTopicIDs(ids);
      setAnsweredLoaded(true);
    })
    .catch(() => {
      // Fallback: use localStorage answers if server fetch fails
      const localAnswerIds = topics
        .filter(t => answers[t.short_title] != null && answers[t.short_title] > 0)
        .map(t => t.id);
      setAnsweredTopicIDs(localAnswerIds);
      setAnsweredLoaded(true);
    });
}, [isLoggedIn, topics, answers]);
```

Key changes:
1. Add `isLoggedIn` to the dependency array (was `[]` -- fired once before auth check completed)
2. Also add `topics` and `answers` as dependencies so guest mode re-derives when context changes
3. For guests: derive IDs from `answers` context (which is backed by localStorage) and immediately set `answeredLoaded = true`
4. Add `.catch()` fallback that also sets `answeredLoaded = true` with localStorage-derived IDs
5. Add `res.ok` check before calling `res.json()` to properly handle non-200 responses

Do NOT change the route gating in App.jsx -- the Library route is already guest-accessible (line 42). The problem is purely the data fetch inside Library.jsx.

<task type="auto">
  <name>Task 2: Hydrate full answer values for all topics on answeredTopicIDs fetch</name>
  <files>CompassV2/src/pages/Library.jsx</files>

Fix the drawer answer state restoration problem for logged-in users:

**Current problem:** After login, localStorage answers are cleared (Login.jsx line 73-74). The Library page fetches `/compass/answers` (GET) to get answeredTopicIDs, but only extracts the `topic_id` from each response object -- it discards the `value` field. Meanwhile, `getAnswer(topic)` reads from the `answers` context object, which is empty after login clears localStorage. Result: cards show checkmarks (answeredTopicIDs populated) but the drawer does not highlight the selected stance (answers[short_title] is undefined).

**Fix:** In the same answeredTopicIDs fetch (Task 1's logged-in branch), also populate the `answers` context with answer values from the server response. The GET `/compass/answers` response returns objects with `{ topic_id, value, write_in_text }`. Use these to hydrate answers:

In the logged-in branch's `.then((data) => { ... })` callback, after setting answeredTopicIDs, add:

```jsx
.then((data) => {
  const ids = data.map((a) => a.topic_id);
  setAnsweredTopicIDs(ids);

  // Hydrate answer values so drawer can highlight the correct stance
  const answerEntries = data
    .map((a) => {
      const topic = topicsRef.current.find((t) => t.id === a.topic_id);
      if (!topic) return null;
      return [topic.short_title, a.value];
    })
    .filter(Boolean);
  if (answerEntries.length) {
    setAnswers((prev) => ({ ...prev, ...Object.fromEntries(answerEntries) }));
  }

  // Also hydrate write-ins
  const writeInEntries = data
    .map((a) => {
      const topic = topicsRef.current.find((t) => t.id === a.topic_id);
      if (!topic || !a.write_in_text) return null;
      return [topic.short_title, a.write_in_text];
    })
    .filter(Boolean);
  if (writeInEntries.length) {
    setWriteIns((prev) => ({ ...prev, ...Object.fromEntries(writeInEntries) }));
  }

  setAnsweredLoaded(true);
})
```

This uses the `topicsRef` (already defined at line 89-90) to map topic_id to short_title, the same pattern used by the selectedTopics batch fetch (lines 96-135).

This means ALL server-side answers are loaded into context, not just those for selectedTopics. The drawer's `getAnswer(topic)` will now find the correct value for any topic.

Note: `setWriteIns` is already destructured from useCompass at line 60.
