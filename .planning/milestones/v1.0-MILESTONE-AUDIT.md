## Integration Findings

### FINDING 1 — HIGH (Functional Break): connect.ts compass-import uses wrong column name

**File:** `backend/src/routes/connect.ts` line ~493
**Issue:** `compass_topics` is queried with `.eq('is_active', true)` but the column is `is_live` (per Phase 4 schema and all other routes using `compass.ts:62`).
**Impact:** The compass-import validation phase (`confirmed: false`) always produces `liveVersionMap = {}`, making every submitted topic version appear mismatched. Users see all topics flagged as mismatched and `ready_to_import: false` regardless of actual topic versions.
**Requirement broken:** CONN-04
**Fix:** Change `.eq('is_active', true)` to `.eq('is_live', true)` in connect.ts compass-import handler.

---

### FINDING 2 — HIGH (Functional Break): Admin role revoke sends wrong payload shape

**File:** `admin/src/pages/admin/AccountDetailPage.tsx` ~line 88-90
**Issue:** Revoke action sends `{ userId, roleId }` (camelCase + id) but backend `RoleActionSchema` expects `{ user_id, role_slug }` (snake_case + slug).
**Impact:** Every role revoke attempt from the admin UI returns 400 Zod validation error. Role revocation via UI is non-functional.
**Fix:** Update AccountDetailPage revoke handler to send `{ user_id: userId, role_slug: roleSlug }` using the role's slug field (not its id).

---

### FINDING 3 — MEDIUM (Silent Data Gap): Role name field mismatch in admin UI

**Files:**
- `admin/src/pages/admin/RolesPage.tsx` — UI reads `role.display_name`, API returns `role.name`
- `admin/src/pages/admin/AccountDetailPage.tsx` — Same mismatch in roles section

**Issue:** The `public.roles` table column is `name`. The `GET /api/roles` backend returns `name`. The admin UI TypeScript interfaces define `display_name` and render it. Result: role names are blank throughout the admin UI.
**Impact:** Non-crashing but roles pages are non-functional visually — all role names display as empty strings.
**Fix:** Update admin UI role interfaces to use `name` instead of `display_name`, or add a `display_name` alias in `getAllActiveRoles()` query.

---

### FINDING 4 — LOW (Non-crashing): GET /api/admin/me returns incomplete payload

**File:** `backend/src/lib/adminService.ts` line ~464
**Issue:** `getAdminMe()` returns `{ isAdmin: true }` only. The Login page stores `user.id = ''` in authStore.
**Impact:** `user.id` is always empty string in the admin auth store. Server-side audit logging is unaffected (uses JWT-attached `req.userId`). No immediate crash.
**Fix:** Extend `getAdminMe()` to return `{ isAdmin: true, id: user.id, email: user.email }` from the Supabase auth user.
