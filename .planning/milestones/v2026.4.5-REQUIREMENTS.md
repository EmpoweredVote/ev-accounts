# Milestone v2026.4.5 Requirements — Compass-First Politician Card (ARCHIVED)

**Status:** ✅ ARCHIVED 2026-04-26

**Goal:** Ship a compass-first horizontal politician card (based on the existing `/prototype` variant C) across Essentials, with a view toggle, preserved card metadata, and non-compass variants for roles without a meaningful compass.

## Requirements

### CARD — Compass-first card component (ev-ui)

- [x] **CARD-01**: Publish a `CompassCardHorizontal` component in `@empoweredvote/ev-ui` based on Prototype variant C (horizontal radar-left / meta-right layout), with props for politician, user compass answers, and tier/branch visuals
  - **Outcome:** ✅ Satisfied via Phase 127. Stale checkbox (not updated at phase completion).
- [x] **CARD-02**: Card supports a dual-view toggle between compass (radar) view and portrait/photo view; toggle state persists per page (or per user preference — decided in discuss-phase)
  - **Outcome:** ✅ Satisfied via Phase 127. Toggle persists to localStorage per page. Stale checkbox.
- [x] **CARD-03**: Card preserves all existing PoliticianCard affordances without regression — tier/branch badges, elected/appointed marker, unopposed icon, term dates, years-in-office, chamber/district subtitle, initials fallback
  - **Outcome:** ✅ Satisfied via Phase 127. Stale checkbox.

### STATES — Empty and non-compass variants

- [x] **STATE-01**: When the user has insufficient compass answers (<3 topics), card renders a placeholder radar with a "Build your compass" CTA deep-linking to CompassV2 calibration for the relevant topics
  - **Outcome:** ✅ Satisfied via Phase 128 (computeVariant + CompassCardHorizontal empty variant). Stale checkbox.
- [x] **STATE-02**: Administrative roles (clerks, auditors, recorders, treasurers, and similar non-policy offices) render a non-compass variant — portrait-forward layout with role-appropriate content replacing the radar (content spec defined in discuss-phase)
  - **Outcome:** ✅ Satisfied with scope adjustment: generic "unavailable" portrait plate ships; role-specific content (office description) deferred. Stale checkbox.
- [x] **STATE-03**: Judicial roles render a judge-appropriate non-compass variant (retention history / court level / appointment source — spec defined in discuss-phase); retention judges continue their existing dual-appearance behavior on the representatives page
  - **Outcome:** ✅ Satisfied with scope adjustment: generic "unavailable" portrait plate ships; retention judge dual-appearance preserved. Stale checkbox.

### ADOPTION — Wire into Essentials

- [x] **ADOPT-01**: Representatives page politician cards replaced with the new compass-first card, preserving existing sort/filter controls, elected/appointed filter, and scroll-spy background bands
  - **Outcome:** ✅ Verified via Phase 129 automated + human smoke-test.
- [x] **ADOPT-02**: Elections page candidate cards adopt the new card — incumbents use full compass, challengers use appropriate empty/minimal variant
  - **Outcome:** ✅ Verified via Phase 129 automated + human smoke-test.
- [x] **ADOPT-03**: `/prototype` route retired or reduced to an internal reference once adoption ships, to prevent UI drift
  - **Outcome:** ✅ Route deleted, all prototype files removed, 0 residual references.
- [x] **ADOPT-04**: ev-ui version bumped via the auto-bump pipeline; essentials and CompassV2 compass picker continue to render correctly on main after merge
  - **Outcome:** ✅ ev-ui v0.6.1 tag pushed; auto-bump PRs merged (essentials #23, CompassV2); both confirmed on ^0.6.1.
