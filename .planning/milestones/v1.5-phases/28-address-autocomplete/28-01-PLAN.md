**Hook extension (useGooglePlacesAutocomplete.js):**

1. Add `useState` to the import from React (currently only imports `useEffect, useRef`).
2. Add `const [loadError, setLoadError] = useState(false);` inside the hook function.
3. In the early return guard: if `!API_KEY`, call `setLoadError(true)` before returning. This handles the "no key configured" degraded state.
4. Add a `.catch(() => { setLoadError(true); })` to the `importLibrary('places')` promise chain. This handles network failures, bad API keys, quota exhaustion.
5. Change the return from `undefined` (implicit) to `return { loadError };`.
6. Keep ALL existing behavior unchanged: `callbackRef` pattern, `ensureConfigured()`, `place_changed` listener with `formatted_address` guard, cleanup function. Do NOT change the function signature or the `onPlaceSelected` callback pattern.

**Landing page refactor (Landing.jsx):**

1. Replace `zip` state variable with `addressInput` state (`useState('')`).
2. Add `hasValidSelection` state (`useState(false)`) — tracks whether current input came from a Google Places selection.
3. Add `showSelectionHint` state (`useState(false)`) — controls visibility of the "please select" hint.
4. Destructure `loadError` from the hook: `const { loadError } = useGooglePlacesAutocomplete(inputRef, { ... })`.
5. In `onPlaceSelected` callback: set `addressInput` to the formatted address, set `hasValidSelection` to `true`, set `showSelectionHint` to `false`. Do NOT call `navigate()` — per locked decision, user must click Search.
6. Create `handleInputChange(e)`: sets `addressInput` from `e.target.value`, resets `hasValidSelection` to `false`, resets `showSelectionHint` to `false`.
7. Rewrite `handleSearch()`: if `!hasValidSelection`, set `showSelectionHint(true)` and return early. If valid, navigate to `/results?q=${encodeURIComponent(addressInput)}`. No ZIP detection (`/^\d{5}$/` test) — all input goes through `?q=`.
8. Remove `handleKeyDown` function entirely — Enter key should NOT submit raw text. The Google autocomplete handles Enter internally (selects first suggestion if dropdown is open, fires `place_changed` which only calls onPlaceSelected if `formatted_address` exists). With the `hasValidSelection` guard, Search button stays blocked until a suggestion is selected.
9. Update the input element:
   - `value={addressInput}` (was `zip`)
   - `onChange={handleInputChange}` (was inline)
   - Remove `onKeyDown={handleKeyDown}`
   - `placeholder="Enter your address"` (was "Enter ZIP code or address")
   - Add `disabled={loadError}` attribute
   - Add `disabled:bg-gray-100 disabled:cursor-not-allowed` to className
10. Update the Search button:
    - `disabled={!addressInput.trim() || loadError}` — keeps the visual disabled state for empty input and degraded mode. The `hasValidSelection` check happens inside `handleSearch()` to allow showing the hint.
11. Update subheading text from "Enter your ZIP code or address to see who represents you" to "Enter your address to see who represents you".
12. Add degraded mode error message below the search row (after the flex container): render a `<p>` with text "Address search is temporarily unavailable. Please try again later." in `text-sm text-red-600`, conditionally shown when `loadError` is truthy.
13. Add selection hint below the error message area: render a `<p>` with text "Please select an address from the suggestions." in `text-sm text-amber-700`, conditionally shown when `showSelectionHint && !loadError`.
14. Keep the right-side illustration/magnifying glass SVG unchanged.
15. Keep the `SiteHeader` import and usage unchanged.
