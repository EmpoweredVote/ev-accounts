    1. Extract ZIP from URL param, validate with `isZip5()`

    5. For local candidates (district_type IN LOCAL_EXEC, LOCAL, COUNTY, SCHOOL, JUDICIAL): join through `essentials.zip_politicians` for ZIP filtering
    6. For state/federal candidates: filter by `o.representing_state` matching the derived state
    7. Add `p.external_id` to the SELECT to populate `CandidateOut.ExternalID`
    8. Map rows to `CandidateOut` structs (already defined ~line 3506) with `IsCandidate: true`
    9. Return JSON response via `writeJSON(w, candidates)`

    Use the SQL pattern from RESEARCH.md Pattern 1 (DB-Only GetCandidatesByZip code example). Key adjustment: include `p.external_id AS external_id` in the SELECT for React key generation in the frontend.

    Also delete the `raceChamberName` and `levelToDistrictType` helper functions — they were only used by the old BallotReady-based GetCandidatesByZip and are now dead code. The new DB version gets district_type directly from the districts table.

    Remove the `ballotready` import from handlers.go if it is only used by the code being deleted in this task and the functions being deleted in Task 2. If other references remain (warmers, ensureCandidacyData), leave the import — it will be cleaned up in Plan 02.
