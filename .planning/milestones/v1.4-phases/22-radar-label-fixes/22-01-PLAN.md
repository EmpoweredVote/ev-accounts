<task type="auto">
  <name>Task 2: Implement dynamic horizontal padding for the SVG viewBox</name>
  <files>ev-ui/src/RadarChartCore.jsx</files>
  <action>
Replace the current static `padding` prop approach with dynamic horizontal padding that measures actual label widths:

**Approach — estimate-based dynamic padding (no DOM measurement needed):**

Since SVG `<text>` elements don't give us width before render, estimate label widths using character count and font size. This is the standard approach for SVG radar charts.

1. **Calculate per-label estimated width:**
   For each spoke label, after wrapping and font sizing:
   - `estimatedWidth = longestLineCharCount * fontSize * 0.6` (0.6 is a reasonable average character width ratio for Manrope/sans-serif at a given font size)

2. **Classify each label as left, right, or center:**
   - Left side: `angle > Math.PI` (these extend left of center)
   - Right side: `angle > 0 && angle < Math.PI` (these extend right of center)
   - Top/bottom (angle ≈ 0 or ≈ π): centered, no horizontal overflow

3. **Calculate required padding per side:**
   - `leftPadding = max(estimatedWidth for all left-side labels) + labelOffset`
   - `rightPadding = max(estimatedWidth for all right-side labels) + labelOffset`
   - Apply a minimum padding of 40px on each side so the chart never looks cramped

4. **Update the SVG viewBox:**
   Currently: `viewBox={`-${padding} -${padding} ${size + padding * 2} ${size + padding * 2}`}`

   Change to use asymmetric horizontal padding while keeping vertical padding symmetric:
   ```
   const verticalPadding = padding; // keep the existing prop for top/bottom
   viewBox={`-${leftPadding} -${verticalPadding} ${size + leftPadding + rightPadding} ${size + verticalPadding * 2}`}
   ```

   This widens the SVG horizontally to fit labels without changing the chart polygon size.

5. **Keep the `padding` prop as the base/vertical padding** (default 80). The new dynamic left/right padding overrides horizontal padding only. This maintains backward compatibility — callers don't need to change anything.

6. **Ensure the chart remains visually centered** within the SVG viewBox. Since the polygon center is at `(centerX, centerY) = (size/2, size/2)`, and the viewBox origin shifts by `-leftPadding`, the chart will appear centered as long as the SVG's `preserveAspectRatio="xMidYMid meet"` is maintained.

**Important:** The label position calculations (labelX, labelY) must NOT change — they're already correct relative to the chart center. Only the viewBox changes to give more room.
