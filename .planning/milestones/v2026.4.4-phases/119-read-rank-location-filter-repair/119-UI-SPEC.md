**zero-state empty message** required by D-06 (CONTEXT.md). All other visual work is
diagnostic and wiring — existing components are not restyled.

## Zero-State Empty Message — New Element

When `locationFilter !== null` and `filteredIssues.length === 0`, replace the issue card
list with this element. Do NOT auto-clear the filter.

### Visual Spec

Container: `max-w-2xl mx-auto`, `text-center`, `py-12`

Heading:
- Copy: "No issues with local quotes for this area"
- Font: Manrope, 15px, weight 700, color `#1a1a2e` ink
- Margin bottom: 8px

Body:
- Copy: "We don't have quotes from your representatives for any issues yet."
- Font: Manrope, 13px, weight 400, color `#64748b` warm-slate
- Line-height: 1.5
- Margin bottom: 16px

Clear filter button:
- Copy: "Clear location filter"
- Style: `.ev-button-secondary` class (border `1.5px solid #00657c`, color `#00657c`, background transparent, border-radius `0.5rem`, padding `0.5rem 1.5rem`)
- On click: calls `clearLocationFilter()` from Zustand store
- No confirmation required (non-destructive action — user can re-apply at any time)

Motion wrapper: `framer-motion` `<motion.div>` with `initial={{ opacity: 0, y: 8 }}`, `animate={{ opacity: 1, y: 0 }}`, `transition={{ duration: 0.3 }}` — consistent with existing IssueHub motion patterns.

## Interaction Contract

### Address Mode

1. User types in address input → Google Places autocomplete fires suggestions
2. User selects a suggestion → `onPlaceSelected(formattedAddress)` fires
3. Spinner appears inside input field (right-aligned)
4. `searchPoliticians()` POSTs to `/api/essentials/candidates/search`
5. On success with IDs: `setLocationFilter({ address, politicianIds })` → filter chip replaces input
6. On success with 0 IDs: inline warning "No representatives found with quotes for this address." shown for 3 seconds then auto-dismissed
7. Focus ring on input: `border-color #00657c` on focus, `#e8e2d9` on blur

### Browse Mode

1. State dropdown loads on mount from `/api/essentials/browse/states`
2. State selected → Area Type dropdown appears (loaded from `/api/essentials/browse/states/:state/areas`)
3. Area Type selected → Area Name dropdown appears (filtered client-side)
4. Area selected → "Apply Filter" button appears
5. "Apply Filter" clicked → `handleBrowse()` POSTs to `/api/essentials/browse/by-area`
6. Button shows "Loading..." and `opacity: 0.5` during request
7. On success: filter chip replaces entire input section
8. On failure: inline error text in `#e64a34`

### Filter Chip (active state)

- Location pin SVG icon (stroke `#00657c`) + truncated address (max 40 chars + ellipsis) + `&times;` dismiss
- Chip background: `#e8f4f6`
- Text: 14px, weight 400, color `#1a1a2e`
- Dismiss button: `aria-label="Remove location filter"`, `color #64748b` → `#1a1a2e` on hover

### Issue Count Subtitle (active filter)

- "Showing {N} of {M} issues" — 12px, weight 400, color `#64748b`, centered, shown only when `locationFilter !== null`

### Zero-State Transition

- When `filteredIssues.length` drops to 0 while filter is active: issue card list unmounts, zero-state message mounts with fade-up motion
- When filter is cleared: zero-state unmounts, all issues re-appear with existing staggered animation
