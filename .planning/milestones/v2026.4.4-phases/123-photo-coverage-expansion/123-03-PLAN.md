<interfaces>
Data contract — `import-123-data.json` MUST be an array of:

```typescript
interface CandidateImport {
  politician_id: string;   // UUID (validated by UUID_RE in the script)
  full_name: string;
  slug: string;             // from politicians.slug; used to build Storage filepath phase_123/{slug}.{ext}
  photo_source_url: string | null;  // null for NO_PHOTO rows
}
```

Load-bearing patterns (from 123-PATTERNS.md, copy verbatim from import-120-contested-bios-photos.ts):
- dotenv + pg.Pool + supabase-js client bootstrap
- `--commit` flag; default is dry-run
- UUID_RE validator
- `fetchImageBytes(url)` helper
- `detectExt(url)` helper — returns `{ ext, contentType }`; contentType is MANDATORY on upload (Pitfall 7)
- Pre-flight `detectUniqueConstraint()` on `essentials.politician_images` (2-column unique on (politician_id, type))
- Transaction-per-candidate (BEGIN / COMMIT / ROLLBACK on a dedicated client)
- Dual write (Pitfall 2): INSERT/UPSERT `politician_images` AND UPDATE `politicians.photo_custom_url`
- Storage filepath: `phase_123/${slug}.${ext}` (prefix MUST be `phase_123/`, not `phase_120/`)
- `upsert: true` on Storage upload

Drop from analog (photo-only per D-09):
- All `bio_text` reads/writes
- Bio length validation
- Slug-generation-from-name if the JSON already provides slug (it will)

NO_PHOTO handling (NEW): when `photo_source_url` is null, log `[skip] ${full_name} NO_PHOTO`, increment `stats.skipped`, perform zero DB writes. Frontend initials fallback handles render.
</interfaces>
