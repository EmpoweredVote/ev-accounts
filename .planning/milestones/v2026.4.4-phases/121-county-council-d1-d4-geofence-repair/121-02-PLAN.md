## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-121-02-01 | Tampering | Malformed GeoJSON from FeatureServer could trigger PostGIS exception on ST_GeomFromGeoJSON | mitigate | `ST_Force2D(ST_GeomFromGeoJSON(...))` throws cleanly on invalid geometry; wrap each feature insert in try/catch and increment an errors counter (per load-ca-state-boundaries.ts lines 207-210 precedent). Pre-validation in fetch script (feature count, SRS, bbox sanity) reduces surface |
| T-121-02-02 | Tampering | SQL injection via CountyCouncil field from external source | mitigate | All DB calls use `pg` parameterized queries (`$1, $2, …` placeholders) per load-ca-state-boundaries.ts pattern; the string "1"-"4" is concatenated only into `geoId` / `districtId` literals, which are then passed as parameters — never concatenated into SQL text directly |
| T-121-02-03 | Denial of Service | FeatureServer unreachable during import | accept | Fetch script exits non-zero on any HTTP failure; import script fails fast if evidence file missing with clear message. No automatic retry loops that could hammer the county server |
| T-121-02-04 | Information Disclosure | DATABASE_URL secret leaking into logs | mitigate | Scripts use `dotenv/config` to load `.env` which is gitignored per project convention; no `console.log(process.env)` calls permitted |
| T-121-02-05 | Tampering | Re-using geo_id='18105' (the county-wide polygon) for per-district rows would cause ST_Covers double-match | mitigate | Acceptance criteria grep-check: the county-wide row `(18105, G4020)` MUST still exist post-import, and the new rows MUST use `18105-mcc-d{N}` with mtfcc `X-MCC-DISTRICT`. Pitfall 1 in RESEARCH.md explicitly called this out |
| T-121-02-06 | Elevation of Privilege | Import script running against PROD DB by accident | accept | DATABASE_URL is controlled by the developer's local `.env`. Standard project practice (Phase 118/119 precedent) is DEV-first, PROD only after Render deploy. Plan 04 handles the prod verification gate |
</threat_model>
