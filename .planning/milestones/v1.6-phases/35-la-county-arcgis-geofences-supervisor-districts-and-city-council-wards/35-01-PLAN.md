**1. Schema change — widen geo_id and add quality_flag (geofence_models.go):**

The `GeoID` field in `GeofenceBoundary` struct currently has `gorm:"size:50"`. OCD-ID strings like `ocd-division/country:us/state:ca/place:los_angeles/council_district:1` are ~68 chars and will be truncated. Change to `gorm:"size:255"` to match the OCDID field's size. GORM AutoMigrate will widen the column on next server start.

Add a `QualityFlag` field to GeofenceBoundary:
```go
QualityFlag string `json:"quality_flag,omitempty"` // NULL=clean, "geometry_repaired", "source_outdated", etc.
```
Place it in the Metadata section after `ImportedAt`. No `gorm:` size tag needed — defaults to text.

**IMPORTANT:** After modifying the model, run `cd EV-Backend && go build -o /dev/null .` to verify the Go code compiles. Do NOT start the server (no DATABASE_URL available).


**3. Create ArcGIS import script (import_arcgis_geofences.py):**

Follow the canonical pattern from `import_ca_place_boundaries.py` with these key differences:
- Reads source URLs and field names from `arcgis_sources.json` instead of hardcoded TIGER URLs
- Uses HTTP fetch (requests) instead of shapefile download
- Uses delete-before-insert pattern (not upsert) for idempotent re-runs
- Applies `shapely.validation.make_valid()` to every geometry, sets `quality_flag = 'geometry_repaired'` when repair needed
- geo_id is OCD-ID format string (from `geo_id_template.format(n=district_num)`)
- Also sets `ocd_id` to the same OCD-ID string (for X0001 boundaries, geo_id = ocd_id)

Script structure:
```python
#!/usr/bin/env python3
"""
Import geofence boundaries from ArcGIS FeatureServer endpoints.
Reads source configuration from arcgis_sources.json.
"""
```

Key functions:
- `fetch_arcgis_geojson(url, retries=3)` — HTTP fetch with exponential backoff (1s, 2s), returns parsed JSON or None
- `load_config()` — loads `arcgis_sources.json` from same directory
- `import_supervisor_districts(engine, config)` — fetches supervisor data, builds GeoDataFrame with geo_id from template, delete-before-insert
- `import_city_council(engine, entry)` — for a single city_council config entry, fetches data, builds GeoDataFrame, delete-before-insert. Skips entries with `source_url` of `"TBD"` or `null` or `election_type` of `"at-large"`
- `import_all(engine)` — orchestrates: supervisors first, then each city_council entry, reports summary with counts and failures
- `verify_import(engine)` — verification queries:
  - Count supervisor X0001 records (expected: 5)
  - Count LA City council X0001 records (expected: 15)
  - ST_IsValid check on all new X0001 records
  - Point-in-polygon test at LA City Hall (34.0537, -118.2427) — should hit both supervisor and council ward
  - Point-in-polygon test at Compton (unincorporated, 33.8958, -118.2201) — should hit supervisor but NOT council ward
  - geo_id join test: `SELECT gb.geo_id, d.ocd_id FROM geofence_boundaries gb JOIN essentials.districts d ON gb.geo_id = d.ocd_id WHERE gb.mtfcc = 'X0001'` — confirms geo_ids match existing district records

For the GeoDataFrame columns, include: `geo_id`, `ocd_id`, `name`, `mtfcc`, `state`, `geometry`, `source`, `imported_at`, `quality_flag`.

**Critical implementation details:**
- The `district_field` for LA County supervisors is a STRING ("1"-"5"), not integer. For LA City council, `district` is an INTEGER (1-15). The `int()` conversion in `geo_id_template.format(n=int(district_num))` handles both cases.
- Always append `&outSR=4326` to ArcGIS URLs (already in config URLs) — without this, LA County MapServer returns California State Plane coordinates.
- Apply `make_valid()` BEFORE building the GeoDataFrame, not after.
- Use `from utils import get_engine, load_env` with the standard `sys.path.insert(0, str(Path(__file__).parent))` pattern.

Run the script after creation to import supervisor districts and LA City council wards.
