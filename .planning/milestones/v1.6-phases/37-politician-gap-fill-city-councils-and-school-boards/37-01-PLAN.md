Create `EV-Backend/scripts/city_sources.json` with entries for all 87 incorporated LA County cities (excluding City of Los Angeles, already covered in Phase 36).

Structure each entry following the pattern from 37-RESEARCH.md Pattern 2:
```json
{
  "cities": [
    {
      "id": "burbank_city_council",
      "name": "City of Burbank",
      "place_geoid": "0608954",
      "election_type": "at-large",
      "district_type": "LOCAL",
      "title": "Council Member",
      "mayor_title": "Mayor",
      "state": "CA",
      "expected_council_count": 5,
      "has_mayor": true,
      "ocd_id_base": "ocd-division/country:us/state:ca/place:burbank",
      "ocd_id_template": "ocd-division/country:us/state:ca/place:burbank/council_district:{n}",
      "url": "https://www.burbankca.gov/government/city-council",
      "status": "pending",
      "failure_reason": null
    }
  ]
}
```

Key fields per city:
- `place_geoid`: 7-char Census GEOID from Phase 34 G4110 import. Query `SELECT geo_id, name FROM essentials.geofence_boundaries WHERE mtfcc = 'G4110' AND name ILIKE '%burbank%'` to verify each city's GEOID.
- `election_type`: "at-large" or "district". For cities with X0001 ward geofences already imported in Phase 35 (Long Beach, Pasadena, Torrance, Inglewood, West Covina, Glendale), set "district". For cities known to have switched to district elections via CVRA but without ward geofences, set "at-large" (they'll use G4110 boundary; ward geofences can be added later). When in doubt, default to "at-large".
- `ocd_id_base`: The city-level OCD-ID (used for at-large and mayor). Pattern: `ocd-division/country:us/state:ca/place:{place_name_lowercase_underscored}`
- `ocd_id_template`: For district cities only. Pattern: `ocd-division/country:us/state:ca/place:{place_name}/council_district:{n}`
- `url`: City's official council page URL. Can be null if unknown — SOS PDF is the primary source.

The list of 87 cities comes from the G4110 boundaries imported in Phase 34. Query:
```sql
SELECT geo_id, name FROM essentials.geofence_boundaries
WHERE mtfcc = 'G4110' AND state = 'CA'
AND geo_id IN (
  -- LA County cities; filter by bounding box or county match
  SELECT gb.geo_id FROM essentials.geofence_boundaries gb
  WHERE gb.mtfcc = 'G4110'
)
ORDER BY name;
```

If the exact LA County city list is hard to determine from geofences alone, use the known list of 88 incorporated LA County cities minus Los Angeles.

For each entry, `status` starts as "pending". After scraping, it transitions to "scraped" or "failed" with a `failure_reason`.

SOS PDF data can pre-populate the `roster` field with extracted names:
```json
"roster": [
  {"name": "Jess Talamantes", "district": 0, "party": "", "role": "Mayor"},
  {"name": "Zizette Mullins", "district": 0, "party": "", "role": "Council Member"}
]
```

For at-large cities, `district: 0` for all members. For district cities, `district: N` per ward number.

Create `EV-Backend/scripts/scrape_city_councils.py` — a batch scraper for all 87 LA County city councils.

**Architecture:**
- Reads `city_sources.json` for city list
- Primary data source: CA SOS Roster PDF (extracted in Task 1, names pre-populated in roster field of config)
- Fallback: per-city website scraping with requests + BeautifulSoup, then Playwright for JS-heavy sites
- Per-source COMMIT (not global transaction) — prevents one failed city from rolling back all progress
- Reuses core functions from `scrape_la_officials.py`: `get_connection()`, `find_existing_politician_for_seat()`, `upsert_politician()`, `normalize_party()`, `split_name()`, `verify_no_duplicates()`

**Key functions to implement:**

1. `extract_cities_from_sos_pdf(pdf_path)` — Uses pdfplumber to extract city-by-city council member lists from the SOS PDF. Returns dict mapping city_name -> list of {name, role} dicts. Per RESEARCH.md Pitfall 2: handle both at-large (plain member list) and district (numbered entries) formats. Per Pitfall 7: validate extracted names (2+ words, starts with capital).

2. `fetch_html_with_fallback(url, timeout=15)` — Try requests first; fall back to Playwright if response has <500 chars of body text (JS-rendered indicator). Per RESEARCH.md Pattern 3. Import playwright lazily (`from playwright.sync_api import sync_playwright`) to avoid import error if chromium not installed.

3. `parse_generic_council_page(html, source_config)` — Per RESEARCH.md Pattern 4: generic parser handling common CMS patterns (tables, card layouts, list items with council member names). Extract name + district number when present.

4. `process_city(conn, city_config)` — Per-city processing:
   a. If city has a pre-populated `roster` field (from SOS PDF), use that directly
   b. Else if city has a `url`, fetch and parse the website
   c. For each official in the roster:
      - For at-large cities: `geo_id = place_geoid` (G4110 Census GEOID)
      - For district cities: `geo_id = ocd_id` (from template)
      - Mayor always gets `district_type = LOCAL_EXEC`, `geo_id = place_geoid`
   d. Call `find_existing_politician_for_seat()` for dedup (import from scrape_la_officials or copy the function)
   e. Call `upsert_politician()` or equivalent to insert/update
   f. COMMIT after each city succeeds; update `status` in city_sources.json
   g. On failure: rollback, set `status = "failed"`, log `failure_reason`, continue to next city

5. `find_or_create_city_chamber(cur, city_config)` — Create chamber for this city's council. Pattern: `"{City Name} City Council"` as chamber_name.

6. `find_or_create_city_district(cur, city_config, official_data)` — For at-large: one district per city with `geo_id = place_geoid`. For district cities: per-ward districts with `geo_id = ocd_id`.

**geo_id assignment rules (CRITICAL — per RESEARCH.md Pitfall 1):**
- At-large city council members: ALL share `geo_id = place_geoid` (the G4110 Census GEOID, e.g., "0608954" for Burbank). This joins to the G4110 boundary imported in Phase 34.
- District city council members: Each gets `geo_id = ocd_id` per their ward. This joins to X0001 boundaries imported in Phase 35.
- Mayors (all cities): `district_type = LOCAL_EXEC`, `geo_id = place_geoid`. Same G4110 boundary.

**Per-source commit pattern (CRITICAL — per RESEARCH.md Pitfall 6):**
```python
for city in cities:
    conn.autocommit = False
    try:
        process_city(conn, city)
        conn.commit()
        city["status"] = "scraped"
    except Exception as e:
        conn.rollback()
        city["status"] = "failed"
        city["failure_reason"] = str(e)
```

**Data quality rules (per CONTEXT.md):**
- Minimum viable record: name + seat only
- Party = "Nonpartisan" for cities where party is unknown (most city councils are nonpartisan)
- `data_source` = SOS PDF URL or city website URL
- `source` = "scraped"
- `is_active` = true

**Dedup rules (reuse Phase 36 patterns):**
- Seat-first: match on ocd_id + title
- Exact name match -> UPDATE
- Fuzzy last-name match (Levenshtein <= 1) -> UPDATE
- New person in seat -> deactivate old, INSERT new
- No seat found -> CREATE district + chamber + office + politician
