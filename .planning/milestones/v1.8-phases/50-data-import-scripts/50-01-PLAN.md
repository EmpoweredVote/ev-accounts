## Goal
A `./server import-stances` CLI subcommand exists that reads `data/stance_research.csv`, validates every row, resolves politician full_name to `essentials.politicians.id`, resolves topic_key to `compass.topics.id`, and upserts rows into `compass.answers` (with source URLs stored in `compass.contexts`). Safe to re-run (upsert semantics). Invalid rows are skipped with warnings; a summary is printed at the end.

## Context
- The stance CSV has 455 data rows (23 politicians, 21 topics) with columns: `full_name,external_id,topic_key,value,source_url_1,source_url_2,source_url_3`
- `compass.answers` has fields: ID (string PK), PoliticianID (uuid), UserID (string), TopicID (uuid), Value (float64), WriteInText, CreatedAt
- `compass.contexts` has fields: ID (string PK), PoliticianID (uuid), UserID (string), TopicID (uuid), Reasoning (string), Sources (text[])
- The existing `compass.answers` table stores politician stances with `politician_id` and `value` (float64, where 1-5 maps to stances)
- Source URLs should be stored in `compass.contexts.Sources` array for audit trail and display
- Current main.go is a pure HTTP server; it needs a subcommand check before starting the server
- Politician lookup: exact `full_name` match against `essentials.politicians`; if external_id is present in CSV, use as fallback
- Topic lookup: `topic_key` match against `compass.topics.topic_key`

## Tasks

<task id="50-01-01" title="Create stance import package">
Create `EV-Backend/internal/stanceimport/csv.go`:

1. Define `StanceRow` struct with fields: `FullName`, `ExternalID` (string, may be empty), `TopicKey`, `Value` (int), `SourceURLs` ([]string, up to 3)
2. Create `ParseCSV(path string) ([]StanceRow, error)` function:
   - Open file, create csv.Reader with `LazyQuotes: true` (quote_text in the CSV may contain commas)
   - Read header row, build column index map
   - Required columns: `full_name`, `topic_key`, `value`
   - Optional columns: `external_id`, `source_url_1`, `source_url_2`, `source_url_3`
   - For each data row: parse value as int, collect non-empty source URLs into slice
   - Return all parsed rows (validation happens in the import step)

Create `EV-Backend/internal/stanceimport/import.go`:

1. Define `Config` struct: `CSVPath string`, `DryRun bool`
2. Define `ImportResult` struct: `Processed int`, `Inserted int`, `Updated int`, `Skipped int`, `Errors []string`
3. Create `Run(cfg Config) (*ImportResult, error)` function:
   - Use `db.DB` (the global GORM connection from `internal/db`) -- do NOT open a new connection
   - Load all `compass.Topic` records, build `map[string]uuid.UUID` keyed by `topic_key`
   - Load all `essentials.Politician` records (just `id`, `full_name`, `external_id`), build `map[string]uuid.UUID` keyed by `full_name`; also build `map[int]uuid.UUID` keyed by `external_id` for fallback
   - **Detect ambiguous names:** After building the full_name map, make a second pass over the politicians to find names that appear more than once. Build a `map[string]bool` (`ambiguousNames`) containing any `full_name` that maps to more than one politician ID. Implementation: iterate politicians, track counts in a `map[string]int`; any name with count > 1 goes into `ambiguousNames`. (Note: the `map[string]uuid.UUID` silently overwrites on duplicates, so the ambiguous set is the safety net.)
   - Parse CSV via `ParseCSV(cfg.CSVPath)`
   - For each row:
     a. **Validate** value is 1-5; if not, add error `"row N: value X out of range 1-5"`, increment Skipped, continue
     b. **Validate** topic_key exists in topics map; if not, add error `"row N: unknown topic_key 'X'"`, increment Skipped, continue
     c. **Check ambiguous name**: if `full_name` is in `ambiguousNames`, add error `"row N: ambiguous politician name 'X' — multiple matches in database"`, increment Skipped, continue
     d. **Resolve politician**: try `full_name` map first; if not found and `external_id` is non-empty, try external_id map (parse as int); if neither, add error `"row N: politician 'X' not found"`, increment Skipped, continue
     e. If `cfg.DryRun`, increment Processed, continue (no DB write)
     f. **Upsert answer**: query `compass.answers` WHERE `politician_id = ? AND topic_id = ?`; if found, update `value`; if not found, create new with `uuid.NewString()` as ID, `PoliticianID`, `TopicID`, `Value` (as float64)
     g. **Upsert context**: query `compass.contexts` WHERE `politician_id = ? AND topic_id = ?`; if found, update `Sources` array; if not found, create new with `uuid.NewString()` as ID, `PoliticianID`, `TopicID`, empty `Reasoning`, and `Sources` = collected source URLs
     h. Increment Inserted or Updated accordingly
   - Return the result

4. At the end of `Run`, print summary: `"Processed: N, Inserted: N, Updated: N, Skipped: N"`
5. If there are errors, print each on its own line prefixed with `"ERROR: "`
</task>

<task id="50-01-02" title="Wire CLI subcommand into main.go">
Modify `EV-Backend/main.go` to support CLI subcommands before starting the HTTP server:

1. Add import for `"github.com/EmpoweredVote/EV-Backend/internal/stanceimport"`
2. After `db.Connect()` and before the router setup, check `os.Args` for subcommands:
   ```go
   if len(os.Args) > 1 {
       switch os.Args[1] {
       case "import-stances":
           csvPath := "data/stance_research.csv"
           dryRun := false
           if len(os.Args) > 2 {
               csvPath = os.Args[2]
           }
           // Check for --dry-run flag anywhere in args
           for _, arg := range os.Args[2:] {
               if arg == "--dry-run" {
                   dryRun = true
               }
           }
           result, err := stanceimport.Run(stanceimport.Config{
               CSVPath: csvPath,
               DryRun:  dryRun,
           })
           if err != nil {
               log.Fatal("import-stances failed: ", err)
           }
           fmt.Printf("Import complete: %d processed, %d inserted, %d updated, %d skipped\n",
               result.Processed, result.Inserted, result.Updated, result.Skipped)
           os.Exit(0)
       }
   }
   ```
3. The compass.Init() and essentials.Init() calls must happen BEFORE the subcommand check so tables are migrated and available
4. The existing server behavior is unchanged when no subcommand is provided
</task>
