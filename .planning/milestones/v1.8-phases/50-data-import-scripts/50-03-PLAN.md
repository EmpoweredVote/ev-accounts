## Goal
A public API endpoint serves quotes from `essentials.quotes` in the format Read & Rank expects, and the Read & Rank frontend fetches quotes, candidates, and issues from the API instead of hardcoded `mockData.ts`. The end-to-end flow works: CSV loaded into DB (Plan 02), DB served via API (this plan), Read & Rank consumes API.

## Context
- Read & Rank `Quote` interface: `{ id: string, text: string, candidateId?: string, issue: string, sourceUrl?: string, sourceName?: string }`
- Read & Rank `Candidate` interface: `{ id: string, name: string, party: string, office: string, photo: string, alignmentPercent: number, issuesAligned: number, totalIssues: number }`
- Read & Rank `IssueData` interface: `{ id: string, title: string, question: string }`
- The `essentials.quotes` table (created in Plan 02) has: politician_id, topic_key, quote_text, source_url, source_name
- The existing `essentials.politicians` table has full_name, party, photo_origin_url, photo_custom_url
- The existing `essentials.offices` table has title (office title)
- The existing `compass.topics` table has topic_key, title, question_text
- Read & Rank currently imports from `../data/mockData` in 3 files: IssueHub.tsx, ResultsPhase.tsx, CandidateAlignmentPage.tsx
- No VITE_API_URL env var exists yet in Read & Rank -- the API base URL needs to be configurable
- The API should return data shapes compatible with the existing TypeScript interfaces so the store doesn't need changes

## Tasks

<task id="50-03-01" title="Add quotes API endpoint to essentials">
Add a public endpoint to `EV-Backend/internal/essentials/` that serves quotes grouped for Read & Rank:

1. In `EV-Backend/internal/essentials/handlers.go`, add a `GetQuotes` handler:
   - Route: `GET /essentials/quotes`
   - Query the `essentials.quotes` table joined with `essentials.politicians` (for full_name, party, photo_origin_url, photo_custom_url) and `essentials.offices` (for title as office_title)
   - Also query `compass.topics` to get all topic_keys that have quotes, with their title and question_text
   - Build a response JSON with three top-level arrays:
     ```json
     {
       "quotes": [
         {
           "id": "<uuid>",
           "text": "<quote_text>",
           "candidateId": "<politician_id as string>",
           "issue": "<topic_key>",
           "sourceUrl": "<source_url>",
           "sourceName": "<source_name>"
         }
       ],
       "candidates": [
         {
           "id": "<politician_id as string>",
           "name": "<full_name>",
           "party": "<party>",
           "office": "<office_title>",
           "photo": "<photo_custom_url or photo_origin_url>",
           "alignmentPercent": 0,
           "issuesAligned": 0,
           "totalIssues": <number of distinct topics for this candidate>
         }
       ],
       "issues": [
         {
           "id": "<topic_key>",
           "title": "<topic.title>",
           "question": "<topic.question_text>"
         }
       ]
     }
     ```
   - Use DISTINCT ON politician_id for the candidates array (one entry per politician)
   - Use DISTINCT ON topic_key for the issues array
   - The SQL should efficiently join tables. **IMPORTANT:** Politicians may have multiple office records (e.g., held multiple positions). Use `LEFT JOIN LATERAL` with `LIMIT 1` to pick one office per politician and avoid duplicating quote rows. Example approach:
     a. Query all quotes with politician join: `SELECT q.id, q.quote_text, q.politician_id, q.topic_key, q.source_url, q.source_name, p.full_name, p.party, COALESCE(p.photo_custom_url, p.photo_origin_url, '') as photo, o.title as office_title FROM essentials.quotes q JOIN essentials.politicians p ON p.id = q.politician_id LEFT JOIN LATERAL (SELECT title FROM essentials.offices WHERE politician_id = p.id ORDER BY id DESC LIMIT 1) o ON true`
     b. Build candidate map from unique politician_ids seen
     c. Query compass.topics for matching topic_keys

2. In `EV-Backend/internal/essentials/routes.go`, add the route in the public section:
   ```go
   r.Get("/quotes", GetQuotes)
   ```
   Place it after the existing `r.Get("/politician/{id}/elections", ...)` line.
</task>

<task id="50-03-02" title="Create API client and update Read & Rank frontend">
Create an API client module and update all Read & Rank components to fetch data from the API:

1. Create `EV-prototypes/read-rank/src/data/api.ts`:
   ```typescript
   import type { Quote, Candidate, IssueData } from '../store/useReadRankStore';

   const API_BASE = import.meta.env.VITE_API_URL || 'https://api.empowered.vote';

   interface QuotesResponse {
     quotes: Quote[];
     candidates: Candidate[];
     issues: IssueData[];
   }

   let cachedData: QuotesResponse | null = null;

   export async function fetchQuotesData(): Promise<QuotesResponse> {
     if (cachedData) return cachedData;

     try {
       const res = await fetch(`${API_BASE}/essentials/quotes`);
       if (!res.ok) throw new Error(`API error: ${res.status}`);
       const data: QuotesResponse = await res.json();
       cachedData = data;
       return data;
     } catch (err) {
       console.error('Failed to fetch quotes from API, falling back to mock data', err);
       // Fallback to mock data for offline/dev use
       const { allIssues, mockQuotes, mockCandidates } = await import('./mockData');
       return {
         quotes: mockQuotes,
         candidates: mockCandidates,
         issues: allIssues,
       };
     }
   }

   export function getQuotesForIssue(quotes: Quote[], issueId: string): Quote[] {
     return quotes.filter(q => q.issue === issueId);
   }

   export function getCandidateById(candidates: Candidate[], id: string): Candidate | undefined {
     return candidates.find(c => c.id === id);
   }
   ```

2. Update `EV-prototypes/read-rank/src/components/IssueHub.tsx`:
