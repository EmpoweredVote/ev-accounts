# Milestone v2026.4.5: Compass-First Politician Card

**Status:** ✅ SHIPPED 2026-04-26
**Phases:** 127–129
**Total Plans:** 9 (of 10 scoped; 128-04 folded into Phase 129 execution)

## Overview

Promoted the compass-first horizontal politician card from the `/prototype` harness into full production across Essentials Representatives and Elections pages. The new `CompassCardHorizontal` / `CompassCardVertical` component was published in `@empoweredvote/ev-ui` with a dual-view toggle (compass radar ↔ portrait), full affordance parity with the legacy PoliticianCard, and a variant system covering empty-compass, administrative, and judicial card states. The prototype route and all prototype-only components were retired from Essentials. ev-ui v0.6.1 was shipped via the auto-bump pipeline and confirmed rendering on both essentials and CompassV2.

## Phases

### Phase 127: CompassCardHorizontal in ev-ui

**Goal**: A production-ready horizontal compass-first card component is available in `@empoweredvote/ev-ui` with view toggle and full metadata parity with the existing PoliticianCard.
**Depends on**: Nothing (first phase of milestone)
**Requirements**: CARD-01, CARD-02, CARD-03

Plans:

- [x] 127-01-PLAN.md — Scaffold @floating-ui peer dep + port PlaceholderRadar + port IconOverlay (leaf primitives)
- [x] 127-02-PLAN.md — Build CompassCardHorizontal + Meta + compassHelpers; add barrel exports
- [x] 127-03-PLAN.md — Update essentials Prototype harness + view toggle persistence + human-verify checkpoint

**Details:**

Scaffolded `PlaceholderRadar` (dashed SVG octagon for empty-compass state), `IconOverlay` (floating-ui tooltip badges for BallotIcon/CompassIcon/BranchIcon), and `CompassCardHorizontal` — a horizontal layout with radar slot on the left (~260px) and politician metadata on the right. `compassHelpers.js` provides `computeCompassScore`, `buildUserAnswersMap`, and `SLOT_WIDTH`. A `SegmentedControl` view toggle switches between compass (radar) and portrait (photo) views with localStorage persistence. Full affordance parity: tier/branch badges, elected/appointed marker, unopposed overlay, term dates, years-in-office, chamber/district subtitle, initials fallback.

## Milestone Summary

**Known Gaps at Close:**

- Phase 128-04 (formal plan never executed): ev-ui minor version bump with new public API was done as part of Phase 129 execution (v0.6.1) rather than as a standalone plan. ADOPT-04 verified complete via Phase 129.
- CARD-01/02/03 and STATE-01/02/03 requirement checkboxes in REQUIREMENTS.md were never updated — stale. Functional requirements all satisfied; checkboxes acknowledged as known gap at milestone close.
- STATE-02 (administrative plate) and STATE-03 (judicial plate) ship with a generic "unavailable" portrait plate; role-specific content (retention history, court level, etc.) was descoped during discuss-phase.

**Key Decisions:**

- CompassCardHorizontal exported as both `CompassCardHorizontal` and `CompassCardVertical` from ev-ui (same component, vertical viewport integration alias) — both names work, essentials uses `CompassCardVertical`
- View toggle persistence: localStorage per page (not per user preference across devices) — simpler, sufficient for demo confidence
- 128-04 scope folded into Phase 129: no separate minor-version bump plan needed since Phase 129 did the ev-ui tag push

**Technical Debt Carried Forward:**

- `CompassCardVertical` alias in ev-ui exports creates a confusing dual-name export — should consolidate naming in a future cleanup
- Administrative and judicial card plates show generic "unavailable" text; role-specific content (court level, retention history for judges; office description for admins) deferred
