## Tech Debt

### Phase 15: Uncalled backend routes (non-critical)

- `PATCH /api/admin/compass/politicians/:id` — exists in admin.ts, no React UI caller. `PoliticianDetailPanel` shows profile data but provides no edit form for `office_title`, `full_name`, `is_active`, `is_candidate`. Backend is ready; UI form was not in Phase 15 scope.
- `GET /api/admin/compass/categories` — exists in admin.ts, uncalled by any React page. `CategoriesPage.tsx` uses public `/compass/categories` instead (intentional: public route returns nested topic data needed by the UI). Admin-only list route is reachable but has no current consumer.

### Phase 15: Human verification required (live DB)

Three items cannot be confirmed without a running backend and seeded database:
1. Stance editor inputs populate with current stance text after topic selection
2. StanceSelector RadioGroup renders five option buttons in politician answer rows
3. Full create-topic → toggle live → GET /api/compass/topics round-trip

### Phase 13: Runtime concern (non-critical)

- `saveSelectedTopics` in `compassService.ts` calls `JSON.stringify(topicIds)` before storing to `connected_profiles.selected_topic_ids`. If the column is `jsonb`, this may cause double-serialization at runtime. Verify against live DB column type before Alpha user onboarding.

### Cross-phase: Migration deployment path

- Migrations 026–029 live in `backend/migrations/` and must be applied manually to the Supabase database. They are not tracked in `supabase/migrations/` for Supabase CLI application. Consistent with project practice, but requires explicit deploy runbook step.
