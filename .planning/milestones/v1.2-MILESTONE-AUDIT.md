## Cross-Phase Integration Issues

### DELETE /compass/answers/me Behind Admin Middleware (Medium)

**From:** Phase 14 — `Compass.jsx:446` `handleResetCompass` and `Layout.jsx:41` `handleClearCompass`
**To:** `EV-Backend/internal/compass/routes.go:39` — `DELETE /compass/answers/me` inside AdminMiddleware group

Non-admin logged-in users who click "Reset compass" receive 403. localStorage and context state are cleared first (before the fetch), so the client shows an empty compass but the server retains answers. On refresh or re-login, old answers reappear.

**Impact:** Medium. Guest users (primary v1.2 audience) are unaffected — no server state to delete. Only logged-in non-admin users hit this. No v1.2 requirement explicitly mandates reset-for-all-users. Backend changes are out of v1.2 scope.

**Fix:** Move `r.Delete("/answers/me", DeleteMyAnswersHandler)` from the admin group (lines 30-40) to the session-only group (lines 21-29) in `routes.go`.

### HelpGuard / completed_onboarding Desync (Low)

**From:** Phase 15 — `App.jsx:21-33` HelpGuard reads `localStorage.help_seen`
**To:** Phase 15 — `Login.jsx` reads `completed_onboarding` from `/auth/me`

Two parallel onboarding-state systems that never synchronize. Returning logged-in users on new devices see /help again because `help_seen` is absent from localStorage even though `completed_onboarding` is true in DB.

**Impact:** Low. Not a hard break — /help works correctly. The show-once intent is defeated only for cross-device or incognito sessions.

**Fix:** After auth check in CompassContext, if `completed_onboarding === true`, seed `localStorage.setItem("help_seen", "true")`.

### Unused Import (Cosmetic)

`Router` imported but unused in `App.jsx` line 2. No functional impact.
