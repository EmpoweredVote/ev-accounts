<objective>
Make logged-in users mirror their writes (compass answers, address, read-rank verdicts) into ev-context so they get the same instant cross-subdomain hydration that guests already enjoy. The API remains source of truth — ev-context is a stale-while-revalidate cache for authed users, gated by userId stamping so cached data can't leak across user switches.

Purpose: Closes the second of four "ev-context follow-ups" in CLAUDE.md. Today only guests benefit from cross-subdomain hydration; authed users see a blank UI on each subdomain until the API resolves. Mirroring the three named domains gives authed users parity without changing the source-of-truth model.

Output: Updated `@empoweredvote/ev-ui` (with new authed-slice helpers on `evContext`) plus wired call sites in CompassV2, essentials, read-rank, and treasury-tracker.
</objective>


<!-- New surface (this plan adds) -->
```js
// Top-level stored shape becomes:
//   { compass?, address?, verdicts?, authed?: { userId, compass?, address?, verdicts? } }
//
// Guest slice = top-level compass/address/verdicts (unchanged contract).
// Authed slice = single `authed` object stamped with userId.

evContext.getAuthedSlice(userId: string): Promise<{ compass?, address?, verdicts? } | null>
// Reads the `authed` key, returns its body iff stored userId === requested userId, else null.

evContext.setAuthedSlice(userId: string, patch: { compass?, address?, verdicts? }): Promise<boolean>
// Reads current full value, writes back: { ...current, authed: { userId, ...(current.authed?.userId === userId ? current.authed : {}), ...patch } }
// Stomps the existing authed slice if its userId differs (user switch).
// Preserves guest slice (compass/address/verdicts at top level) untouched.

evContext.clearAuthedSlice(): Promise<boolean>
// Optional convenience; not required by any consumer in this plan (logout intentionally does NOT wipe — slice goes inert via userId mismatch). Provide it but don't call it from consumers.
```

Implement:

1. `async getAuthedSlice(userId)`:
   - Calls existing `this.get()`.
   - If result is null or `result.authed` is missing → return `null`.
   - If `result.authed.userId !== userId` → return `null` (mismatch = inert per D-03).
   - Else return `{ compass: result.authed.compass, address: result.authed.address, verdicts: result.authed.verdicts }` (omit undefined keys).

2. `async setAuthedSlice(userId, patch)`:
   - `patch` is `{ compass?, address?, verdicts? }`. Reject (return false) if `userId` is falsy or `patch` contains no recognized key.
   - Read current full value via `this.get()`.
   - Determine prior authed body: if `current.authed?.userId === userId`, keep its existing keys; otherwise treat as empty (user-switch = stomp).
   - Compose `nextAuthed = { userId, ...priorAuthedBody, ...patch }`.
   - Write `{ ...current, authed: nextAuthed }` via `this.set(...)`. Guest top-level keys are preserved untouched.

3. `async clearAuthedSlice()`:
   - Read current, write back with `authed` removed (use destructure-omit).
   - Provided for completeness; consumers in this plan must NOT call it on logout (D-03 says logout leaves the slice inert via userId mismatch).
