# Phase quick Plan 260404-t49: Ballot Tooltip Show Primary Date Summary

**One-liner:** Backend LATERAL join against essentials.races/elections surfaces per-office next_primary_date and next_general_date; frontend ballotStatus utility prioritizes real DB dates over heuristic term-end computation, showing "Primary: May 5, 2026" or "General: Nov 3, 2026" in ballot tooltips.

## What Was Built

**Backend (ev-accounts):**
- Added `UPCOMING_ELECTIONS_LATERAL` constant — a reusable LEFT JOIN LATERAL subquery that fetches `MIN(next_primary_date)` and `MIN(next_general_date)` from `essentials.races` joined to `essentials.elections`, filtered to `election_date >= CURRENT_DATE` for a given office (`r2.office_id = o.id`).
- Added `next_primary_date: string` and `next_general_date: string` to both `PoliticianFlatRecord` and `PoliticianDetail` interfaces.
- Wired the lateral join + SELECT columns into all 6 politician list queries: browse, district (getRepresentativesByAddress), statewide (getRepresentativesByAddress), getRepresentativesByJurisdiction (district + statewide via shared JOINS constant), and getLocalOfficialsByUserId.
- Wired into `getPoliticianById` base query for the detail endpoint.
- Updated all mapping blocks to include `next_primary_date` and `next_general_date`.

**Frontend (essentials):**
- Refactored `getSeatBallotStatus` to accept `nextPrimaryDate` and `nextGeneralDate` params with 3-priority logic: real primary > real general > heuristic fallback. Real-date paths bypass the 1-year guard. All return paths include `electionLabel`.
- Updated `IconOverlay.jsx` tooltip to use `ballot.electionLabel` as the label prefix and added `day: 'numeric'` for full date display (e.g., "Primary: May 5, 2026").
- Updated `Results.jsx`, `Profile.jsx`, and `PoliticianGrid.jsx` to pass `pol.next_primary_date` and `pol.next_general_date` to `getSeatBallotStatus`.
