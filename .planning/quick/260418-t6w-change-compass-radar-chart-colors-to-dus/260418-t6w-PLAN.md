Edit `ev-ui/src/RadarChartCore.jsx`:

1. **User polygon color swap (4 style objects to update — both `countChanged` branches use same styles, so update both the static `<polygon key="user-static">` and animated `<animated.polygon key="user-animated">`):**
   - Change `fill: 'rgba(255, 87, 64, 0.4)'` → `fill: 'rgba(124, 107, 158, 0.4)'`
   - Change `stroke: 'rgb(255, 87, 64)'` → `stroke: '#7C6B9E'`
   - Keep `strokeWidth: 3`.

2. **Compare polygon color swap (both static `<polygon key="compare-static">` and animated `<animated.polygon key="compare-animated">`):**
   - Change `fill: 'rgba(89, 176, 196, 0.3)'` → `fill: 'rgba(90, 154, 110, 0.3)'`
   - Change `stroke: 'rgb(89, 176, 196)'` → `stroke: '#5A9A6E'`
   - Keep `strokeWidth: 2`.

3. **Render vertex dots with white border.** After the user polygon block but before the compare polygon block (i.e., dots sit between the two polygons so user dots appear under compare polygon; then render compare dots after compare polygon so they sit on top). Use `<circle>` per vertex:

   User dots — render from `pointsArr`:
   ```jsx
   {pointsArr.map(([cx, cy], i) => (
     <circle
       key={`user-dot-${i}`}
       cx={cx}
       cy={cy}
       r={5}
       fill="#7C6B9E"
       stroke="#FFFFFF"
       strokeWidth={2}
     />
   ))}
   ```

   Compare dots — render only when `hasCompareData && comparePoints`, parsing `comparePoints` (or iterating the same spokes loop used to build `cpts`). Cleanest approach: refactor the `cpts` build to also retain an array of `[x,y]` pairs (e.g., `const compareCoords = spokes.map(...)` returning arrays, then `comparePoints = compareCoords.map(p => p.join(',')).join(' ')`). Then render:
   ```jsx
   {hasCompareData && compareCoords.map(([cx, cy], i) => (
     <circle
       key={`compare-dot-${i}`}
       cx={cx}
       cy={cy}
       r={4}
       fill="#5A9A6E"
       stroke="#FFFFFF"
       strokeWidth={2}
     />
   ))}
   ```

   Rendering order in the SVG (top-down = back-to-front):
     guidePolygons → spoke lines → labels → user polygon → user dots → compare polygon → compare dots → hitbox lines

   This keeps dots crisp on top of their own polygon fill while the transparent hitbox lines remain last (on top of everything) to preserve click targeting.

4. **Dots are static, not animated.** They will snap to new positions on re-render rather than tween with the spring — this is acceptable (faster visual feedback, avoids second spring complexity). Do NOT add `animated.circle` or second spring hooks.

5. Do not change any other behavior: spoke lines, labels, guide polygons, inversion hitboxes, spring configs, and padding math remain untouched.
